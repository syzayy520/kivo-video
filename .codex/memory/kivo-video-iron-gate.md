# Kivo Video 铁律门闸

> 本文件是**长期记忆**：任何助手接手本仓库都必须先读它。
> 2026-11-12 按用户明确要求增补了"工作方式"一节。

所有 Kivo Video 相关推进必须按以下门闸顺序执行：

1. 构思
2. 规划设计
3. 设计自然家族树
4. 实现
5. 单文件单职责
6. 禁止平铺文件

## 执行要求

- 未完成前一门闸，不进入后一门闸。
- 设计阶段必须先确定自然家族树、模块边界、目录归属，再开始落文件。
- 实现阶段每个文件只承担一个清晰职责。
- 新增代码、文档、配置必须进入有语义层级的目录结构，避免在根目录或同一目录平铺堆叠无归属文件。
- 根目录只保留项目级入口、约定文件或必要配置；细节内容必须归入自然家族树。
- **每个 `.kt` ≤ 300 行**；超了必须**按"变化原因"拆**（不是按控件个数拆），
  拆出来的文件必须有独立语义，不能是"只有一个调用方"的空壳。

## 工作方式（用户明确要求，长期遵守）

| 规则 | 说明 |
| --- | --- |
| **同一个工作目录** | 固定在 `C:\kivo video`。**不允许新建项目包**，不另起炉灶，不复制目录。 |
| **中文回复** | 面向用户的回复一律用中文。 |
| **单文件单职责** | 见上；实现期每落一个文件都要能一句话说清它只负责什么。 |
| **先设计家族树再落代码** | 新增功能先在设计稿里画出归属与边界，再写实现。 |
| **不堆砌代码** | 同一个组件不塞多套逻辑；四个长得一样的东西应是**同一个东西的四份数据**，不是四个文件。 |
| **不许静默降级** | 任何"点了没反应/功能缺失"必须带**非空 reason 且用户可见**（提示、说明、灰显说明）。 |
| **不许伪造状态** | UI 显示的面板/选项必须来自**内核真实状态**；读不到就返回"未知"，不能编一个默认值。 |
| **证据路径** | 没有可复算的证据路径，不许说"完成"。模拟器数字无效。 |
| **改完要真机自检** | 每个功能都要在真机（K40 `b6e950ee`）上截图自检，并与参考实现做**逐项对比**；达不到参考就继续做，直到**持平或超过**。 |
| **交互要有过渡** | 参考实现（REX）有淡入淡出/缩放/闪示等动效；我们的实现不能是"瞬现瞬消"的硬切换。 |

## 参考实现的对照纪律

以 REX 1.0.2 真机录屏为基准：

- **结构照搬、形态按 Android 重画**（线框图标 vs Material 实心图标）。
- **数值以像素实测为准**（`tools/measure_rex_player.py`），不靠印象；
  参考的拆解见 `docs/reference/rex-teardown/05-ui-spec-from-recording.md` §六
  与 `audit/interactions.csv`（动效与交互目录）。
- **"参考有而我们没有的"逐个补齐**；做不出来就做到**一模一样**，不做成"简化版"。
- 我们**确实更好**的地方要**写明理由**（例：顶栏加淡渐变，因为我们的片源黑场多，
  纯透明图标会整个消失）。
