## 1. 构思：先稳定已认可的页面，再补交互和证据

用户已确认“现在没问题了”。将当前首页/详情分层效果作为回归基线；这表示当前效果获得认可，不表示全应用、所有影片和所有动效已经像素级验收。没有新的对照证据，不再次推倒页面或反复调色。

保留用户明确要求：

- 默认静态图片，预告片须用户主动选择开启。约 2 秒等待是当前实现的拟合初值，不称为从 REA 解出的常量。预告就绪后替换同一媒体区域，不能成为海报上方另一块视频。
- 首页使用实时数据源与有效缓存，不写死影片或按日期轮换几张本地图。上游数据可能连续两天相同，不能承诺每天必然出现不同影片。
- 上滚时媒体保持锚点并轻微放大，内容、片名和渐变前景向上覆盖；片名独立于媒体层。下拉只放大媒体，不把片名一起缩放。
- 背景偏浅、可读性和“继续观看 >”完整显示必须回归；亮图、暗图都要可读，不能只挑暗图掩盖白字问题。
- TMDB 评分、观看统计保留在范围内；无来源评分不伪造。PRO 付费、iCloud 不纳入本轮复刻。
- 固定签名、覆盖安装、不清数据、不卸载；不借 UI 复刻改动后端、JNI 或 Surface 链路。硬解失败给出原因，禁止软解回退。

## 2. 证据与冲突裁决

用户当前产品决定优先。关于原版行为的判断依次使用：相同版本与设置下的连续真机操作 → 可核查的包内资源/文案事实 → 已知版本的旧截图/录屏 → 拆解者推断。不同版本先并列记录，不能简单相互覆盖。

当前 iPhone 原版为 Rex 1.1，静态拆解包为 1.0.2。包是 FairPlay 加密版本；CSV 中系统惯例、推测时长、弹簧参数均是候选值。文案证明有某个入口或能力，不证明该入口在当前手机版的位置、默认状态、动画常量或完整状态机。

拆解整理入口：[audit/status.md](../../../reference/rex-teardown/audit/status.md)。逐条保留原始等级，另外标注“运行时未测”，避免把一个“✅”传播成整行已实测。缺原始图片的资产元数据不能当作已恢复素材。

### R2：已确认的实际缺口与验收场景

开工前代码盘点（2026-11-08，历史状态）：收藏/待看/更多当时仅绘制图形，`SimilarList(... onOpen = {})` 当时为空回调。现已接线并完成标记持久化和底部卡片阶段回归；本轮再验证电影/剧集连续点击与返回、简介、首载失败恢复、刷新失败重试和关闭。仍有下列未验场景，不能列成“详情已全部完成”。播放按钮已有资源匹配及无资源说明，预告已有点击入口，先回归，不重复造功能。

1. 原版确认图标语义，逐项核对短按/长按；只实现有依据的菜单项。已观看/收藏/待看不得共用一个含混布尔值。
2. 添加与取消动作各做一次；切页、返回、杀进程重开后状态一致。网络行为若存在，记录等待、成功、失败与撤销，不显示虚假成功。
3. 展开/收起长简介；打开相似影片再返回；连续快速点击不能堆叠多个相同页面。
4. 有本地资源正常进入播放器并返回；无资源明确说明；预告无可用网络时保留图片和可理解的提示。
5. 深浅色场、长片名、缺 logo、缺图、无评分/无演员/无预告均有可读布局。已有家长指南浅色卡文字修正保留。

## 5. 像素与动效验收方法

目标改为 Kivo 自己的完整设计，以像素级精度校核选定的布局、构图和动作细节；不以全页复制 REX 为目标。[多播放器观察与取舍](player-study.md) 区分已观察、异常与未测。每次比较固定：原版版本、页面、影片/同一张图片、语言、字体缩放、浅深模式、预告开关、滚动锚点、截图色彩空间。系统状态栏与不同内容区域单列，不能用全屏平均掩盖关键元素误差。

- 坐标：使用实际屏幕 scale/density 换算 pt/dp；保留安全区。只对布局确实按宽度变化的区域做等比映射，不将字号、圆角、触控区全部乘宽度比例；不纵向拉伸截图。
- 几何：逐项报告海报裁切、logo 包围框、元信息/按钮/章节锚点、箭头边界。首轮目标为主要锚点偏差 ≤2 个逻辑单位；这是项目准入线，不是从原版提取的参数，也不代表零像素误差。
- 颜色：先识别 ICC 并转换为同一 sRGB；同素材、同状态区域报告多块采样和色差分布。P3/透明图解码、模糊、字体光栅差异单列，不靠单列像素或一个 ΔRGB 阈值验全页。
- 动态：连续录屏覆盖按下、拖动、松手、取消、重入。记录视频帧率与时间量化误差；逐段拟合时长/位移/速度，区分手势跟随与自动动画。手机 USB 分段截图能确认结构，不能证明精确缓动曲线。
- 性能：K40 实测并记录实际刷新率，预热后同一路径连续操作 30 秒、3 轮，保留 FrameTimeline 或可用的 gfxinfo 原始记录。按实际采集方式报告帧时分布与超预算帧比例。旧稿 jank <5% 只能作为待校准项目目标，不冒充“完全无掉帧”；方法不可用时记缺口。
- 可用性：默认字级验证视觉，1.3× 字体另验不截断；触控和 TalkBack 标签/顺序独立验。无来源评分不补假值来凑外观。

当前尚需校准的视觉差异列在 R0 证据记录里，包括 logo 宽度、按钮材质、空资源插画、演职员标题、顶部模糊和深滚色场。用户已认可的状态不再无证据修改；有同状态对照后逐项修正并回归。

## 6. 每卡实施和收口

开工前：确定证据、真实现状、状态图、文件边界和自然家族树。实现只做该卡范围。涉及持久化/取消竞态时补有意义的测试；纯布局优先真机截图，不写照抄实现的测试。

收口：构建、覆盖安装、卡片场景真机验证、保留失败与未测项；证据落 `docs/evidence/<stage>/<card>/`，更新 TASKS/CURRENT；精确选择文件提交并推送。不覆盖其他助手改动，不使用全仓 `git add .`，不把未提交快照称为已提交实现。

每卡保留起始 commit 和补丁。失败时只撤回该卡变更；不回滚共享文件的其他编辑、不卸载清数据。没有逐项证据只能维持 DOING/TODO；“用户认可当前画面”“功能跑通”“像素验收通过”分别记录。

不按猜测给工期。先完成下一张 R2 的盘点与可执行设计，按缺口和真实回归成本再排后续卡；不得因旧稿写了“定稿/完成”而跳过验证。
