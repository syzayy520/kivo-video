# 真实网络片源验证与入口约束

2026-11-09，基线 da3a3ec5。R2/R4 的跨页验证子阶段，不重写认可视觉。

## 构思与范围

用户提供 SMB 与两组 Emby 测试源。先验证连接、读取，再通过现有界面浏览和返回。凭据仅用于本次连接，不入库、不归档媒体列表或令牌。PC API 成功不能代替 Android 真机通过。

盘点发现 PlayerComposeActivity 网络入口要求先找到本地测试视频，并在网络会话失败后构造 FFmpeg 软解会话。前者阻断无本地片源用户；后者违反项目禁止软解回退。只调整 Activity 路由：先选择 SMB/URL，再解析本地文件；网络启动失败保留可见原因并允许返回，不自动软解。网络 URL 不再写进状态文案和入口日志，避免 Emby token 暴露。不得修改 NetworkPlaybackSession、backend、JNI、Surface 或解码循环。

- 本设计稿：范围、门闸、后续缺口。

## 验收与限制

构建成功；K40 合成不可播放 URL 的失败原因可见且不退回软解，返回正常；真实源连接与媒体读取独立记录。已有 NetworkPlaybackSession 使用 createDecoderByType，尚不能据此保证选中硬件组件；它只处理视频，不能宣称完整影音播放通过。性能、音画同步、网络会话生命周期和播放器整体重写另卡处理。若真实播放依赖这些缺口，明确记录而不降级或冒充通过。

## 真机观察后追加：既有 Emby 表单优化

K40 第一组账号经现有表单登录，出现 60 条电影网格。中文输入法在服务器字段进入候选组合，需网址键盘；登录后网格吃满高度，连接状态被挤出可视区。此卡只修改既有 EmbyActivity 的输入体验与布局：服务器 URL / 用户文本 / 密码键盘，Next/Done 焦点流，表单可滚动并避开键盘，网格使用剩余高度，空库有说明，库内返回先回连接页。沿用既有 EmbyClient 与会话，不另建登录服务。验收用真实登录、返回、失败状态，以及合成无效 URL 播放；私人媒体与凭据不归档。
