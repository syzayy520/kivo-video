## 零、这份文档解决什么

上一轮把播放页做成了一个"能用但不成形"的状态：
控制条只有进度条 + 播放/暂停 + 两个"弹""投"文字按钮，
顶栏**完全缺失**（没有返回、没有片名、没有动作入口），
状态信息用一个 10sp 的黑底白字浮在左上角（像调试日志，不像产品）。

本文件给出**可验收的规格**，并回答一个更重要的问题：
**照抄 REX 是不够的** —— REX 有几处明确做得不如我们该有的样子，
§五 逐条列出并给出更好的解法。

## 二、视觉语言：四层信息架构

播放页的本质是**让画面消失**。所有 chrome 必须服从于这一点。

```
┌─ L1 画面层 ────────────────────────────────────────────┐
│  视频画面（无遮挡）                                        │
│  字幕：画面内，底部居中，白字 + 描边阴影（15pt）              │
│  弹幕：画面内，顶部两行（与字幕共存，互不遮挡）                 │
└─────────────────────────────────────────────────────────┘
┌─ L2 顶栏（44pt 高）───────────────────────────────────┐
│  左：✕ 返回 · 片名(17pt)      右：画质/音频/字幕/耳机 + 网速   │
│  背景：透明（无渐变）—— 用图标自身的可读性保证              │
└─────────────────────────────────────────────────────────┘
┌─ L3 底部区（内容高约 100pt）──────────────────────────┐
│  上：进度条(3.5pt 细轨) + 两端时间(17pt)                    │
│  下：⏸ ⏭(左)              4K 选集 倍速(右)              │
│  背景：**底部渐变 scrim**（黑 0% → 55%，从进度条上方 24pt 起）  │
└─────────────────────────────────────────────────────────┘
┌─ L4 浮层 ────────────────────────────────────────────┐
│  面板（倍速/字幕/画质）：深色毛玻璃，13pt 圆角，59pt 行高        │
│  加载：中央三点波纹                                          │
│  错误：面板式，居中                                          │
└─────────────────────────────────────────────────────────┘
```

**关键决策（为什么这样分层）**：

1. **顶栏不遮画面**。REX 顶栏完全透明，靠图标自身对比度。我加一层**极淡的顶部渐变**
   （黑 0% → 28%，仅覆盖顶栏 44pt）—— 比 REX 多一层，理由是
   **我们的片源更暗**（片头黑场多），纯透明图标会看不见。
   这就是"比 REX 更好"的第一处：**不是照抄，是按自己的内容调**。

2. **进度条用细轨 + 无滑块**。Material3 `Slider` 那个大圆头滑块在横屏下太重、
   且会盖住画面。改成 3.5pt 细轨，**拖动时才显示一个小圆头**（8pt）。
   这是"比 REX 更好"的第二处：REX 完全无滑块，拖动时用户不知道抓哪里。

3. **底部渐变 scrim 提到进度条上方 24pt**。REX 的字幕在最底下，
   如果我们的控制条也压在字幕区，字幕就被遮住了（本轮已修过一次这个 bug，
   见 `p6-2-subtitle-diagnosis.md`）。所以**控制条与字幕必须分区**：
   字幕在 24pt 以上的安全区，控制条在其下。

4. **网速进顶栏右端**，不单独占位。REX 把它放最右上（与电池争位置），
   我们把它放在图标行左侧，避开系统状态栏。

## 三、组件规格（可验收）

### 3.1 顶栏 `PlayerTopBar`

| 元素 | 规格 |
| --- | --- |
| 高度 | 44 pt |
| 返回 ✕ | 16.5 pt 线框图标，触达区 44×44 pt（无障碍最小） |
| 片名 | 17 sp，`maxLines=1`，超长省略号；左侧留 12 pt |
| 动作图标 | 21.5 pt 线框，**间距 50 pt**，右端距边 16 pt |
| 网速 | 12 sp 等宽，放在动作图标**左侧** 12 pt |
| 背景 | 垂直渐变 黑 0%→28%，仅 44 pt 高 |

| 图标 | 行为 | 状态 |
| --- | --- | --- |
| 画质比例 | 打开画质面板 | 已有 mpv 属性，本轮接 |
| 字幕样式 | 打开字幕样式面板 | mpv `sub-font-size`/`sub-margin-y` 可做 |
| 音轨 | 打开音轨面板 | mpv `aid` 已通 |
| 投屏 | 打开投屏 sheet | **已有**（`CastSheet`），从"弹/投"文字钮升为图标行 |

| 滑块 | **默认不可见**；拖动中显示 8 pt 白圆点（带 20% 阴影） |

### 3.3 字幕 `PlayerSubtitleLayer`

| 元素 | 规格 |
| --- | --- |
| 位置 | 底部居中，**距底 24 pt**（避开控制条） |
| 字号 | 15 sp（横屏 844pt 基准） |

| 描边 | 黑色阴影（2px 模糊，60% 不透明）—— 保证任何亮画面上都可读 |
| 容器 | 水平内边距 24 pt，最多两行 |
| 与弹幕 | 弹幕在**顶部两行**，字幕在底部 ⇒ 天然不冲突 |

### 3.4 面板 `PlayerOptionPanel`

| 元素 | 规格 |
| --- | --- |

| 圆角 | 13 pt |
| 行高 | 59 pt（与设置页同规格） |
| 行内 | 标题 17 sp + 副标题 11 sp 灰 + 右侧值/箭头 |
| 选中态 | 右侧白勾 |
| 位置 | 右侧贴边（REX 的做法），上下留 44 pt |

### 3.5 状态层 `PlayerStatusLayer`

| 状态 | 表现 |
| --- | --- |
| 加载/缓冲 | **中央三点波纹**（不是转圈 spinner）—— REX 的做法，比 Material `CircularProgressIndicator` 安静 |
| 失败 | 居中面板：图标 + 原因 + "重试"按钮 |
| 网络中断 | 底部渐变区内的轻提示（不遮挡画面中央） |

在产品界面里像日志。改由状态层承担。

## 四、家族树（单文件单职责）

沿用 [player-ui.md](player-ui.md) 定下的家族，只补齐实现与新增文件：

```text
android/app/src/main/java/com/kivo/cinema/ui/compose/player/
├── PlayerOverlay.kt        # 显隐编排 + 顶/底/字幕/面板/状态 四层的叠放顺序
├── PlayerTopBar.kt         # 顶栏：返回 / 片名 / 动作图标组 / 网速
├── PlayerBottomBar.kt      # 底栏：细轨进度条 + 两端时间 + 播放键 + 右侧文字钮（含拖动预览浮窗）
├── PlayerSubtitleLayer.kt  # 字幕层（Compose 侧；内核字幕由 mpv 画，两者不重叠）
├── PlayerOptionPanel.kt    # 通用面板（倍速/音轨/画质/字幕样式共用，一个实现）
├── PlayerPanelData.kt      # 面板数据装配（条目必须来自内核真实状态）
├── PlayerStatusLayer.kt    # 加载三点波纹 / 失败面板 / 断网提示
├── PlayerGestureLayer.kt   # 手势层（仅在控制条隐藏且无面板时启用）
├── PlayerWindow.kt         # 沉浸式全屏窗口配置 + 挖孔安全区
├── PlayerGlyph.kt          # 统一矢量图标（线框，21.5pt / 16.5pt 两档）
└── PlayerTokens.kt         # 播放页专用 token（颜色/字号/间距/圆角）
```

> **落地的两处偏差**（有理由，见证据 README §四）：
> ① `PlayerTimeline.kt` **没有单独成文件** —— 进度条与拖动预览只在一个组件里，
>    拆出去只会造出一个"只有一个调用方"的文件（违反单文件单职责的本意：职责按**变化原因**切，
>    不按**控件个数**切）。
> ② 面板行高 46dp 而非 REX 的 59pt —— 我们的面板要与底栏共存，可用高度只有 253dp。

**旧的 `PlayerControls.kt` 已删除** —— 新的 `player/` 家族完全取代它，
留着就是两套并行的控制条（"保兼容"在还没有第二个调用方时是负担，不是保险）。

**边界**：

| 规则 | 含义 |
| --- | --- |
| P1 | `player/` 家族**只负责展示**，不碰会话、不碰 Surface 生命周期 |
| P2 | 图标一律用 `PlayerGlyph` 画的 `Path`，**不用 Material 图标**（Material 是实心填充，REX 是线框，形态不统一） |
| P3 | 面板**只有一个实现**（`PlayerOptionPanel`），倍速/音轨/画质/字幕样式都靠数据驱动，不各写一个 |
| P4 | 状态一律走 `PlayerStatusLayer`，**不再有裸 Text 浮在画面上** |
| P5 | 每个 .kt ≤ 300 行 |

**接入点**：`PlayerComposeActivity` 只保留 `setContent` 里的编排与回调，
把 `PlayerControls.kt` 降级为**兼容适配**（旧调用仍能工作），最终删。

## 五、超越 REX 的六处（逐条有理由）

| # | REX 的做法 | 我们的做法 | 为什么更好 |
| --- | --- | --- | --- |
| 1 | 顶栏**完全透明** | 顶栏加 28% 淡渐变 | 我们的片源有大量黑场片头，纯透明图标会消失。**渐变只加 44pt，不遮画面** |
| 2 | 进度条**无任何拖动指示** | 拖动时显示 8pt 圆点 | REX 用户不知道往哪按；圆点只在拖动时出现，不干扰观看 |
| 3 | 倍速/画质/字幕菜单**每次现开** | 菜单项**记住上次选择**并预置当前值 | REX 每次打开都在默认位；预置当前值后调整更少点击 |
| 4 | 音频/字幕等切换**无任何反馈** | 切换后顶栏对应图标**高亮 1.5s** | REX 点了不知道成没成；高亮是零成本的确认 |
| 5 | 缓冲**只有波纹** | 缓冲时显示**已缓冲百分比**（有网络进度时） | 百分比让"还要等多久"可预期；无数据时不显示 |
| 6 | 字幕固定白色 | 字幕样式可调（字号/边距/背景） | REX 有字幕设置但播放页不体现；我们的 mpv 有 `sub-font-size`/`sub-margin-y` **真能调** |

**不做的事**（避免过度设计）：不加顶部搜索、不加竖屏播放、不做小窗/画中画、不做倍速记忆的持久化（先做会话内）。
