# 详情媒体滚动动效设计

日期：2026-11-08。范围：详情页首屏媒体层的滚动与回弹，不包含播放器控制条。

## 目标

详情页采用独立的媒体层、前景层和回弹层：

- 上滑时媒体纹理保持在近似锚点，同时随已消费的上滑量轻微放大；
- 片名、元信息、按钮和渐变前景属于列表内容，按列表滚动覆盖媒体；
- 下拉回弹只增加媒体尺寸，不改变片名位置；
- 上滑放大和下拉回弹放大使用独立参数，可分别回归；
- 媒体缺失或加载失败时不创建空白的放大层。

## 证据与拟合

REX 1.1 的《荒野丛林》连续截图 `C:\Users\Administrator\Pictures\REX\2026_11_08_19_25_03_IMG_0149.PNG` 至 `...IMG_0158.PNG` 用固定树枝纹理配准：相对首帧的媒体缩放约从 `1.000` 递增到 `1.107`，配准平移接近媒体视口中心。这证明了“上滑媒体确实变大”，但没有证明原版源码常量。

随后将前景位移换算为 pt，0150–0157 的上滑量依次为 52.67、94.33、122.67、164.67、195.33、232.67、270.00、311.67；媒体比例依次为 1.01799、1.03224、1.04192、1.05629、1.06675、1.07953、1.09227、1.10652。拟合约为 `scale = 1 + scroll / 2925`。0158 配准不足，不使用。早期草稿的“72dp 达到 10%”已作废，不能据此实现。

Android 使用 `1 + clamp(scrollDp, 0, 350) / (585 * 5)`。350dp 是 Kivo 对完全遮盖前媒体的保护上限（约 12%），不是已破解的原版常量；参数集中在 `DetailBackdrop.kt`。

## 家族树与职责

```text
docs/design/ui/replica/detail-media-motion.md   # 本卡设计、证据、验收
android/app/src/main/java/com/kivo/cinema/ui/detail/
  DetailBackdrop.kt                             # 媒体层变换与渐变，不持有列表状态
  MovieDetailActivity.kt                        # 计算上滑/回弹量并传入媒体层
  DetailHeroContent.kt                          # 标题与按钮前景，不参与媒体缩放
```

不新增通用动画组件；本卡只有一个媒体变换职责。详情动作接线、首页 feed 和播放器手势仍由各自任务卡负责。

## 变换契约

上滑以 585dp 媒体视口中心为原点缩放，去除旧的 5% 额外上移；下拉仍以顶部为原点缩放。两者正常互斥，`pullDp > 0` 时使用顶部原点。只有媒体接受缩放，片名与渐变不接受。回弹可带动前景原有纵向位置，但不放大片名。

## 验收

1. 同一影片、同一图片、同一语言下，顶部、中滚、深滚三帧均能看到媒体层连续变化；标题的包围框只随列表滚动，不随媒体缩放。
2. 上滑放大在 0–约12% 内连续单调，达到上限后不继续增长；回顶恢复 1.0，下拉回弹释放后恢复 1.0。
3. 媒体加载失败时没有空白放大块；返回顶部后媒体纹理和尺寸可复现。
4. Android 构建成功，K40 覆盖安装后回归详情页；不卸载、不清数据、不改后端/JNI/Surface。
5. 记录原版与我方同锚点截图和参数，不能把拟合参数写成 REX 的源码事实。
