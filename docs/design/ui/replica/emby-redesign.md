# Emby 页面重设计

2026-11-09；用户明确否定旧 Emby 调试表单，授权重新设计。此卡替代此前只修表单间距的 UI 方案；网络失败不软解等入口约束继续保留。

## 构思与参考边界

已有多播放器观察中，EplayerX 的紧凑导航与信息分组、Vidora 的状态区分、REX 的轻色场可以作为视觉原则。已有证据没有覆盖这些应用的 Emby 登录流程，不声称复制了它们的服务器页。新布局是 Kivo 独立设计：浅灰紫底、白色分组输入、克制的绿色主操作；媒体进入后以海报为中心，移除协议术语和大面积空表单。

## 流程

连接页：返回资源库 → 标题与说明 → 服务器地址、账号、可选密码 → 连接媒体库。地址支持完整端口，密码可显隐。连接中禁用重复提交，允许取消，失败就地显示简洁原因、保留输入。输入框有网址/密码键盘，Next/Done 与键盘避让。手机采用紧凑单栏；宽屏引导与表单并列，表单宽度有上限。

媒体页：返回连接页、服务器名称、电影数量 → 搜索当前加载列表、最近添加/名称/年份排序 → 自适应海报网格。标题两行、缺海报中性占位、圆角裁切、空列表/无匹配分别提示。只承诺搜索已加载电影；现有接口只拉电影前 60 条，不伪装全库搜索、剧集或分页已实现。点击仍复用现有播放入口，不新造协议或解码器。

输入与会话跨旋转保留在内存 ViewModel，密码和令牌不写盘。连接结果与海报回写主线程；取消后迟到结果不得切页。缓存按字节限制，不继续旧的无界位图 Map。失败文案不展示 HTTP 原始正文、认证信息或带令牌 URL。

## 闸门

构建、固定签名覆盖安装；平板真实登录、网格、搜索无匹配/恢复、排序、返回保留输入、旋转保留会话；合成失败可重试、取消不被迟到结果带走、键盘下按钮可达。记录未验手机场景，不把平板当 K40 性能证据。不归档私人媒体列表与凭据；backend/JNI/Surface/解码循环保持范围外。
