## 构思与流程

从正常首页进入详情，验证长简介展开/收起、相似作品单次与连续点击、子页返回的纵向和横向位置。以实际 Activity 栈证明只新增一个详情，以同一组文字边界与截图证明返回位置一致，不能只用“看起来没跳”判定。

分别验证电影和剧集；剧集子页继续使用 tv 身份。失败路径采用临时不可用代理端点的确定性故障注入，验证首载和已有内容刷新，再恢复原配置重试。无线/reverse 切断只保留为探索记录，不能保证已有连接失效。原始配置字节、无线设置与 adb reverse 映射必须在 finally 恢复。已加载页重试失败应继续保留原内容。

如果发现问题，先在本记录补充状态与文件边界，再修改生产代码；仅验证通过的现有行为不为了产生 diff 而重写。

## 实测缺口与修正边界

仅关闭 Wi-Fi 不能切断本机其他网络；两次等待重试入口超时保留为方法失败，不算产品通过。改为暂开飞行模式并关闭 Wi-Fi，ping 不通后触发刷新，finally 恢复原状态。确认已有内容时错误文字覆盖片名（`loaded-refresh-offline-before-fix.png`）。

新增 `ui/detail/loading/DetailLoadFeedback.kt`，只负责首载错误卡片与已有内容的底部 Snackbar；活动继续拥有加载/重试状态。已有内容失败不遮片名、不移动列表，提示可关闭或重试；首载失败保持明确原因和按钮。两种状态都要在真机复验，不改媒体构图。

首次无线恢复后仍无法加载，检查发现应用配置使用 loopback SOCKS，但 adb reverse 映射为空。主机通过原有 SOCKS 请求 TMDB 返回 HTTP 200，恢复 `tcp:10808` 原链路后，错误页重试成功。此问题归为取证环境恢复不完整，不能据此声称应用重试失效。后续断网脚本先快照映射、切断应用 USB 出网，再开启飞行模式；finally 同时恢复无线与所有原有映射，不修改密钥、代理配置或 VPN。

最终包再次测试时，切断无线/reverse 后未出现错误。已有连接可能存活，该方法判为不确定，不能当作产品失败或离线通过。`unavailable_requests()` 临时把应用代理端点改为不可用地址，让新请求避开原连接池，finally 原样恢复并逐字节断言；不输出私有配置。此方法证明请求失败/重试 UI，不证明真实无线断网和全部网络故障类型。

最终包已验证简介展开/收起、电影首载失败→恢复→返回、剧集《辛普森一家》→《干杯酒吧》连续四次点击仅新增一页、集数仍在、返回全部可见节点坐标一致。已有内容刷新失败保留节点，重试后 25 秒观察窗未再出现错误；此路径没有加载完成指示，不把观察窗当作请求计时。最终结果及未验范围见本卡 `status.md`。
