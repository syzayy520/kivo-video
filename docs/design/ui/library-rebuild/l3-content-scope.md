## 已确认的代码问题

- EmbyClient.items 固定 IncludeItemTypes=Movie、Recursive=true，没有查询用户 Views 或使用 ParentId 限定服务器媒体库。因此当前实际是跨库电影查询，剧集还可能根本没有列出来，不能只用几个分类按钮掩盖问题。
- EmbyItem 只有 id/name/year/posterUrl，缺少 Type、CollectionType 与剧/季/集关系；当前所有海报直通 streamUrl，无法完成剧→季→集选择。
- 当前浏览标题、空态和搜索语义按电影编写，未表达当前服务器媒体库和搜索范围。

首页 TMDB 分区需另行审计，本轮没有确认其是否具有相同问题。不能据本卡声称全部页面已查清。

## 设计前必须补的事实

先查询用户有权限的服务器媒体库，记录名称、CollectionType、条目类型与分组。尊重服务器现有的电影、剧集、综艺等组织；纪录片、动画、演唱会未必拥有独立协议类型，不能凭片名或 genre 强猜。混合库、未知类型、空库、受限账号需要明确展示与可见原因。

研究 REX 与其他播放器的内容范围入口、层级返回、搜索范围及状态恢复，区分实际操作记录和静态拆解线索，不宣称加密包提供了业务源码。

## 验收

1. 两源分别列出实际可见媒体库，切源不串账号、目录或海报；原服务器命名保留。
2. 电影按所属库浏览；剧集可进入季/集，返回保留上一层位置；文件夹/季不能当影片直播放。
3. 搜索明确当前范围；排序和分页遵守相同 ParentId/类型；换库、快速搜索与返回取消旧请求，不混入旧结果。
4. 超过60条加载第二页，重试不重复；空、权限错误、网络错误分别表达；未知内容类型有可见处理。
