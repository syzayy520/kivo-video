# 367 · Emby 浏览页列表缓存（承接 366 同类审计）

> 366 把详情/季集/图片尺寸接上了缓存，但**列表**还没接。这一轮做同类审计时实测：
> Emby 浏览页每个分类行一次 `/Users/{uid}/Items` 请求，**每次 0.4–1.4 s**，滚动、返回、再进入全部重打。

## 一、实测（真机 K40 `b6e950ee`，`[emby-items]` 埋点）

| 场景 | 单次请求耗时 | 说明 |
|---|---|---|
| 冷进（缓存已清） | 412 / 567 / 809 / 379 / 441 / 776 / 592 ms | 7 次请求，行随组合逐个触发 |
| 热进（**修 init 前**） | 531 / 805 / 1369 / 368 / 374 / 407 ms | 仍全打网络 —— 缓存空转 |
| 热进（**修 init 后**） | **3 / 4 / 1 / 1 / 2 / 2 ms** | 本地读，网络 0 次 |

## 二·A 先踩到的坑：缓存没初始化

`EmbyResponseCache.init()` 此前只在 `MovieDetailActivity.onCreate` 调。
**EmbyActivity 从没初始化** ⇒ `dir == null` ⇒ `get()/put()` 全部退化为空转，
热进仍然是每行 0.4–1.4 s（日志里一条 `[emby-cache]` 都没有，这个"没有"就是证据）。

修法：`EmbyActivity.onCreate` 与 `MainActivity.onCreate` 各补一次 `init(cacheDir)`（幂等）。

## 二·B 接上的缓存

| 端点 | TTL | 理由 |
|---|---|---|
| `/Users/{uid}/Items…`（分类行 / 分页列表 / 搜索） | **10 分钟** | 新片入库会变 ⇒ 短 TTL；足够覆盖"来回浏览" |
| `Items/Counts` | **不缓存** | 它同时用来**判断服务器是否在线**；缓存会让已挂掉的服务器继续显示"在线" |

> 列表缓存键 = 完整 URL（含 userId / ParentId / 类型 / 排序 / 分页 / 搜索词），不同行互不串。

## 三、验证

- `ui_gate` PASS（无新增超限文件）；单测 111 例 0 失败；`assembleDebug` SUCCESS。
- 真机截图：Emby 浏览页 hero / 继续观看 / 分类行均正常，无空白行、无转圈、无错误文案。

## 四、边界（如实）

1. 列表**最多陈旧 10 分钟**：服务器新入库的片在该窗口内可能不出现。
2. 搜索词也在同一个缓存键里 ⇒ 同一关键词 10 分钟内复用，换词不走缓存。
3. 分类行"逐个出现"的观感来自 `LazyColumn` 按视口组合 + 每个行各自请求；
   缓存已把单次耗时压到毫秒级，但**行本身仍是懒加载**（未改成一次性并发取全部行）。
