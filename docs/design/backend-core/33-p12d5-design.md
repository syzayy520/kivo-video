# P12-D5 设计：上屏时刻（present fence）—— 一次被证伪的"不可测"

- 版本：V1.0
- 日期：2026-10-29
- 关联：`23-p12c7-status.md` §六 第 6 条（**该条已作废**）、`25-p12c8-status.md` §九
- 卡片判据：能报出"这一帧何时真的显示在屏幕上"，**或**明确证明此架构下不可测并给出替代判据

---

## 一、先说结论：C7 那句"不可测"是错的，错在一个参数

C7 当时试了 `dumpsys SurfaceFlinger --latency` 三种层名，全都只返回刷新率一行
（`16666666`），于是下了"这个架构下拿不到上屏时刻"的结论，写进了
`23-p12c7-status.md` §六 第 6 条，还被 C8 引用成"默认路径 `av_drift` 不可测"的原因。

**真实的层名长这样**（`dumpsys SurfaceFlinger --list`）：

```
SurfaceView[com.kivo.cinema/com.kivo.cinema.ui.PlayerActivity](BLAST)#115401
                                                                     ↑ 这个 #id 必须带上
```

C7 用的是去掉 `#id` 的名字 —— `--latency` 按名字匹配，匹配不到就只吐刷新率。
**命令没失败、没有报错、也没有提示"没找到这个层"**，它只是安静地返回一行。
这就是为什么当时没起疑。

改成一个字符都没少的完整名字，数据立刻出来了。

## 二、先验列语义，再谈测什么

`--latency` 返回三列（外加首行刷新周期）。不查清这三列是什么，后面的数字全是猜。
做了两个实验：

### 实验一：拿 uptime 对表

| 量 | 值 |
| --- | --- |
| `/proc/uptime` 第一字段（BOOTTIME） | 615 009 s |
| 首行刷新周期 | 16 666 666 ns |
| 第二列 | 424 981 884 838 297 ns = 424 981 s |

424 981 ≠ 615 009，但如果把"设备睡眠时间"减掉：`615 009 − 424 981 = 190 028 s ≈ 52.8 h`。
一台用了 7 天的手机挂起 52 小时完全正常 —— 所以**第二列是 `CLOCK_MONOTONIC`**，
和我们代码里的 `core::pace::monotonic_now_ns()` 是同一口钟。

### 实验二：换一种排程，看第一列怎么变

| 排程 | 第一列样例 | 第三列 |
| --- | --- | --- |
| `cpu_paced`（`releaseOutputBuffer(idx, true)`） | `33 333 000` / `66 666 000` … | 与第一列相同 |
| `surface_at_time`（`releaseOutputBufferAtTime(idx, due_at)`） | `425 061 094 137 433` / `425 061 127 470 277` … | 与第一列相同 |

`cpu_paced` 下第一列是 **33.3 ms、66.6 ms 递增 —— 那是媒体 pts**；
`surface_at_time` 下第一列跳到 **CLOCK_MONOTONIC 量级**，正是我们传给
`releaseOutputBufferAtTime` 的 `due_at`。

### 结论（三列的语义）

| 列 | 名字 | 含义 |
| --- | --- | --- |
| 1 | `desiredPresentTime` | 缓冲上携带的时间戳。`cpu_paced` 下 = pts；`surface_at_time` 下 = 我们要求的上屏时刻 |
| 2 | `actualPresentTime` | **合成器真正锁存这一帧的时刻（CLOCK_MONOTONIC）** |
| 3 | `frameReadyTime` | 这一层上与第一列相同（厂商实现如此，不作判据） |

于是：

```
Δ = actualPresentTime − desiredPresentTime
```

在 `surface_at_time` 下，**Δ 就是"我们要它在这个时刻上屏，它实际晚了多少"**。
而 `due_at` 按节拍器的定义等于"这一帧为了音画同步应该上屏的单调时刻"，
所以 **Δ 同时就是音画偏差在上屏端的真实值** ——
和 `av_drift` 说的是同一件事，只不过 `av_drift` 量在"交出去"那一刻，Δ 量在屏幕上。

这正好把 C8 留下的那句"默认路径测不了"补上：**默认路径不是测不了，是当时没测对。**

## 三、方法：主机侧读，播放器一行不改

不改播放器是这次的关键取舍。理由：

1. 播放器已经承载 C5–C8、D1–D4 的全部取证口径，动它就要重跑所有回归；
2. 上屏时刻本来就是**合成器的知识**，不在我们的进程里 —— 去进程里加代码追它，
   本质上是在猜；
3. `dumpsys` 的输出稳定、可复算，且能被独立脚本重跑。

新工具 `tools/probe_present_timing.py`：

```
清空统计 → 起播（surface_at_time）→ 等层出现 → 等 4 s → 按完整层名 dump → 解析 → 写 JSON
```

- 层名每次运行都变（`#id` 递增），所以**必须运行时从 `--list` 里现取**，不许写死。
- 全程在应用还活着的时候 dump —— 层一旦销毁，统计就没了。

## 四、判据与它的边界

### 4.1 能测什么

- 每一帧的 `(desired, actual)` 对，以及 Δ 的 p50/p95/p99/max；
- **错过 vsync 的帧数**（`Δ ≥ 刷新周期`）—— 这是"这一帧被推迟了一个刷新周期"的直接证据；
- 换成 `cpu_paced` 时第一列会退回 pts，工具必须**显式识别并拒绝算 Δ**，
  而不是拿媒体时间减单调时间得出一个荒唐的数。

### 4.2 测不到什么（写死在这里，别日后当成"已经覆盖"）

1. **环形缓冲只有 128 行**（实测 129 行含刷新周期）。30 fps 下 ≈ **4.3 s**。
   更早的帧会被覆盖 —— 所以只能测窗口，不能测整段。要用更长的窗口得改用
   `--frametimeline`（实测为空）或 GL 路径。
2. **层名与窗口是运行时事实**，证据里必须连同层名、清空时刻、dump 时刻一起记，
   否则复算的人不知道该对哪一段。
3. **它量的是"合成器锁存时刻"，不是"液晶翻转时刻"**。后者在面板里，任何 API 都拿不到。
   差一个扫描周期（16.7 ms 量级），对 40 ms 的判据不影响，但要写清楚。
4. **只有 `surface_at_time` 能算 Δ**。`cpu_paced` 下第一列是 pts，
   Δ 的物理含义不存在 —— 这不是工具的限制，是那个模式**本来就没有**"请求上屏时刻"。

### 4.3 验收怎么算过

| 项 | 判据 |
| --- | --- |
| 能报出上屏时刻 | 每帧一对 `(desired, actual)`，且 `actual` 落在 `CLOCK_MONOTONIC` 量级 |
| Δ 可复算 | 独立脚本从原始行重算 p50/p95/p99/max/vsync-miss，与汇总逐位一致 |
| 有区分度 | 空载与负载（5 忙循环）两组 Δ 必须能分开；分不开说明这个量测不出东西 |
| 不许美化 | 负载组变差就写变差。C7 买的是"不受调度摆布"，不是"上屏更准"，两者不是一回事 |

## 五、实验设计

| 轮 | 排程 | 负载 | 看什么 |
| --- | --- | --- | --- |
| P1–P2 | `surface_at_time` | 空载 | 基线 Δ（预期 < 1 个刷新周期） |
| P3–P4 | `surface_at_time` | 5 忙循环 | 负载下 Δ 是否变大、vsync miss 是否出现 |
| P5 | `cpu_paced` | 空载 | 工具必须拒绝算 Δ，并说明原因 |

片源用 `long_1080p8.mp4`（24 s，30 fps）—— 要够长，才能在 dump 之前攒够 4 s 的窗口。

## 六、明确不做

- **不做 GL 改造**（`eglPresentationTimeANDROID` + `EGL_ANDROID_get_frame_timestamps`）。
  那条路能拿到更细的 `EGL_TIMESTAMP_*`（含 `RENDERING_COMPLETE`、`PRESENT` 分项），
  但代价是把直出 Surface 改成 GL 渲染，整条呈现链路要重写。
  **在 `dumpsys` 已经够用的前提下，没有理由先付这个代价。**
- **不做 `--frametimeline`**：实测返回空。
- **不做多设备**：只有 K40。
- **不改 `av_drift` 的语义**。Δ 是"上屏端"的量，`av_drift` 是"交出端"的量，
  两者**并列**存在、各有各的证据字段，不合并 —— 合并之后就没有人能判断
  "偏差是发生在我们的决策里，还是发生在合成器里"。

## 七、风险

| 风险 | 处置 |
| --- | --- |
| 128 行环形缓冲导致窗口不可控 | 清空后立刻起播、4 s 内 dump；把窗口边界写进证据 |
| 层名取错（这次就是栽在这） | 从 `--list` 现取，且**取不到就报错退出**，不许回落到"没有 id 的名字" |
| 厂商改 `frameReadyTime` 语义 | 只把第一、二列当判据，第三列只记录不判断 |
| 把 Δ 当成"液晶上的时刻" | 写进 §4.2 第 3 条，并写进状态文档的诚实清单 |
