# 176 · 决策材料：`present_jitter` 的"最差"是 max 还是 max-abs？

- 状态：**待拍板**（不是设计稿，是两案对照 + 建议）
- 前置：`175-p14ag-status.md` §七、`174-p14ag-design.md` §四之二

## 一、问题

`render_quantiles()` 有一个既有约定：`worst.lateness_ns` **必须与同口径直方图的 `max_ns()` 逐位相等**
（判据 F1 在守它）。这条约定在 `lateness` / `av_drift` 那三块上是合理的 —— 那里"最差"就是
"迟到最多"（晚比早糟）。

但 `present_jitter` 的样本是**有符号**的：`间隔 − 期望`。早交 80 ms 与晚交 80 ms 都是"画面跳了一下"，
**没有哪个方向天然更糟**。于是"最差"有两个候选定义，而它们给出的答案常常不同。

## 二、实测：这不是理论问题，283 轮里 30% 受影响

把 283 份有 `present_jitter` 直方图的证据全扫一遍（`histogram.min_ns` / `max_ns` 都是精确极值）：

| 事实 | 数字 |
|---|---|
| `\|min\| > \|max\|` 的轮次 | **148 / 283（52%）** |
| 其中差距 > 10 ms 的 | **86 轮（30%）** |
| 这 86 轮里 `frames_dropped = 0` 的 | **70 轮** —— 也就是说，**它们不是丢帧的副产物** |
| 这 86 轮的 `\|min\|` 中位 / `\|max\|` 中位 | **32.4 ms / 5.0 ms** |
| 这 86 轮里 `\|min\| > 100 ms` 的 | 11 轮 |
| 单轮最大差距 | **954.6 ms**（`p14ag-999ms-b1`：`min = −955.67`，`max = 1.11`） |

最刺眼的一行：`p14ad-800ms-b1` 的 `present_jitter.max` 印的是 **0.47 ms**，
而同一份证据的直方图里躺着一笔 **−754.93 ms**。**没有任何一格 headline 数字说得出它。**

那 11 轮 `|min| > 100 ms` 里，多数是丢帧的另一面（一次跳掉 24–31 帧，下一帧的"间隔 − 期望"
自然是个大负数），但也有 70 轮没有任何丢帧 —— 那是**真实的抖动**，只是方向为负。

## 三、三个选项

| | 定义 | 代价 | 谁能读对 |
|---|---|---|---|
| **A**（现状） | `worst = max`，F1 逐位守 | 30% 的轮次把"最差"报小了；`p14ad-800ms-b1` 报 0.47 ms 而真值是 −754.93 ms | 只有翻 `histogram.min_ns` 的人 |
| **B** | `worst = max-abs`，改 F1 为 `\|worst\| == max(\|min\|,\|max\|)` | F1 的语义变了；`av_drift` 那三块若共用同一段代码，会一起变（那里"晚比早糟"是对的，不该跟着变） | 所有人，但 `av_drift` 那三块的读法要重新解释 |
| **C**（建议） | 新增一格 **`present_jitter.worst_abs = {value_ns, media_ns}`**，`worst` 那套一个字不动 | 多一格；`worst_abs` 的名字与 `worst` 并存，要写清楚区别 | 想要"最极端"的人看 `worst_abs`；沿用 F1 的人看 `worst`（本块仍没有 `worst`） |

## 四、建议 C，理由是三条

1. **不动既有语义**。F1 守的是"最差 = 最大迟到"，那在 `lateness` / `av_drift` 上是对的；
   jitter 是两个方向都算糟，那条约定本来就不适用 —— **不该让一个不适用的约定去改另一个块**。
2. **名字即口径**。`worst` 与 `worst_abs` 摆在一起，读的人必须选一个，选的时候会问"差别是什么"，
   而答案就写在字段名里。这比在注释里解释"这里的 worst 其实是 max-abs"可靠。
3. **可判**。`worst_abs` 能直接对直方图验：`|value_ns| == max(|min_ns|, |max_ns|)`，
   不需要引入新的采样。

## 五、若选 C：改动与判据草案

| 位置 | 改动 |
|---|---|
| `PaceStats` | 记一个 `interval_worst_abs_`（`media_ns` + 带符号 `value_ns`） |
| 报告 | `present_jitter.worst_abs = {value_ns, media_ns}`（`/41` → `/42`） |
| 判据 **AH1** | `\|value_ns\| == max(\|histogram.min_ns\|, \|histogram.max_ns\|)`（逐位） |
| 判据 **AH2** | `media_ns` 必须落在 `[首帧 pts, 末帧 pts]` 之间；且 `samples > 0` 时该格必须存在 |

预算：源码约 +12 行，判据 +20 行，单测 +25 行（三笔样本的替换逻辑 + reset）。

**读法上还要加一句**（写进 `176` 的结题与 `CURRENT`）：
`worst_abs` 与 `dropped_events.total` 必须一起读 —— 一次跳掉 24 帧会让 `worst_abs` 变成
−755 ms 那种数，那是"丢帧的另一面"，不是"调度抖了一下"。11 轮 `|min| > 100 ms` 里多数是这种。

## 六、若选 B：要连带改的东西（列出来是为了说明代价）

1. F1 的判据要从 `worst == max_ns` 改成 `|worst| == max(|min|,|max|)`；
2. `av_drift` 三个块共用 `render_quantiles`，得加一个开关区分"单向"与"双向"口径；
3. 13 份引用 F1 的老证据要重新解释（它们当时是 max，不是 max-abs）；
4. `lateness` 的 `WorstEpisode`（P13-P）要不要跟着改？它现在是"最差 = 最晚"。

这四条没有一条是"顺手"能做的，所以我不建议为了一个字段走这条路。

## 七、我的建议

**选 C**，并把 §五 那句读法一起写进交接文档。若你同意，下一张卡（P14-AH）就按 C 落地：
`worst_abs` + AH1/AH2 + 三轮真机（对照 / 一次丢帧 / 一次纯抖动）。
