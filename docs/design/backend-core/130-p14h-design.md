# P14-H 设计卡：让守卫知道过了多久

- 上游：`129-p14g-status.md`（4 次钳制的候选步长与观测间隔逐位相等，残差≈0）
- 落位：`core/audio/clock/monotonic_clock_guard.{hpp,cxx}`；调用方 `backends/aaudio/clock/aaudio_clock_source.cxx`
- 证据：`docs/evidence/p14h/`（注入回归 + 60 s 烟测 + 30 分钟长跑）

## 一、缺陷的形状

守卫现在的逻辑（`monotonic_clock_guard.cxx`）：

```cpp
const std::int64_t advance = candidate_ns - max_ns_;
if (advance > jump_threshold_ns_) { clamp; }
```

`advance` 是"位置前进了多少"，但**没有减去这段时间里位置本来就该前进的量**。
阈值 200 ms 的注释写着"远大于任何合理查询间隔（一个视频帧 16–42 ms）" ——
它把"查询间隔很小"当成了前提，而这个前提在真机上不成立：

| 场景 | 间隔 | 位置前进 | 残差 | 旧行为 | 该有的行为 |
| --- | --- | --- | --- | --- | --- |
| 片尾等 EOS | 383 ms | 383 ms | ≈ 0 | **钳掉 200 ms** | 放行 |
| 启动首帧 | 284 ms | 284 ms | −9.7 µs | **钳掉 200 ms** | 放行 |
| 真实跳变（注入） | 0.5 ms | 226 ms | 225.5 ms | 钳制 ✓ | 钳制 ✓ |

三行的区别只有一个量：**残差**。而旧逻辑里根本没有它。

## 二、修法：把"该走多少"还给判定

```cpp
allowance = jump_threshold_ns_ + elapsed_ns;      // 这段时间最多能合理前进多少
if (advance > allowance) { clamp 到 max_ns_ + allowance; }
```

- `elapsed_ns` 由调用方给（`AaudioClockSource` 知道墙钟，守卫是纯逻辑、不拿时钟）。
- 默认参数 `0`：等价于旧语义，既保住全部既有桌面断言，也是**最保守**的一侧
  （调用方没说自己过了多久，就按"没过时间"判）。
- 上限保护：`elapsed` 超过 1 小时按 1 小时算，避免 `threshold + elapsed` 溢出。

## 三、为什么不走另外两条路

| 方案 | 为什么不做 |
| --- | --- |
| 调用方发现长间隔就 `guard_.reset(candidate)` | 重置会**顺手关掉倒退保护**一个窗口，而且这次事件从 `jumps_clamped` 里**彻底消失** —— 计数器变干净了，但代价是"真的跳了"也看不见。**证据不能靠删事件变好看。** |
| 把阈值从 200 ms 调大（比如 1 s） | 只是把误判的边界挪走：400 ms 的间隔照样误判，而真实跳变的检测被削弱 5 倍。**挪阈值治不了量纲错。** |

## 四、判据

| 编号 | 判据 | 为什么它能抓错 |
| --- | --- | --- |
| H1 | 注入 300 ms 台阶后 `jumps_clamped ≥ 1` 且 `beyond_threshold ≥ 1` | **回归**：修完之后真跳变还必须被钳制。只看"不再误伤"会做出一个什么都不拦的守卫 |
| H2 | 60 s 烟测 `jumps_clamped = 0` 且 `long_gaps ≥ 1` | 修法的直接证据：同一段启动期停顿，以前钳 1 次、现在 0 次，而间隔照样被记下来 |
| H3 | 30 分钟长跑 `jumps_clamped = 0` | 稳态与片尾都不再误伤 |
| H4 | 上述三份都满足 `verify_p14g_tail` 的 T1–T7 | 尾部记账不许因为改守卫而错位 |

## 五、桌面单测（`kivo_p12c4_clock_tests`）

| 例 | 断言 |
| --- | --- |
| 既有 C1/C2/C2b | 不传 `elapsed` 时语义不变（倒退仍拒、跳变仍钳、正常仍放行） |
| C24 | 间隔 287 ms + 位置同量前进 → **不钳制**（P14-G 的假案） |
| C25 | 间隔 0.5 ms + 位置跳 225.5 ms → **钳制**，且位置只放行 `threshold + elapsed` |
| C26 | 间隔 190 ms + 位置前进 210 ms → **不钳制**（残差 20 ms，间隔已解释掉） |
| C27 | 钳制之后 `max_position_ns` 的增量必须等于 `allowance`（不是裸阈值） |

## 六、诚实边界

1. 这个修法把"我们没看的那段时间"整段放过 —— 如果设备**真的**在那段时间里跳了，
   我们不会发现。可接受：没有观测就没有证据，假装能判才是错的。
2. `elapsed` 由调用方给，调用方算错就全错。所以 `AaudioClockSource` 里那份 `elapsed`
   必须与 `tail` 用的间隔**同一个来源**（同一个 `last_mono_ns_`），否则两处会分叉。
3. 不解决"查询循环为什么会停 383 ms"。它只是让停顿不再变成假跳变。
