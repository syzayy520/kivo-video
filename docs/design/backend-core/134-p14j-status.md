# P14-J 状态卡：那 230–250 ms 在收尾，不在启动

- 上游：`133-p14i-status.md` §六.1（"260 ms 究竟在启动还是收尾，本卡没有钉死"）
- 落位：`backends/aaudio/clock/aaudio_clock_tail.{hpp,cxx}`；证据 `kivo.p12c.sync/24` 的 `audio.clock.tail`
- 校验：`python tools/verify_p14g_tail.py docs/evidence/p14j/*-sync.json` → **2/2 exit 0**（T1–T8）
- 门禁：`ctest -R "kivo_p1[234]"` **25/25**；`kivo_p12c4_clock_tests` **148 断言**

## 一、加了三个字段

| 字段 | 含义 |
| --- | --- |
| `span_ns` | 会话已观测的跨度（最后一个间隔终点 − 起点） |
| `first_long_gap_at_ns` | 第一次 ≥200 ms 间隔发生在**第几纳秒**（相对起点，`-1` 表示没有） |
| `last_long_gap_at_ns` | 最后一次 |

**为什么要两个而不只留一个**：同一次会话里可能两端各来一次。
只留最后一个，"开头那次"就被抹掉；而开头（预热/首帧）与结尾（排空 + 收尾快照）
的含义完全相反。

## 二、两轮 60 秒：都在最后一圈

| 轮 | 长间隔 | 位置 | `span_ns` | 判断 |
| --- | --- | --- | --- | --- |
| r1 | 1 次 / 253.0 ms | **+60.23 s** | 60.23 s | 位置 == 跨度 → **最后一圈** |
| r2 | 1 次 / 228.5 ms | **+60.21 s** | 60.21 s | 同上 |

两轮都只有一次长间隔，而且**位置与跨度逐位相等** —— 它就在观测的最后一个间隔里。
60 秒片源在 60 秒处结束，所以这是**收尾**：`audio_playback` 的排空
（`kDrainTimeoutMillis = 300`）+ `output_->stop()` + `clock_end_ns` 快照。

**启动端这两轮一次都没有长间隔。** P14-G 烟测里"启动后 757 ms 的钳制"是个偶发，
不是每次都有的固定行为 —— 两轮都复现不出来，本卡不替它编解释。

## 三、判据 T8

| 条件 | 检查 |
| --- | --- |
| `long_gaps > 0` | `last_long_gap_at_ns ∈ [0, span_ns]` 且 `first ≤ last` |
| `long_gaps == 0` | 位置必须是 `-1`（不能记下一个不存在的事件） |

对 `/24` 之前的证据**显式跳过**（它们的 tail 里没有这两格），不重写历史文件。
跳过是打出来的，不是静默的。

## 四、桌面单测

`kivo_p12c4_clock_tests` 新增 C28 / C29（148 断言）：

| 例 | 断言 |

| C28 | 位置相对**会话起点**（1 ms）而不是 0；`span_ns` 同步 |

## 五、结论：这条线封口

P14-G → H → I → J 四张卡连起来：

| 卡片 | 问题 | 结论 |
| --- | --- | --- |
| P14-G | 钳制多久一次 | 2 小时 **0 次真跳变** |
| P14-H | 假钳制怎么来的 | 守卫判跳变不看时间；修好后**钳制归零** |
| P14-I | 那 200–380 ms 是什么 | **不是循环停顿**（循环最长 41.9 ms） |
| **P14-J** | 那它在哪一端 | **收尾**（位置 == 跨度），不在启动 |

对"最稳定播放器"的意义：**播放期间没有可归因的停顿**；
剩下的 230–250 ms 全部发生在片尾、用户已经看到最后一帧之后。
继续在这条线上挖的收益已经接近零。
