# 94 · P13-T 设计：把「门有没有生效」变成能判的一件事

> 卡片：P13-T
> 前置：P13-S（`92-p13s-design.md` 装了门，但真机 `drift_rebases` 全 0，A/B 不成立）
> 结论：两件事——① 修掉"算了但没出版"的字段；② 用**受控负载 + 实测空闲率**把
> "尖峰"与"时钟位移"分开

---

## 一、问题

P13-S 的结论卡在两个不确定上：

1. **计数没有走到证据**。`drift_rebases` 在 `PaceStats` 里算了，`PaceStats::summary()`
   却没写进 `PaceSummary` —— 于是"门没响"与"门响了但没出版"长得一模一样。
2. **负载没验证**。三轮里 r1 空载异常、r2/r3 标称满载正常，说明忙循环可能根本没起来
   （P12-D5 犯过同一个错：`TaskStop` 只杀了本地 adb，远端 44 个忙循环还在）。

---

## 二、判据设计

### 2.1 接线：S3 端到端单测

用 1.5% 的假快钟驱动**完整** `FramePacer`（不是只驱动 tracker），断言
`pacer.summary().drift_rebases >= 1`。这一条同时钉住三段：
tracker 判定 → `PaceStats::note_drift_rebase()` → `summary()`。

### 2.2 负载：每轮前实测空闲率

`/proc/stat` 首行取两次（间隔 1 s），`idle_delta / total_delta` 即空闲率。
每轮记进证据旁边的一行文本 —— 不写进 JSON schema（那是另一件事），
但必须能与该轮对应。

### 2.3 分离两个现象

同一批轮次里同时看三组数：

| 组 | 读数 | 说明什么 |
|---|---|---|
| 尖峰 | `per_frame.max` | 交出动作晚没晚 |
| 时钟 | `clock_ahead` / `playback_rate` | 时间轴有没有被推快 |
| 门 | `drift_rebases` | 门有没有被触发 |

三者能分开，才谈得上"门有用"或"门没用"。

---

## 三、验收

| 编号 | 判据 |
|---|---|
| T1 | S3 单测通过（1.5% 快钟 ⇒ `summary().drift_rebases ≥ 1`） |
| T2 | 每轮记实测空闲率，且写进结题表 |
| T3 | 至少一轮出现"尖峰大、时钟不动"或"时钟动、门响"的分离组合 |
| T4 | 总收口四层通过 |
