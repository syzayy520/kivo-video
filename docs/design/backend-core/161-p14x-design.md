# 161 · P14-X 设计：给每一笔复位一个时刻

- 日期：2026-10-31
- 前置：`160-p14w-status.md`（60 s 上量到一笔 104.71 ms 的修正，解释是"启动期盲区一次还清"）
- 目标：把那个解释变成**可证伪**的断言 —— 记录每一笔复位"什么时候、修了多少、修之前领先多少"。

---

## 一、要证伪的那句话

P14-W 在 4K30 的一轮里看到 `drift_max_correction_ns = 104.71 ms`，是迟滞带（5 ms）的 21 倍；
同一批另外两轮只有 5.2 / 5.8 ms。当时的推断是：

> 启动期（首帧后 1 s，P13-W 的保护）里 `cum` 自由累积；盲区一结束，
> 第一次读把攒下的量一次还完。

算术上它自洽（`350.16 − 49×5 = 105.16`），但**证据里没有时刻**，
所以它只是"最自洽的解释"。这一卡就是给它一个时刻。

## 二、怎么记

`ClockPositionTracker` 加一个定长环：

```cpp
struct RebaseSample {
    std::int64_t at_ns;          // 距首帧读数（相对量：绝对单调钟列出来没法读）
    std::int64_t amount_ns;      // 这一笔修了多少
    std::int64_t lead_before_ns; // 修之前看到的领先量（恒 ≥ amount）
};
```

只留**最近 8 笔** + 首笔时刻 + 最大一笔。不做无界列表：两小时的会话会有上万个样本，
而"最大那笔在什么时候"三个数就能回答。8 笔 = 8 s 的迟滞带锯齿，够看出形状。

出版（`sync/35`，顶层 `drift_rebase_trace`）：

```json
{"rebases": 49, "sampled": 8, "first_at_ns": 11020000000,
 "max": {"at_ns": 24430000000, "amount_ns": 146750997, "lead_before_ns": 186750997},
 "recent": [ ... 8 笔 ... ]}
```

## 三、判据（X 组）

| 判据 | 内容 | 打红意味着 |
|---|---|---|
| X0 | 没复位过就必须是干净的空 | 幽灵样本 |
| X1 | `trace.rebases == clock_health.drift_rebases`、`sampled == min(rebases, 8)`、`len(recent) == sampled` | 三处计数有一处漏写/重复写 |
| X2 | 时间严格升序、幅度为正、`amount ≤ lead_before` | 环回绕写错，或修得比看到的还多 |
| X3 | `trace.max.amount_ns == clock_health.drift_max_correction_ns` | 同一个数两处各算一遍 |
| X4 | 单笔 > 迟滞带 + 一帧 ⇒ 那一轮必须有一次可查的钟事件 | 门在自己造偏差 |

**X4 的第一版写的是"必须落在 ≤3 s"**（即验证启动期假说）。这一版被真机数据推翻了，
见 `162-p14x-status.md` §三 —— 现在的 X4 守的是**已证实的规律**，不是一个猜测。

## 四、预期

- 四轮 4K30 60 s（5 000 ppm，门开），至少有一轮出现"单笔 ≫ 迟滞带"；
- 若启动期假说成立，`max.at_ns` 应落在 **1.0 s 附近**；
- 所有轮的 `first_at_ns` 应在 **11 s 附近**（`reach = 9 s` + `arm_after = 2 s`）；
- 正常轮的最大单笔应在 `band + 一帧 = 38 ms` 以内（4K30 一帧 33.3 ms）。

## 五、不做的事

- 不改门的判据（`limit` / `band` 一个不动）。这一卡只加观测。
- 不把 `recent` 做成变长数组：定长 8 笔对"看出形状"够用，而变长会让报告大小
  随会话长度增长 —— 一份两小时的证据里塞一万个样本，没人为那个精度付钱。
