### 2.1 r2 是这张卡的靶心

P13-J 和 P13-K 都在回答"与 0 分得开吗"。r2 说：**分得开**（CI 两端全负，`detectable = true`）。
如果只有这两张卡，读者会把这个 `true` 读成"有漂移，得管"。

`/10` 紧接着说：这个漂移在 99.97 秒里累积 **34.3 µs**
—— 相当于 60 Hz 一帧（16.7 ms）的 **0.2%**，额度的 **0.076%**。

两句话不矛盾，它们是同一件事的两个维度：

```
看得见（尺子细）  ✅   CI = [−0.683, −0.003] ppm，不含 0
要紧吗（量太小）  ❌   34.3 µs，人耳检测阈值的 0.076%
```

这正是本卡存在的全部理由。在 r2 之前，这个组合只在单测里被构造出来过（`t10` 第一例）。

### 2.2 `r2 = 0.0015` 与 `detectable = true` 可以同时成立

直觉上"只解释 0.15% 方差"和"分得开"该互斥，其实不然：
`r2` 是**信号占方差的比例**，`detectable` 是**信号相对其标准误的大小**。
样本量足够大时，极弱的信号也能从噪声里分出来 —— 2000 个点、SE 0.173 ppm、
斜率 −0.343 ppm，t 统计量约 −2.0，刚好压线。

所以两个字段都不能单独用来判断"要不要管"。管不管，看累积量。

### 2.3 一个副作用：P13-J 的精确中位数在真机上真的生效了

| 轮次 | `first_window_median_ns` | `last_window_median_ns` | `delta_median_ns` |
|---|---|---|---|
| r1 | **74 000** | **74 219** | +219 |
| r2 | **75 417** | **72 709** | −2 708 |
| r3 | **77 178** | **75 251** | −1 927 |

P13-D 到 P13-I 的八窗中位数**一直全是 125 000**（桶中心）。这一轮全是 74~77 µs
—— P13-J 换成原始值 `nth_element` 之后第一次在真机上给出连续读数。

同时暴露 P13-J 遗留第 ③ 项仍在：整场 `quantiles.media_time_decimated.p50`
三轮也都是 **125 000**。趋势说 74 µs，整场分位数说 125 µs，同一个物理量差 **69%**。
两份都在同一份证据里并排躺着，谁也没标"我这是桶中心"。

### 2.4 r1 的两个数方向相反，而它们都"对"

r1：`drift_accumulated_ns = −24.3 µs`（整段在往下走），
`delta_median_ns = +219 ns`（末窗比首窗**高** 0.2 µs）。
方向相反，量级差 111 倍。

这不是算错，是**序列不线性**的证据：半程斜率 +0.397 / +0.220 都是正的，
而全序列斜率 −0.238 —— 说明中途换过向。`slope_halves_agree = true` 只因为两个半程同号，
它看不见"前半比后半陡 1.8 倍"这件事。

这条直接印证诚实清单第 3 条：**上界只覆盖斜率的抽样误差，不覆盖模型失配。**
r1 的 63.9 µs 上界是在一条本身就不成立的直线上算出来的。

### 4.2 第一版变异自测是假的（必须记下来）

第一版用 `shutil.copy2` 还原，而它**连 mtime 一起复制**。
恢复后的源文件比 `.obj` 更旧，MSBuild 判定"无需重编"，
于是从 m03 开始，每一条变异测的都是**同一条陈旧二进制**。

表现是：m04 起的失败列表里带着 m03 特有的三条（`kAudibleThresholdNs == 45 * kMs` 等），
而 m04 该有的那条（`on_edge` 判成 over）反而没出现。
第一版打印的是"存活 0 / 10"和一个"还原后：红"——**那个 0/10 是假的**。

改法：`copyfile` + `os.utime(now)`，并给每条变异加**三段式守卫**
（注入前必须绿 → 注入后必须红 → 还原后必须绿，任何一段不符立即中止）。
重跑之后每条失败的断言都与注入点对得上，这才是真的 10/10。

## 五、诚实清单

1. **45 ms 是检测阈值，不是可接受上限。** 三轮 `within_budget` 只说明
   "这三段播放的漂移大概率听不出来"，不说明体验合格。
2. **累积量只覆盖 `span_ns` 那一段。** r1 的 2048 点只覆盖 102.4 s，
   片源 130 s —— 前面 27.6 s 被环形覆盖掉了。长片源上这个数是**下限**。
3. **上界只覆盖斜率的抽样误差，不覆盖模型失配。** r1 就是活证据：
   全序列斜率说 −24.3 µs，首末窗口中位数说 +219 ns，方向相反。
   那条 63.9 µs 的上界是在一条本身就不成立的直线上算的。
4. **三态没有区分"算出来了但趋势不可用"。** `unknown` 时四个数值字段里
   可能真有一个算出来的累积量，读者只能靠 `upper != 0` 去猜。这是为换取
   判定语义单一性而接受的信息损失。
5. **判的是漂移增量，不是绝对偏移。** 三轮的 `lateness` 中位数在 74~77 µs，
   而 `verdict` 一个字也没提这个数。绝对偏移归分位数那份。
6. **45 ms 对称使用，比标准偏严。** BT.1359 是 +45 / −125 ms 的不对称阈值。
7. **三轮全 `within_budget` 不等于验收通过。** 同一批证据里
   `quantiles.p50 = 125 000` 而趋势中位数 74 000 —— 差 69%，这个矛盾还没解决（见 §六②）。
8. **`estimated` 没有写进 JSON。** 结构体里有，报告层没输出。
9. **向前 seek 不切段 —— 本卡撞出的缺陷。** `DriftSeries::note()` 只在
   媒体时刻**倒退**时切段。媒体时刻**向前跳** 10 秒（seek 到更后面）时，
   它看到的只是"前进"，于是两段被拼在一起回归。
   物证在 `docs/evidence/p13l/defect/p13l-forward-seek-mixed-sync.json`：
   `segments = 1`、`segment_accepted = 2400 > capacity = 2048`、`span = 112.367 s`
   —— 序列跨了一个 10 秒空洞，而 `verdict` 照样报 `within_budget`。
   **这份证据的累积量不可引用**，它被隔离在子目录里，不进总收口。
10. **`drift_verdict` 不参与 `usable` 之外的任何判定。** 它现在只是一个结论，
    校验器、报告层、JSON 都没有拿它去 gate 别的东西 —— 所以它写错了
    只能靠 L2/L3 间接抓住。这是刻意留的窄接口，也意味着它的正确性目前
    依赖那六条判据，而不是某个更强的结构约束。

## 六、下一步

按优先级：

1. **向前 seek 切段**（缺陷，见诚实清单第 9 条）。判定条件不能只看"倒退"——
   需要区分"媒体时间跳了 10 秒"和"解码卡了 10 秒"。
   `unobserved_cells` 是现成的信号：跳跃会产生上百个没帧跨过的格点，正常卡顿不会。
   要定阈值、要论证、要给向后 seek 与正常卡顿两条对照 —— 独立一张卡。
2. **整场 `quantiles.*.p50` 仍是桶中心 125 000**，而趋势中位数已是 74 000。
   同一份证据里两个数差 69%，没有任何字段标明"我这是桶中心"。
   P13-J 只修了趋势那一侧。
3. **跨轮汇总判据**。单轮 `verdict` 不是设备常数（P13-K 已证 SE 从 0.2152 跳到 1.762968）。
   现在三轮各报各的，缺一个"多轮放在一起看"的单元。
4. **`slope_halves_agree` 太弱**：r3 的前半 −2.915 / 后半 −0.217 也被判"一致"
   （只因同号）。它需要一个量级比，而不只是符号。
5. **`media_span` 的多段算法只有单测覆盖**，真机上没验过（本次 r2 的
   `media_span = 159.867 s > 片长 130 s`，因为两段相加 —— 这是对的，但没人判过它）。
