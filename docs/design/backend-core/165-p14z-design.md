## 一、要回答的那句话

P13-W 定过一条规则：启动期之外的 30 ms–1 s 正向台阶"按墙钟吃掉"，
理由是**不还的话时间轴整体平移，帧会一次性迟到、然后丢**（S5 用例的名字就叫
"中台阶必须被吃掉"）。P14-X 又量到：还它的代价是**一帧修正 146.75 ms**
（迟滞带 29 倍）。P14-Y 把这两件事记进了同一本账。

于是问题变成一句可以被数据回答的话：

> 一次 120 ms 的钟台阶，是**还掉**（画面平滑，但 A/V 差 40 ms 常驻），
> 还是**不还**（A/V 对齐，但时间轴一跳 120 ms）？

两条都不是"正确"，是两个不同的代价。**必须先测出各自的代价，再谈默认值。**

## 二、两臂的定义

| 臂 | 开关 | 门 | `cum` 的输入 | 预期 |
| --- | --- | --- | --- | --- |
| A（今天） | `step_repay = true` | 开 | `raw_lead` | 台阶被还，`|lead|` 收敛到 `limit − band = 40 ms` |
| B（探针） | `step_repay = false` | 开 | `raw_lead − offset` | 台阶不还，`|lead|` 停在台阶量级（≈120 ms） |

**两臂只差一个开关**：门都开着、注入相同、片源相同。否则比的不是这件事。

要测的量（都已在 `/36` 的出版里，不需要新字段）：

| 量 | 在哪 | 读它回答什么 |
| --- | --- | --- |
| `clock_lead_trace.last_ns` | 报告 | 这一段结束时 A/V 差多大（相对墙） |
| `clock_health.drift_max_correction_ns` | 报告 | 还的时候那一帧有多狠 |
| `frames_dropped` / `present_gap` | 报告 | 不还的时候画面有没有被打断 |
| `drift_discontinuity.*` | 报告 | 台阶本身长什么样（两臂应逐位相同） |

## 四、判据（Z 组，只在桌面单测里）

| 判据 | 内容 |
| --- | --- |
| Z1 | A 臂：注入 120 ms 台阶后 `drift_rebases == 1`，`max_correction ≈ 80 ms` |
| Z2 | B 臂：同一注入下 `drift_rebases == 0`，且 `offset` 与 A 臂逐位相同 |
| Z3 | 无台阶轮：两臂的 `drift_rebases` / `max_correction` / `lead` **逐位相同**（开关不该影响它） |
| Z4 | B 臂下台阶仍在账里（`events == 1`）—— 不还 ≠ 不记 |

Z3 是这一卡的"不该动的东西"：一个探针开关如果顺手改变了正常轮次，它就不是探针了。

## 五、真机（两臂各两轮，注入 +120 ms @20 s，4K30 60 s）

| 轮 | 臂 |
| --- | --- |
| z1 / z2 | A（`step_repay=on`） |
