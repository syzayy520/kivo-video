# 168 · P14-AD 设计：台阶幅度扫描 —— "不还"的代价从哪一段开始付

- 状态：**已执行**，见 `169-p14ad-status.md`（这一卡不改产品代码，只有脚本 + 证据 + 两篇文档）
- 前置：`166-p14z-status.md`（两臂 120 ms 对照）、`164-p14y-status.md`（不连续那本账）

## 一、这一卡要回答什么

P14-Z 量到一件与 P13-W 相反的事：**B 臂（台阶不还）在 120 ms 上 0 丢帧**，
`undelivered = 0`、`jitter.max = 21.23 ms`（一帧 33.3 ms 以内）。
而 P13-W 立"中台阶必须吃掉"的理由正是"不还就整体平移，帧一次性迟到然后丢"。

**一个点定义不了一条曲线。** 这一卡把幅度做成自变量，问三件事：

1. "不还"的代价是不是只在某个幅度以上才出现？若是，阈值在哪一段？
2. "还"的代价（一次性修正）是不是随幅度线性增长，而残差恒定？
3. 两臂的残差各自长什么样 —— 这是 A/V 偏差真正留在哪里。

## 二、自变量与因变量

| 项 | 取值 | 为什么 |
|---|---|---|
| 台阶幅度 | **0 / 120 / 300 / 800 ms**（正台阶） | 120 是 Z 的点；300 ≈ 9 帧；800 ≈ 24 帧，仍在跳变门限以内 |
| 速率注入 | **`rate_ppm = 0`** | 这一卡的自变量只有一个。5000 ppm 在 60 s 里自己就攒出 300 ms，会和幅度混在一起 |
| 臂 | `step_repay` on / off | 与 Z 同一套探针 |
| 轮次 | 对照 1 轮/臂，其余每格 2 轮 | 对照是曲线的零点，必须真实存在 |
| 片源 | `p13af_4k30_60s_av.mp4` | 与 Y/Z 同一份 |

**不选 ≥ 1000 ms**：`jump_limit_ns = 1 s`，跨过去 `jump_rebased` 会触发，那是另一种机制
（重锚 + 按墙推进），混进来曲线就读不懂了。那一段属于下一张卡。

**不选负台阶**：倒退钳制会把它吞掉（P14-Y 的 c2：−120 ms 只记 −33.60 ms，`raw = −86.6` 不进账），
自变量不干净。负台阶的账在 P14-Y 已经量过，不重复。

因变量：`frames_dropped` / `undelivered_frames` / `due_step_frames` / 末态 `|clock_lead|` /
`drift_max_correction_ns` / `present_jitter.max` / `drift_discontinuity.offset_ns` / `over_budget_frames`。

## 三、预测（先写下来，等着被打死；裁决见 169 §二）

| 编号 | 预测 | 若不成例会怎样 |
|---|---|---|
| **H1** | A 臂末态 `\|lead\| ≈ drift_limit − drift_band = 40 ms`，**与幅度无关**；单笔修正 ≈ 幅度 − 40 | 若 A 臂残差随幅度增长 ⇒ "修回带内"不成立，门在追不上 |
| **H2** | B 臂末态 `\|lead\| ≈ 幅度`（线性），代价出现在丢帧 / 迟到那一侧 | 若 B 臂也收到 40 ms ⇒ 有第二道机制在还，得找出来 |
| **H3** | 存在一个幅度，B 臂从"0 丢帧"翻成"丢帧" | 若 800 ms 仍 0 丢帧且 jitter ≤ 一帧 ⇒ **P13-W 的前提要重写成"只在 X 以上成立"**，不能再说"不还就丢帧" |

**H1 附带一个不好看但必须说的推论**：`40 ms > 33.33 ms`（30 fps 一帧）⇒
A 臂收敛后按 P14-AC 的定义仍是 `clock_off`。门的目标本身就是"贴着可闻阈值（45 ms）的下限"，
不是"归零"。这不是判据太严，是目标函数的性质 —— 这一卡会用四组数据把它钉住。

## 四、判据：只加一条

**AD1（正台阶必须进账）**：`clock_injection.offset_ns > 0` 且门开着时，
`drift_discontinuity.offset_ns` 必须满足 `|offset − injected| ≤ band + 一帧`。

为什么加这一条、而不是加一堆：
探针（`step_repay = false`）是这一卡的实验条件，它**只许改门的输入，不许改账**。
哪天它悄悄连记账一起关掉，B 臂就会显示"零事件"，而那正是 P14-Y 花一整卡消掉的"沉默的零"。
这一条只对**正**台阶生效 —— 负台阶被钳制吞掉是已登记的行为，不能拿它判红。

**不加**"丢帧必须出现在有台阶的轮次"这类判据：自然轮也可能因为过热 OOM 丢帧，
那样的红是误报；丢帧有没有出处，靠证据里的 `over_budget_frames` 与 `due_step_frames` 读。
