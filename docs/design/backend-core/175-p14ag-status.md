## 一、补的是什么

`pace.dropped` 一直只是一个计数。一份证据说"丢了 24 帧"，却回答不了那个判读上最要紧的问题：

- **一次性丢** ⇒ 台阶被跳掉，之后恢复正常；
- **分散丢** ⇒ 基准一直在飘，说明有持续追赶。

两种形状在数字上完全一样。这一卡给丢帧补了现场：定长环 16 笔，每笔 `media_ns` + `lateness_ns`，
外加 `total` / `sampled` / `truncated` 三个数说明"还有多少没留下"。

## 二、三轮真机

| 轮 | `frames_dropped` | `total` | `sampled` | `truncated` | 现场（media） |
|---|---|---|---|---|---|
| 0 ms A（对照） | 0 | 0 | 0 | false | 空 |
| 800 ms B（不还） | 24 | 24 | 16 | **true** | 20.30 → 20.80 s（跨 500 ms） |
| 999 ms B（不还） | 31 | 31 | 16 | **true** | 20.53 → 21.03 s（跨 500 ms） |

## 三、答案：它是一簇，而且形状干净得可以直接读

`p14ag-800ms-b1` 的前四笔（注入在 20.0 s）：

| media | lateness |
|---|---|
| 20.300 s | **508.7 ms** |
| 20.333 s | 478.2 ms |
| 20.367 s | 450.1 ms |
| 20.400 s | 421.5 ms |

每帧降 **28–30 ms**，正好一帧（33.3 ms）的量级：**丢一帧、追回一帧、再看还差多少**，
直到迟到掉到退出阈值（`late_drop_ns / 2` = 50 ms）为止。环里最小的一笔是 77.3 ms，
与"追到 50 ms 以下就退出"对得上。

24 帧 × 33.3 ms = 800 ms ⇒ 第一帧大约在 20.03 s。环里只有 20.30–20.80 s 这 16 笔，
**前 8 笔被截掉了** —— `truncated = true` 说的就是这件事，不是"只丢了 16 帧"。

所以 P14-AD §九 留的那个问题现在有答案了：**不是分散丢，是注入之后 0.8 秒内的一簇**。
`999 ms` 那轮（31 帧）形状相同，起点晚 0.23 s、迟到从 501.5 ms 起 —— 与更大的台阶一致的偏移。

## 六、诚实清单

1. **环只有 16 笔**：800 ms 那轮丢了 24 帧，前 8 笔不在证据里。要知道起点，得靠
   `total × 帧长` 反推（20.03 s），或者把环加大 —— 这一卡选了前者，因为形状已经清楚。
2. **没有逐帧全量时间轴**：这是设计里明确不做的（§五.1）。要问"第 1000 帧为什么晚"，
   这份证据仍然答不了。
3. **判据不硬编码 `late_drop_ns`**：只要求 `lateness > 0`。阈值是策略、定义是"迟到"，
   判据不该把策略抄进来 —— 否则将来调阈值会连带改判据。
4. **`present_jitter.worst` 没做**：设计 §四之二 写了原因（`worst` 的既有约定是 max，
   而 jitter 的"最差"是 max-abs，两者在负向样本上会分叉）。这是下一张卡的第一件事。
5. **一台设备、一个片源**；两轮丢帧样本都是"不还台阶"的臂，A 臂那一侧（丢 0 帧）没有形状可看。
