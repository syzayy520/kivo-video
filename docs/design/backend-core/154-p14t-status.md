# P14-T 状态卡 · 那 5.6% 不是视频跑快了，是钟跑快了

> schema：`kivo.p12c.sync/30` → `/31`
> 一张卡只答一个问题：**P14-S 登记的 4 份越界，成因是什么？**
> 答案：**钟在墙上多走了 46–427 ms，视频忠实地跟着它走。** 而 `av_drift` 量的正是
> "视频相对这只钟"，所以它**结构性看不见**这个量 —— 那四轮真实听起来差 427 ms，
> 而报告里 `av_drift` p50 是 125 µs。
> 一句话副作用：**这 4 份今天复现不出来。** 同片源、同样的门关，领先量是 7.6 µs。

---

## 一、改了什么

| 位置 | 改动 |

| `avsync/report/av_sync_report.cxx` | `pace` 块印 `clock_lead_ns`，紧跟四跨度之后；`kSchema` → `/31`；版本历史补 `/31` 一段 |
| `tools/verify_p12c_sync.py` | 版本上限 → `/31`；**T1** 在场 + 逐位相等；**T2** 媒体盈余必须由钟解释（110 份，新判据）；**T3** 门开着时领先量不许超门限；越界归因带上领先量与门的状态；`KNOWN_OUT_OF_BAND` 升级为 `(说明, 领先量指纹)`，指纹容差 1 ms |
| `tools/verify_p12_all.py` | `/31` 进两张表（`SYNC_QUANTILE_BLOCK_SCHEMAS` 与 `KNOWN_SCHEMAS`）；`SCHEMAS_WITH_SYNC_END_REASON` 补 `/31` |

### 1.1 核心层的改动只有一行

```cpp
out.clock_lead_ns = out.elapsed_span_ns - out.arrive_mono_span_ns;
```

两个数从 `/16` 起就在报告里（P13-R 为四跨度恒等式加的），**一直可以相减，
一直没有人减**。P14-S 把 4 份越界登记进表、状态卡写"成因未查"，
而答案就在同一个块里相邻的两格 —— 差一个名字，就差了整整一张卡。

放在核心层而不是渲染层，是为了能在桌面上被单测钉住：报告层只在 Android 侧编译。

## 二、四份的答案

| 证据 | 钟领先量 | 媒体盈余（`pts − 墙钟`） | 两个数的差 | 领先 / 墙钟 |
|---|---|---|---|---|
| `p13r-4k60-r3` | 426 703 545 | 426 606 336 | 97 µs | 5.647% |
| `p13ad-rate50-off` | 331 771 991 | 331 717 534 | 54 µs | 4.336% |
| `p13s-4k60-r1` | 247 686 616 | 247 628 680 | 58 µs | 3.202% |
| `p13v-8x-r2` | 165 579 639 | 165 390 868 | 189 µs | 2.118% |

差都在一帧以内（16.7 / 33.3 ms）。这不是巧合，是恒等式：

```
due = mono + (pts − anchor − elapsed)   且   present ≈ due（lateness p50 = 125 µs）
⇒  pts − 墙钟 ≡ 钟领先量
```

### 2.1 它是一条全仓成立的关系，不只是这四份

**110 份带实测跨度的证据逐份复算，`|(pts − 墙钟) − 领先量|` 最大 189 µs**，
一份不差。另外 7 份例外全部是 `pts_span = 0`（`surface_at_time` 不给钟读数）——
那里压根没有分子，`|surplus| = 墙钟` 是必然的，不是反例。

于是这一版把它写成判据 **T2**：**媒体盈余必须由钟解释**（容差一帧）。
它抓的不是这四份（它们正满足 T2，属于"钟解释得了"的一类），而是
**以后出现的"视频真跑快了"**——那种情况盈余会有、领先量没有，T2 立刻红，
且报错指向视频而不是钟。变异 `V3` 就是这一条：把墙钟截短 30 ms、钟一格不动。

## 三、门的那条线（这是本卡唯一的真判据）

`drift_gate` 的作用是把钟的领先量夹回门限附近。全仓按门的状态分组：

| 门的状态 | 份数 | 领先量 min / 中位 / max |
|---|---|---|
| `enabled = true` | **58** | −0.122 / 11.948 / **44.938 ms**（门限 45 ms） |
| `enabled = false`（对照组） | 3 | 102.966 / 331.772 / 636.490 ms |
| 无 `drift_gate` 块（`/16`–`/19`，门还不存在） | 56 | −33.208 / 0.183 / 426.704 ms |

**58 份、一条不越。** 这不是"大约"，是门在干活的定义：越过 `limit` 进入收敛中，
修到 `limit − band` 才退出（P13-AC）。于是判据 **T3** 写得出来：
**门开着 + 领先量超门限 + 一帧 ⇒ 红**。它判的不是"跑得快不快"（那是区间的事），
判的是"门有没有在干活"—— 一个 `enabled=true` 却不干活的门，比没有门更糟，
因为报告上看不出来。

### 3.1 那 4 份落在哪

- `p13ad-rate50-off`：**门关着**（对照组，就是为对照生的）—— 领先 331.772 ms。
- 其余三份（`/16`、`/17`）：**门还不存在的年代** —— 领先 426.704 / 247.687 / 165.580 ms。

也就是说：**这四份越界全部落在"药还没出生"或"故意停药"的轮次里。**
这一条在真机证据上成立，而在**今天的构建上复现不出来** —— 见 §四。

## 四、真机三轮：一个负结果

设计只写了"跑一轮 1080p30"。实际跑了三轮，因为 §3.1 那条 29 ms 的缺口说明
"排队深度"解释不了全部，只有把门当唯一变量才回答得了"是不是门的账"。
**这是一次范围扩张，记在这里。**

| | 片源 | 门 | 领先量 | `media_rate` | 结论 |
|---|---|---|---|---|---|
| ① | 1080p30 / 60 s | on | **4 920 ns** | 0.999995 | 基线：钟几乎完美 |
| ② | 4K60 / 8 s | **off** | **7 555 ns** | 0.999978 | **没复现**（旧证据 118–427 ms） |
| ③ | 4K60 / 8 s | on | **7 868 ns** | 0.999987 | 与 ② 几乎一样 |

**②③ 一样，而且是微秒级。** 于是"越界是门的账"这句话**只对历史证据成立**，
对今天的构建不成立。三条预言（§五）都兑现了，但这一条是设计卡没预料的负结果。

顺带排除一个假说：今天的 4K60 轮次 `ring_full_waits = 5885`，
比 `p13r` 当时的 5088 **更多**，领先量却是 7.6 µs 而不是 427 ms。
**排队深度解释不了它。** 剩下的差别只有一个显眼处：`p13r` 那轮
`audio.clock.jumps_clamped = 3`，今天两轮都是 0 —— 线索，不是结论。

## 五、判据（新增三条）

| 编号 | 判什么 | 范围 | 现状 |
|---|---|---|---|
| T1 | `clock_lead_ns` 在场，且**逐位**等于 `elapsed_span − arrive_mono_span` | `/31` | 3/3 绿 |
| T2 | `|(pts_span − 修正墙钟) − clock_lead| ≤ 一帧` | 110 份有实测跨度的 | 110/110 绿，最大偏差 189 µs |
| T3 | 门开着时 `|clock_lead| ≤ 门限 + 一帧` | 58 份门开的 | 58/58 绿，最大 44.938 ms |
| 注意行 | `|clock_lead| / 墙钟 > 1%` ⇒ 打印"这一段 `av_drift` 不能当音画偏差读" | 全部 | 8 份会打 |

`KNOWN_OUT_OF_BAND` 的四条从"一句话"变成 `(一句话, 领先量指纹)`。
指纹容差 **1 ms**（比 T2 的一帧严一个数量级）：T2 判"归因对不对"，
指纹判"这份文件还是不是当初登记的那一份"。变异 `V6` 把 `p13r` 的领先量改 10 ms ——
在一帧以内、T2 抓不到，指纹抓到了。

## 六、单测（18 checks）

`kivo_p14t_clock_lead_tests`：

| 用例 | 守什么 |
|---|---|
| t1 | 钟快 5% 时领先量**逐位**等于两跨度之差，量级 187.350 ms |
| t2 | 钟按墙走时领先量 == 0（不是"大约 0"） |
| t3 | 钟慢时钟领先量为负，方向不许反 |
| t4 | 一帧都没有时是 0，且那个 0 不可读作"钟很准"（由 `clock_supplied_frames` 守） |
| t5 | **门开着时被夹到 45.000 ms**（同 5% 的钟，自由跑 187.350 ms） |

t5 是写测试时才发现的：第一版 t1 没关漂移门，量到的是 45 ms 而不是 190 ms ——
**测试测错了对象**。现在 `run()` 默认门关，t5 专门测门。

## 七、变异（7/7 全部按预期）

| | 变异 | 该红的地方 |
|---|---|---|
| V0 | 真机 `/31` 原样 | 全绿 |
| V1 | 去掉 `pace.clock_lead_ns` | 没有 `pace.clock_lead_ns` |
| V2 | 那一格改 1 ns | `clock_lead_ns 对不上` |
| V3 | 墙钟截短 30 ms、钟不动 | **媒体盈余对不上钟**（T2） |

## 九、诚实边界

1. **本卡只交付归因，不交付病因。** "钟在墙上多走了 427 ms"是算出来的；
   "为什么那只钟会多走"没有定案 —— §3.1 那条 29 ms 的缺口、§四那个
   `jumps_clamped = 3`，都只是线索。
2. **这 4 份今天复现不出来。** 同片源、同门关，领先量 7.6 µs。所以"修好了"这句话
   我也不敢说：我没有做二分，只知道**现在的构建上测不出来**。
3. **T2/T3 的容差是我定的。** 一帧对 T2、门限 + 一帧对 T3。前者来自"逐份核对最大偏差
   189 µs"（余量 88 倍），后者来自 P13-AC 的迟滞带语义。两个都不是从物理约束推出来的。
4. **T3 的 58 份是"没红"，不是"门被测过"。** 它们是历史证据的静态检查；
   真正把门打坏再跑一遍的，是变异 V4，不是真机。
5. **`clock_lead_ns` 在 `surface_at_time` 档恒为 0**（四跨度全 0）。和 `media_rate`
   一样，那个 0 不可读作"钟很准" —— 可测性由 `clock_supplied_frames` 守。
6. **`drift_gate.enabled` 缺失的 56 份**里混着两种东西：门还没出生（`/16`–`/19`）
   与更早的格式。判据把它们统一当"无字段"，没有细分 —— 因为它们都不在今天的判据线上。
7. **门限 45 ms 与区间 ±2% 不同量纲。** 45 ms 在 8 s 窗口上是 0.56%，在 2 s 窗口上是
   2.25% —— 也就是说**门开着的轮次在短窗口上仍然可能被判越界**。
   本卡没有处理这一条，它是下一张卡（§十.2）。
8. **`av_drift` 的定义没有改。** 让它减去领先量会立刻"修好"那四份 —— 而那正是本卡
   最不该做的事：先把判据调成能过，再去查为什么它过不了。现在报告里写着两个数，
   读者知道该减哪一个。

## 十、下一步（按价值排序）

1. **`av_drift` 该相对谁。** 现在它相对"这只钟"，而听得见的是"相对 DAC 实际播出的音频"。
   本卡证明两者能差 427 ms。要做的是让 `av_drift` 也相对"装置侧"报一份，
   或者至少把领先量扣掉再报一份 —— **两个数并排，才谈得上"音画偏差是多少"**。
2. **门限与区间不同量纲。** 45 ms 的绝对门限在短窗口上能把 `media_rate` 顶出 ±2%。
   要么让门限按窗口比例走，要么让区间按窗口长度放宽 —— 两者都得有依据，不能拍脑袋。
3. **4K60 那轮 `jumps_clamped = 3` 的线索。** 今天的轮次是 0，当时是 3。
   如果三次钳制里有一次停在"位置上"，就能解释领先量为何是**偏移**而不是**速率**。
4. **让 `surface_at_time` 也提供钟读数** —— 它一个人贡献 108 份"不可判"里的 7 份，
   而它是默认档（P14-S §九.2 起一直挂着）。
5. **切后台的"回来从哪继续"** —— 要 native 暴露 `position_us`（P14-R 起挂着）。
6. **`I1` 在样本极少时的分支** —— `superseded/p14q-locked` 仍是可复现样本。
7. **32 位 Android** —— CM311-1A 是现成验证机，但要 32 位 FFmpeg。
