## §1 页面结构（自上而下）

```
幕布幕布图（原色全画，标题烙印在图内）      ← 环境色遮罩只盖幕布下部（复用 239 §6 机制）
  meta（类型 · 日期 · 地区/集数）
  简介（2-3 行，左对齐）
  徽章行（有源的源才渲染）
  主操作行：观看胶囊钮 + (+收藏/♥待看) + ⋯
——幕布底缘自然过渡到浅色页面——
  演职员行（横滑：头像+名+角色）
  分类 chips
  预告片卡（/videos，有 trailer 才渲染）
  剧照行（/images backdrops，有图才渲染）
  媒体信息卡（本地库文件：清晰度/容量/码率/源名；无本地文件整卡隐藏）
  片源 logo（有源才渲染）
  相似作品列表（/similar）
```

**数据域**（全部 TMDB 公开 API，key/代理复用既有链路）：
- `/movie|tv/{id}`：meta/类型/简介/评分
- `/videos`：预告片（官方 trailer，zh 优先）
- `/credits`：演职员（cast 前 10）
- `/similar`：相似作品
- 本地媒体信息：WatchStore/媒体库按路径匹配（分辨率/大小/码率/来源名），匹配不到隐藏整卡。

## §3 实现要点
1. 幕布高：与首页 hero 同构（585dp）——E1 幕布原色，页面下部浅色由幕布底缘自然过渡
   （环境色遮罩只盖幕布下部，页面背景 = pageBackground）。
2. 主操作行：胶囊钮文字 = 有集数「观看第1集」/ 电影「观看」/ 加载中显示原因（G9）；
   副钮动作接入 WatchStore（收藏/待看状态持久化）。
3. 演职员/预告/剧照/相似：TMDB 无数据时**整节隐藏**（不渲染空壳）。
4. 媒体信息卡：清晰度大字取本地文件（HDR10/DV/SDR），容量/码率来自 MediaStore，
   源名+绿勾=来源库；无匹配文件隐藏整卡。
5. 返回钮、状态栏、导航玻璃复用首页既有组件。

## §5 真机实测修正（2026-11-08，P3 收口；**本节覆盖上文冲突处**）

v1 稿的 §1 节序与 E3/E6 锚点是按 detail_03/04 的**深色变体**抄的，且把 y 值错配到
不同元素上。真机首轮渲染 + 四帧逐行重测后，以下口径替换：

### 5.1 权威几何（dp，390×844 参照系；四帧一致）

| 元素 | 上沿 | 下沿 | 高 |
| --- | --- | --- | --- |
| 幕布艺术图 | 0 | **507** | 507 |
| meta 行 | 521.3 | 533.0 | 11.7 |
| 主操作行 | **552.3** | 597.3 | 45 |
| 简介 2 行 | 616.3 | 641.7 | 25.4 |
| 徽章行 | 658.7 | 668.7 | 10 |
| 下一节标题 | 720.7 | 737.0 | 16.3 |

**节序（帧为准）：幕布 → meta → 主操作行 → 简介 → 徽章 → 各节。**
v1 §1 写的「meta → 简介 → 徽章 → 主操作行」作废——按它实现会让徽章叠在简介上。

### 5.2 作废条目

| v1 条目 | 作废原因 | 替换口径 |
| --- | --- | --- |
| E1「无遮罩压暗」+ §1「环境色遮罩只盖幕布下部」 | 两条互斥；实测把幕布下半压成奶白（可见底缘 345.8 vs 507） | **不铺色遮罩**；仅在幕布最后 90dp 做「艺术图→页面底色」淡出 |
| E3 meta「类型 · 日期 · 地区/集数」 | 帧实测 meta 无类型；日期为中文格式 | `日期 · 地区 · 片长/集数`，例：`2026年8月19日 · 中国大陆/中国香港 · 2小时40分钟` |
| E6 y 区间 538–557 | 该值是简介行位置，非按钮 | 552.3–597.3，钮高 45 |
| E13「竖列表」被实现成两列网格 | 网格把 2:3 海报裁成横版 | 单列竖排：海报 92×138 + 右文 |
| §3.2 主钮文案「观看/观看第1集」 | 帧里无本地资源时钮面直接显示原因（G9） | 无匹配资源 → 钮面文案 = 原因，不做「假按钮 + toast」 |

### 5.3 主题口径

参照系含深/浅两个变体（movie_05 近黑底、movie_06/09 浅底）。本应用为浅色主题，
**对齐浅色变体**：艺术图淡出 → 页面底色 `pageBackground` → 正文 `textMain`。
文字**不压在艺术图上**（帧里 meta 起就在幕布之下），因此不需要按环境色算前景色——
这一条同时消除了「亮海报 → 白字不可读」的整类故障。

### 5.4 与参照的**故意**差异

| 项 | 参照 | 本实现 | 理由 |
| --- | --- | --- | --- |
| 地区写法 | `香港` | `中国香港` | 地区标注规范 |
| 幕布素材 | 专用 key art（0.769） | TMDB 海报 2:3（Crop 7%/边） | 无 key art 资产；海报自带标题烙印，可满足 E1 意图 |

### 6.4 色场结论（二轮实测修正 §5.3）

- 参照的页面底色 **= 艺术图下部色**，因此幕布**不铺任何遮罩**（旧版首页曲线起点 47% 会把标题区洗白，
  这是首轮「不像」的根因）。
- 页面底色仍按首页机制 `lerp(环境色, pageBackground, 滚动dp/390)`，但**去掉首页那 28% 提亮**——
  详情页要求「页面色 = 艺术图色」才能无缝；首页提亮是为了内容区可读，详情页滚动后自然转浅，无需提亮。
- 文字色按 `HomeAtmosphere.lightForeground` 阈值翻一次，不逐帧重算。

## §9 播放资源 / 媒体信息卡（第五轮，先设计后实现）

### 9.1 构思

参照的两种状态由「本地是否有匹配片源」决定：

| 状态 | 主操作行 | 徽章下 |
| --- | --- | --- |
| 有资源 | 白胶囊「▶ 播放」 | 播放资源：`[4K]` → 媒体信息卡（质量/容量·码率/源名+绿勾）→ 展开媒体信息 |
| 无资源 | 浅灰胶囊「未加载到相关资源」 | 空态块（TV 图标 + 暂无可用资源 + 添加到待看） |

**匹配口径**：TMDB 条目只有标题，本地只有文件名 → 必须做标题归一化匹配。
不做"猜测式"匹配：归一化后要求 TMDB 标题**完整包含**于文件名，否则视为无资源（宁可空态，不给错资源）。

### 9.2 家族树（单文件单职责，不堆砌）

```
library/
├── LocalVideoSource.kt   [新] 唯一职责：拿本地视频列表（MediaStore 查询，返回 List<MediaItem>）
└── TitleMatch.kt         [新] 唯一职责：标题归一化 + 匹配打分（纯函数，无 Android 依赖，可单测）
ui/detail/
├── MediaMatch.kt         [新] 唯一职责：把 List<MediaItem> + TMDB 标题 → MatchedMedia?
│                              （含 sizeBytes / bitrateBps / quality 推导）
├── DetailSections.kt     [改] 只加两个展示组件：PlaySourceHeader、MediaCard
└── MovieDetailActivity.kt[改] 只做接线：匹配结果 → 两种状态互斥渲染
tmdb/TmdbDetail.kt        [不动] 数据域仍是 TMDB，不掺本地文件概念
```

约束：
- `TitleMatch` 不 import Android，纯 Kotlin；`MediaMatch` 只做组装与推导；两者都不碰 Compose。
- 组件只接收已算好的数据（`MatchedMedia?`），不在 Composable 里读磁盘。
- 不新建包，全部落在既有 `library/` 与 `ui/detail/` 下。

### 9.3 推导规则

| 字段 | 规则 |
| --- | --- |
| 质量 | height ≥ 2000 → `4K`；≥ 1000 → `1080P`；≥ 700 → `720P`；否则 `SD` |
| 容量 | `File(path).length()`，格式 `16.4 GB` / `980 MB` |
| 码率 | `size*8/durationSec`，格式 `23.86Mbps` |
| 源名 | 本地文件 → `本地`（TMDB 条目无来源库概念；参照的 `iLoveHD` 属其自有库命名，不复刻） |
| 绿勾 | 表示"文件可用"，本地文件存在即可 |

### 9.4 验收

1. 推一个与 TMDB 标题同名的测试片 → 主钮变「▶ 播放」+ 播放资源 `[4K]` + 媒体卡；
2. 无匹配 → 空态块（现状）；
3. 匹配不得跨标题误命中（用 `TitleMatch` 单测覆盖）；
4. 证据入 `docs/evidence/p240/`。

## §12 滚动结构定稿（第七轮，10 帧逐帧比对）

用户提供 10 帧连续滚动截图（`IMG_0149`–`IMG_0158`），逐帧比对后定稿：

| 观察 | 结论 |
| --- | --- |
| 片名/meta/按钮/简介/空态块/演职员**整体同步上移** | 它们同属一个滚动内容层 |
| 顶部艺术图**原地不动**（第 1 帧到第 10 帧位置不变） | 幕布是**底层固定层**，不进滚动 |
| 艺术图随滚动**逐渐被冲淡**（深绿 → 浅灰绿） | 上层叠一层**随滚动增强的白色提亮**，不是不透明色块 |
| 全程**没有硬边**，也**没有明显模糊块** | 内容层**不带底色**；背景由「固定艺术图 + 提亮层」统一提供 |

**结构**：

```
Box
├── 固定艺术图层（0–589.5dp，原色，无渐变、无裁剪）
├── 提亮层（全屏，白 α = scroll/300 × 0.86）
└── 滚动内容层（透明背景）：占位 404.5 → 片名带 88 → meta → 按钮 → 各节
```

**作废的三版**：
1. 幕布当普通列表项（整页一起滚）—— 艺术图会跟着走，错。
2. 内容层铺不透明色场 —— 出现"脏灰布"硬边，割裂。
3. 模糊海报 + 强提亮材质 —— 模糊块明显，参照里没有这么重。

**提亮参数**：`DETAIL_WASH_MAX_ALPHA = .86`、`DETAIL_WASH_FULL_DP = 300`、
文字翻色阈值 `DETAIL_CHROME_FLIP_DP = 70`（滚过 70dp 转深字）。

### §12.1 提亮曲线实测拟合（10 帧亮度采样）

按用户 10 帧的时间顺序采样顶部 60–100dp 区域平均亮度：

| 帧（时间序） | 滚动量≈ | 顶部亮度 | 推算提亮 α |
| --- | --- | --- | --- |
| 0149 | 0 | 97 | 0 |
| 0150–0154 | 140–285 | 91–94 | 0 |
| 0155 | 365 | 95 | ≈0.02 |
| 0156 | 385 | 106 | ≈0.09 |
| 0157 | 400 | 124 | ≈0.20 |

结论：**前 320dp 完全不提亮**，之后才开始冲淡。拟合参数：

```
α = clamp((scroll − 320) / 350, 0, 1) × 0.85
文字翻色阈值 = 430dp
```

根底色与艺术图提亮同源（`lerp(环境色, 白, α)`），避免艺术图下缘与页面出现接缝。
