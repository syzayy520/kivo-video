# 110 · P13-AC 验收：迟滞带赢了，限速被自己否掉

- 日期：2026-10-30
- 前置：`109-p13ac-design.md`
- 结论：**三版对照做完了**。最终版（迟滞带 + 一次还完）在每个指标上都优于前两版：
  事件帧迟到 **23.6–24.0 ms**（AB 29–31、限速 61.7）、`drift_rebases = 1`、
  残差 **40.00 ms**、`playback_rate` 与 `span/(span−0.040)` 差 ≤ 1.4×10⁻⁵、零丢帧。

## 三、为什么限速必然输

台阶是**输入**：注入那一帧的 `elapsed` 已经多了 80 ms，`due` 也已经被推早 80 ms。
限速能决定的只是"这一帧还回去多少"，所以：

```
事件帧迟到 = 台阶 − 当帧修正量 − 同帧 present_step
```

限速把"当帧修正量"压到 2 ms，迟到就顶到 62 ms；一次还完把 40 ms 还掉，
迟到只剩 24 ms。**要压尖峰，就得当帧多还；要少还，尖峰就更大。** 没有第三条路。

限速唯一还能做的事，是"还完之后剩下的偏差慢慢摊"——可迟滞带方案根本没有"剩下的"。

## 四、两条过程教训

1. **断言写松，单测就发现不了"设计没实现"。** 第一版迟滞写成"一个阈值 + 一个目标"，
   真机残差全停在 44（因为一帧只修 2 ms），而 S8 当时断言的是 `lead <= limit` —— 44 满足。
   现在断言的是 `40 ± 1 ms` 且 `rebases == 1`。
2. **先算再跑救了一次。** 设计里先把"事件帧 `due_step` = −(注入 − 40)"算出来，
   真机拿到 −40.0 / −160.05 一眼就对上了；否则看到 −160 ms 会以为是 bug。

## 五、诚实清单

1. **只有一台设备、一种片源**（8 s 4K60），全部是注入实验。
   **没有在 8 路负载的真实事件上重跑** —— 真实事件是渐变漂移，触发时超出量只有
   几毫秒，预期行为与 AB 相同（都是"一次还完几毫秒"），但这是推理不是观测。
2. **`band = 5 ms` 是拍的**：一个 60 fps 帧的三分之一。没有主观画质数据支撑；
   它只影响"多久之后重新触发"，不影响单次修正的形状。
3. **200 ms 的注入是合成输入**：真实 HAL 抖动是否会瞬时跳百毫秒级，没有样本。
   若真出现，本版会一次还 160 ms（`due` 一帧挪 160 ms），是否可见未测。
4. `A5` 判据（修正总量 = 注入量 − 40 ms，容差一帧）把输入与输出绑在一起，
   是本卡唯一一条端到端恒等式；它顺带证明"修的是该修的那一段"。
