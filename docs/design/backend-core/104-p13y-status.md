# 104 · P13-Y 验收：复位幅度改成「只减超出部分」

- 日期：2026-10-30
- 前置：`103-p13x-status.md`（r1 触发后从 +45 ms 拨到 −33 ms）
- 结论：改动 + 单测完成；**真机四轮没撞上事件**，所以"过冲消失"仍未被真机证实。

## 一、改法

```
旧：position -= cum;          cum = 0      ← 把"播放器已自己追回的那截"也减掉
新：position -= (cum − limit); cum = limit ← 只减超出部分
```

台阶入口（单帧 > 30 ms）仍减整段 —— 台阶是伪值，没有"超出部分"可言。

## 二、单测

S1/S3/S4/S5 + C5 二十六条全过（S1 的断言是"末帧超前 ≤ 门限 + 一帧"，新实现天然满足）。

## 三、真机四轮（8 路，`ps` 前后都是 8）

| 轮 | max (ms) | 丢帧 | `drift_rebases` | `clock_ahead` | `playback_rate` |
|---|---|---|---|---|---|
| r1 | 96.34 | 0 | 0 | +0.01 ms | 1.000014 |
| r2 | 93.67 | 1 | 0 | +0.04 ms | 0.999996 |
| r3 | 45.24 | 0 | 0 | +4.97 ms | 1.000633 |
| r4 | 26.43 | 0 | 0 | +0.02 ms | 1.000013 |

**四轮都没出现位移**（最大 +4.97 ms，远不到 45 ms 门限），所以门没触发是正确的，
但也因此**没法验证新幅度**。历史复现率约 1/3，四轮全空并不意外。

## 四、诚实清单

1. **过冲修复未在真机验证** —— 这是本卡最大欠账，需要"触发且不过冲"的那一轮。
2. `cum = limit` 而不是 0：意味着门一旦响过，之后每帧只差一点就会持续小步复位。
   长片源上的行为没测（P13-S §五.4 提过同样的风险）。
3. r2 丢了 1 帧，账不平（P13-Q 已知）。
4. 四轮里 `max` 仍在 26–96 ms —— **尖峰与时钟位移是两件事**，本卡只碰后者。
