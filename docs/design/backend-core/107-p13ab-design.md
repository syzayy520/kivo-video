# 107 · P13-AB 设计：把「时钟跑偏」从概率事件变成按需事件

- 日期：2026-10-30
- 前置：`106-p13aa-status.md`（账做对了，但五轮一次位移都没撞上）
- 目标：让漂移门第一次能在**确定性**条件下被检验 —— 触发、幅度、无过冲，三件事各自可复算。

---

## 一、为什么不再靠负载撞

| 卡 | 轮数 | 撞到位移 | 命中率 |
|---|---|---|---|
| P13-R | 4 | 2 | 1/2 |
| P13-U | 3 | 1 | 1/3 |
| P13-V | 3 | 1 | 1/3 |
| P13-Z | 8 | 4 | 1/2 |
| P13-AA | 5 | 0 | 0/5 |

累计 23 轮、8 次命中。这个样本量能说明"事件存在"，但**不能**检验门：

- 撞不上时，一份`drift_rebases = 0` 的证据既可能是"门没用"，也可能是"这次没有位移"；
- 撞上时，位移幅度和形态都由设备决定，无法做"输入相同、只改一个变量"的对照。

负载是真实性的来源，也是可重复性的敌人。两者只能分开拿：**真实性用负载轮证明过（已有 23 轮），
可重复性得靠注入**。

## 二、注入点选在 `AudioClockSource`

```
        ┌─────────────────────── 探针路径（仅 kivo.clock_offset_ms != 0）──┐
时钟链： AudioPlayback::clock() → [ClockOffsetSource] → ClockPositionTracker → FramePacer
        └──────────────────────────────────────────────────────────────────┘
```

选这一层而不是往 `ClockPositionTracker` 里塞 debug 开关，理由有三条：

1. **这一层本来就是为注入设计的**。`AudioClockSource` 是纯虚接口（`now()` / `rebase()`），
   存在的目的就是让 C5 的节拍器"不认识 AAudio"。多一个实现类是它的正常用法。
2. **节拍器与 tracker 完全不知道有这回事**。它们看到的仍是一个标准时钟源，
   所以门的反应是真的，不是为测试写死的一条分支。
3. **0 = 不存在**。不带参数时 `offset_clock` 保持空指针，生产路径上一个分支都不多。

## 三、语义：持续偏移，不是脉冲

`ClockOffsetSource(inner, offset_ns, arm_after_ns)`：首次读到位置时定原点，
此后走够 `arm_after_ns` 就把**每一帧**的位置都加上 `offset_ns`。

为什么不做成"只加一帧"：真实时钟跑偏（`elapsed` 估计偏大）不会下一帧自己走回来。
做成脉冲的话，位置回落会被 tracker 的倒退钳制顶住，观测到的形状就变成"一串钳制"，
而不是"一次台阶之后怎么收敛" —— 那就不是我们要测的东西了。

`rebase()` 会作废原点（seek 之后位置可能一下跳几十秒，留着原点会让台阶被"顺手"注入），
但**已经注入过就不再注入**：一次台阶一次观测，重复注入会让账再也算不清。

## 四、证据必须自证

被注入过的证据和真实现场在字段上完全一样。所以 `sync/18` 在顶层固定出版三格：

```json
"clock_injection": { "offset_ns": 80000000, "arm_after_ns": 2000000000,
                     "armed_at_position_ns": 2195266667 }
```

**三格总是写**（不注入时 `offset_ns = 0`、`armed_at_position_ns = -1`），
而不是"没注入就省略" —— 省略会让"这一轮没注入"和"这个字段还没实现"长得一样，
P13-R 的 `normal_branch_frames` 就吃过这个亏（满 480 却全是 0）。

三条判据（`verify_p13p_episode.py` I1–I3）：

| 判据 | 内容 | 打红意味着 |
|---|---|---|
| I1 | 三格必须存在 | 证据无法区分"注入"与"没注入" |
| I2 | `offset == 0` ⇒ `armed_at == -1` | 幽灵注入点：干净的一轮被记成注入过 |
| I3 | `offset != 0` ⇒ `armed_at ≥ arm_after > 0` | 片源没走到那个时刻，这一轮**什么都没测到** |

I3 是这一卡最容易被忽略的一条：给了参数却没触发，`drift_rebases = 0` 看起来和
"门没用"一模一样。

## 五、预期值（写死，先算再跑）

注入 `x` 的台阶，门把领先量压到 `limit = 45 ms`，于是：

- `clock_ahead ≈ limit`（与 `x` 无关 —— 这正是"有界"与"没门"的区别）；
- 播放速率 `rate = span / (span − limit)`：本片源 span ≈ 7.9835 s ⇒ **1.00564**；
  没有门时应为 `span/(span − x)`：80 ms ⇒ 1.0101、200 ms ⇒ 1.0256。
- 注入那一帧的 `due_step = −(x − 超出门限的部分调整后的净台阶)`：
  净台阶恰是 `limit`，故 `due_step ≈ −45 ms`、同帧 `lateness` 抬升 `45 − |present_step|`。

第三条是这一卡唯一"不舒服"的预期：**门不是在事件发生前拦住它，而是在同一帧把台阶削到 45 ms**，
所以事件本身仍会以一次 ~30 ms 的迟到现形。这是"事后纠正"的固有代价，不是缺陷 ——
但必须写进预期，否则跑完看到 29 ms 会以为哪里错了。

## 六、不做的事

- 不做"门关"对照组：`drift_limit_ns` 是可配置的，但把它设成无穷大需要新增探针参数，
  且"没门时 rate = span/(span−x)"这条关系已被 P13-R/U/V/Z 的 8 次真实事件验证过
  （`clock_ahead +73.30 → rate 1.0093`、`+165.58 → 1.0212`）。控制变量留给有需要时再加。
- 不改门的判据。本卡只回答"能不能按需触发、触发后是不是有界不过冲"。
