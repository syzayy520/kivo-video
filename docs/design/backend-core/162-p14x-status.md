# 162 · P14-X 验收：假设被自己的数据推翻 —— 那一笔不在启动期，在钟的一次不连续上

- 日期：2026-10-31
- 前置：`161-p14x-design.md`
- 结论：**启动期假说被推翻**。四轮 4K30 里有一轮出现 **146.75 ms 的单笔修正，
  落在第 24.43 s** —— 不是 1 s。而它与 P14-W 那笔 104.71 ms 的共同点不是"启动"，
  而是 **`extrapolated_frames = 1` 且 `monotonic_rejects = 1`**：
  六轮正常轮这两格全是 0，两次大修正这两格全是 1。**六比六，分得干干净净。**

---

## 一、四轮（4K30 60 s / 5 000 ppm / 门开 / K40）

| 轮 | `rebases` | 首笔时刻 | 最大单笔 | 最大那笔在第几秒 | 钟事件（外推/拒绝/跳变） | 丢帧 |
|---|---|---|---|---|---|---|
| r1 | 49 | 11.02 s | **146.75 ms** | **24.43 s** | **1 / 1 / 0** | 0 |
| r2 | 49 | 10.99 s | 5.19 ms | 30.32 s | 0 / 0 / 0 | 0 |
| r3 | 48 | 11.02 s | 5.18 ms | 19.20 s | 0 / 0 / 0 | 0 |
| r4 | 48 | 11.02 s | 5.18 ms | 38.60 s | 0 / 0 / 0 | 0 |

- **首笔 11.02 s** 四轮一致：`reach = 45 ms / 5 000 ppm = 9 s`，加上 `arm_after = 2 s`，
  与设计预期吻合 —— 这一格反过来证明轨迹记录本身是对的。
- 正常轮最大单笔 5.18 ms ≈ 迟滞带（5 ms）+ 一帧内的一点点增长，符合 P13-AC 的设计。

## 二、和 P14-W 合起来看：六比六

| 轮 | 最大单笔 | `extrapolated_frames` | `monotonic_rejects` |
|---|---|---|---|
| P14-W 4K30 r1 | **104.71 ms** | **1** | **1** |
| P14-X 4K30 r1 | **146.75 ms** | **1** | **1** |
| P14-W 4K30 r2 / r3、P14-X r2 / r3 / r4、P14-W 1080p60 | 5.10–5.77 ms | 0 | 0 |

**两轮大修正 = 两次钟事件；六轮正常 = 零次钟事件。** 这条分离比"启动期"那套说法
强得多：它不需要额外的假设，而且每一轮都能当场核对。

所以正确的说法是：

> 门把**钟的一次不连续**当成漂移还掉了。`monotonic_rejects` 说明时钟源拒了一个
> 回退的候选值，`extrapolated_frames` 说明有一帧走的是"按墙钟补"的外推分支；
> 这两件事之后，`cum` 里多出一段本不属于"漂移"的量，门一次把它抹平。

## 三、我错在哪

第一版的 X4 判据写的是"单笔 > 迟滞带 + 一帧 ⇒ 必须落在 ≤3 s"。真机一跑就红 ——
**判据红了之后，正确的动作不是把阈值放宽，而是承认假设错了**。改判据之前先看数据：
`max.at_ns = 24.43 s`，而且那一轮的钟事件是 1/1 而不是 0/0。

于是 X4 改成：

> 单笔 > 迟滞带 + 一帧 ⇒ 那一轮必须有可查的钟事件（外推 + 拒绝 + 跳变 > 0）。

这条能被变异打死（M5：把三个计数清零、留着 146.75 ms 的修正 → 红），
也能被正常轮放过（M6：5.19 ms + 全 0 → 绿）。

## 四、还有一处没拆开

`monotonic_rejects = 1` + `extrapolated_frames = 1` 只能解释约**一帧多**（≈33 ms，
那一轮的 `present_jitter.max = 34.47 ms` 正好对上），而修正是 **146.75 ms**。
剩下的 113 ms 从哪来，**没有证据**：轨迹只记了修正，没记"那一帧的原始位置与墙钟"。

这是下一张卡的靶心。

## 五、诚实清单

1. **四轮只有一轮复现**（1/4），加上 P14-W 是 2/7 —— 样本少，6/6 的分离虽然干净，
   但仍是相关性，不是机制。
2. **146.75 ms 里只有约 33 ms 有解释**（一帧外推），其余未见证据。
3. 一台设备、一种片源（4K30 60 s）。
4. `X4` 只要求"有钟事件"，不区分事件大小 —— 它挡住的是"完全无中生有"，
   挡不住"有一次小事件却修了 146 ms"。要挡后者，得先有 §四那个证据。
5. `recent` 只留 8 笔，`r1` 的 146.75 ms 那一笔已不在 `recent` 里（被后续 8 笔挤出），
   只看 `max` 一格 —— 这是定长环的取舍，已在设计里写明。
