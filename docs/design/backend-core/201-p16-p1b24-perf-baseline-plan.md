# P16-P1B24 · 性能基线门禁（把画像变成判据）

- 日期：2026-11-06
- 定位：`P16-CLOSEOUT` §六 算出了性能画像，但那是**离线重算**，CI 里没有一条守着退化。
  本卡把它变成可复算的门禁。门闸：构思 → 规划设计 → 家族树 → 实现 → 验收。
- 上位：`P16-CLOSEOUT.md` §六、`03-goals.md` G6/G8、`verify_p12_all.py`（结构门禁，不含性能）。
- 工作目录 `C:\kivo video`；`F:\kivo` **只读**；无新目录。

---

## 一、构思

现在的门禁守"结构"（schema、字段、豁免），不守"数字"。如果有人把 `publish()` 开销翻倍，
丢帧率从 0.09% 涨到 0.4%，**没有任何门禁会报警** —— 因为 `verify_p12_all.py` 只检查
"证据格式对不对"，不检查"数字有没有变差"。

本卡补这一层：从仓库里的证据算性能基线，超阈值即红，且**超预算必须显式登记**
（与项目"豁免明示"的规矩一致）。

---

## 二、规划设计

1. **只读证据**：不跑真机、不改证据、不 import 项目代码。
2. **判据只覆盖当前 schema**：`/19` 及以后。`/13` 那批历史证据的 3 份超预算
   单列豁免（`p13r-4k60-r3` / `p13s-4k60-r1` / `p13k-130s-r1`），
   否则"历史轮次"会让门禁永远红。
3. **超预算必须登记**：`/19+` 里任何一份冷启动 > 300 ms 或 seek > 150 ms，
   都必须进 `KNOWN_OVER_BUDGET` 并带理由；没登记就红。
4. **丢帧率按全局算**：`Σdropped / Σrendered < 0.5%`（G6）。
5. **变异自检**：注入一份超预算证据、删一条豁免，必须被抓到。

### 实现期更正

Q4 初版只把"当前口径"的超预算收进 `seen`，导致 `/13` 的 3 条豁免被判"过期"。
改成"**所有超预算不分 schema 都必须登记**"后 PASS —— 是判据写错了，不是数据问题。
这也更符合项目"豁免明示"的规矩：历史轮次也要写清理由。

### 结论

- 性能基线**现在有 CI 门禁**（`hard-gates` 第 8 步），超预算未登记即红。
- 它守的是"**仓库里的证据数字**"，不是"代码改动"—— 新证据仍要真机跑；
  但至少"证据里出现超预算却没解释"这件事，以后会被拦住。
- 与 `P16-CLOSEOUT` §六 的数字一致（`/19` 冷启动 p99 128.8 ms、丢帧率 0.0876%）。
