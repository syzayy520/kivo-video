# 103 · P13-X 验收：门第一次在真机上响了 —— 但一次就过冲

- 日期：2026-10-30
- 前置：`101-p13w-status.md`（单测齐、真机待验）
- 结论：**门在真机上首次触发（r1 `drift_rebases = 1`）**，但复位幅度过大：
  复位后 `clock_ahead` 从正翻成 **−33.21 ms**、`playback_rate` 掉到 **0.995868**（慢 0.4%）；
  同批 r2 又出现 **+115.32 ms / rate 1.014671** 而门没响。

---

## 一、四轮（8 路忙循环，`ps` 前后都是 8）

| 轮 | max (ms) | 丢帧 | `drift_rebases` | `clock_ahead` | `ahead_wall` | `playback_rate` |
|---|---|---|---|---|---|---|
| **r1** | 95.14 | 5 | **1** | **−33.21 ms** | **−48.73 ms** | **0.995868** |
| **r2** | 99.13 | 0 | 0 | **+115.32 ms** | +99.00 ms | **1.014671** |
| r3 | 56.68 | 0 | 0 | +0.01 ms | −16.52 ms | 0.999990 |
| r4 | 91.49 | 1 | 0 | +23.66 ms | +8.22 ms | 1.002982 |

## 二、两条结论

1. **门是活的**：r1 真的触发了一次（前四张卡一直卡在"没响"，这次响了）。
2. **但一次就过冲**：复位把位置往回拨了整段累积量，之后 `clock_ahead` 变成 −33 ms、
   播放变慢 0.4%。**修正本身引入了新的同步误差**，幅度与被修正的量同量级。
   正确做法应是"只减超出部分"（`cum − limit`）或限幅，而不是减整段。

3. **r2 仍然绕过**：+115 ms 却没触发 —— 与 P13-V 见过的"大台阶被当台阶放过"同形，
   说明 30 ms 台阶门在这条路径上没有覆盖到（可能是丢帧帧距把 drift 摊到了阈值以下）。

## 三、诚实清单

1. 四轮里只有一轮触发，"能触发"是 1/4 的样本，**不能证明它在所有事件上都触发**。
2. r1 有 5 丢帧、r4 有 1 丢帧，账不平（P13-Q 已知缺陷），但跨度不受影响。
3. **过冲是确定性缺陷**，不需要更多样本就能判定：减整段必然把"已经被播放器自己追回的部分"也减掉。
4. 没做"只减超出部分"的对照 —— 那是下一张卡。
