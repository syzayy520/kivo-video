## 二、矛盾与假设

`clock_ahead = elapsed_span − arrive_mono_span` 就是"位置比墙多走了多少"，
按定义应当等于 `Σ drift`。r4 它到了 **+73.30 ms**，超过 45 ms 门限，
可 `drift_rebases = 0` —— **两个数不是同一笔账**。

最可能的来源：`position_ns_` 不只由正常分支推进。`stale` 外推分支、
`jump_rebase` 分支、以及倒退钳制都会**直接加墙钟增量**，而 `cum_drift_ns_`
只在正常分支里累加。于是这些路径凭空把位置往前推，却一个字都不记进漂移账。

这条假设可判：八轮里 `clock_health.extrapolated_frames` / `jump_rebases` 若为 0，
假设就不成立；若非 0，就说明位移是从那些分支漏进来的。

## 三、诚实清单

1. **仍然没修**，本卡只做到"确认账不平"。
2. r1 / r7 有丢帧，账本另外还有 P13-Q 的已知缺陷。
3. `clock_ahead` 与 `Σdrift` 的关系从没被单测钉过 —— S1 只断言"门会响"，
   没有断言"`Σdrift` 等于位置偏移"。这是本卡暴露的测试盲点。
