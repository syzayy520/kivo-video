# 170 · P14-AE 设计：≥ 1 s 的台阶 —— 门把它当 seek，然后报告说"同步"

- 状态：**已执行**，见 `171-p14ae-status.md`（测量卡：源码 0 行、schema 0 变更）
- 前置：`169-p14ad-status.md`（≤ 800 ms 的曲线）、`clock_position_tracker.cxx` 的跳变分支

## 一、为什么下一张卡是它

P14-AD 的曲线只画到 800 ms，因为 `jump_limit_ns = 1 s`：**再往上就是另一条分支**。

```cpp
const std::int64_t drift_ns = raw_delta_ns - wall_delta_ns;
if (drift_ns > policy_.jump_limit_ns || drift_ns < -policy_.jump_limit_ns) {
    position_ns_ += wall_delta_ns;   // ← 台阶被丢掉
    reading.jump_rebased = true;
    ++jump_rebases_;
}
```

这条分支的假设写在注释里：*"换采样率 / seek / 设备重建"*。它把 ≥ 1 s 的位置跳变当作
**合法的**不连续，于是位置按墙推进、时间轴保持连续。

**问题在于：它无法区分"合法不连续"和"钟真的错了 1.5 秒"。** 两者在数据上长得一模一样，
而这条分支替你把它们判成了同一种：位置按墙推进，台阶丢掉，`raw_lead` 回到 0。

于是 `lead = 0` **有了两种来历**：

| 来历 | 画面相对真实音频 | 报告 |
|---|---|---|
| 真的对齐（钟没动） | 对齐 | `av_synced` 说得对 |
| 位置被重写（钟动了 1.5 s，被丢掉） | 也"对齐"—— 因为跟着墙走的是真实时间 | `av_synced` 也对，**但它不知道自己是哪一种** |

**先纠正我自己写设计时的第一版**：我一开始写的是"报告在说谎"。跑之前想清楚了 ——
注入是**假的**：真实音频没动，视频跟着墙走确实和真实音频同步，所以 `av_synced` 在这个场景里是对的。
真正的问题不是"说谎"，是**二义性**：`lead = 0` 可能是"对上了"，也可能是"被丢掉了"，
而报告里没有任何一格区分它们（只有 `jump_rebases` 一个计数和账上那笔 `step = 0` 的跳变）。

**危险的是另一种现场**：音频时钟真的跳了 1.5 s（设备重建 / 换采样率），这时"跟着墙走"
不是跟着音频走，画面与音频差 1.5 s，而报告仍然说 `av_synced`。数据上这两种现场**分不开** ——
这一卡只能量出"代码选了哪种解释、报告说了什么"，不能量出"哪一种现场更多"。

这与 P14-AC 是同一族问题：**数字没错，是它在替一件它不知道的事下结论。**

## 三、预测（先写下来）

| 编号 | 预测 | 若不成例会怎样 |
|---|---|---|
| **H1** | 1500 / 3000：`jump_rebases = 1`、末态 `\|lead\| ≈ 0`、`frames_dropped = 0`、账上 `jumped = 1` 且 `offset = 0` | 若 lead ≈ 幅度 ⇒ 跳变分支没触发，我对阈值的读法是错的 |
| **H2** | 两臂的数字**逐位接近**（开关无效） | 若两臂不同 ⇒ 门在跳变之后还动了手，得重新读顺序 |
| **H3** | **`sync_verdict = av_synced`**，且账上只有一笔 `step = 0` 的 `jumped` —— 即"0 领先"是"被丢掉"的结果 | 若判成 `clock_off` ⇒ 跳变分支没触发，或报告另有一处在算真值 |
| **H4** | 999 → `position_step` + 门还 959 ms（lead 40）；1000 → 看噪声（可能两侧都出现） | 若 999 也走跳变 ⇒ 阈值不是 1 s；若 1000 稳定走台阶 ⇒ 严格大于的判断被噪声吃掉了 |

**H3 是这一卡真正的问题。** 它成立的话，结论不是"改阈值"，而是"`jump_rebased` 必须出版
**被丢掉的幅度**（现在只有 `raw_delta_ns` 埋在账里），让读者能分清 `lead = 0` 的两种来历"。

## 四、判据：加两条（都只对跳变轮生效）

**AE1（跳变要进账）**：`clock_health.jump_rebases > 0` ⇒ `drift_discontinuity.jumped` 必须 > 0。
理由：跳变是"门没管、但位置被改过"的一类事件，账上不记就等于没发生（P14-Y 的裁决表已定：
`jump_rebased` 进账但**不进 offset**）。

**AE2（跳变不许进 offset）**：`jump_rebases > 0` 且这一轮只有跳变（`stepped == clamped == rejected == 0`）
⇒ `offset_ns` 必须是 0。理由：跳变分支已经按墙推进并重锚，若再记一次 offset，
下一张卡算"台阶要不要还"时会重复计数 —— 这是 P14-Y §三 已写的裁决，现在给它一个判据。

两条都可以被变异打死，而且都不依赖幅度。
