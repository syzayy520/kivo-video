# 113 · P13-AE 设计：门在「接近正常」的速率误差下会不会误伤

- 日期：2026-10-31
- 前置：`112-p13ad-status.md`（门把无界累积压成固定 40 ms，但只测了 1.5% 与 5% 两个点）
- 目标：把 100 / 500 / 2000 / 5000 ppm 这四档填掉，并给出"误伤"的**可判据定义**

---

## 一、先算一次，再决定测什么

门的两个常数是 `limit = 45 ms`、`band = 5 ms`（`PacePolicy`，证据里照抄）。
它只在累积超前 `> limit` 时动作，动作完残差落在 `limit − band = 40 ms`。

于是**在 8 秒片源上**，触发所需的最低速率是：

```
ppm_min = limit / 时长 = 45 ms / 8 s = 5625 ppm = 0.5625%
```

**这句话是本卡的前提：P13-A/B/C/D 那些 8 秒片源，在 100–2000 ppm 下
"没有触发"不是结论，是算术。** 拿 8 秒片源去回答"晶振级误差会不会误伤"，
无论跑多少轮都只能得到 0 —— 那个 0 是片长造的，不是门造的。

P13-AD 之所以能看到 12 / 57 次，正是因为它的两个点（15000 / 50000 ppm）
都远在 5625 ppm 之上。**它证明的是"门在高误差下工作"，没有证明"门在低误差下安静"。**

所以本卡换片源：`p13h_360p30_130s_av.mp4`（130 s，360p30，AV）。
130 s 下门的下限降到 **346 ppm** —— 100 ppm 仍在门槛之下（这是有意的：
它必须触发 **0 次**，作为"门不会自己响"的阴性对照）。

---

## 二、预测：次数是可以先算出来的

一轮里累积的领先量是 `ppm × T_eff`。第一次触发要攒满 `limit`，
之后每次只需再攒 `band`（迟滞带）。于是：

```
expected = max(0, floor((ppm × T_eff − limit) / band) + 1)
T_eff    = 时长 − 1.0 s（注入点）− 1.0 s（启动盲期 kStepBlindPeriodNs）
         = 130 − 2 = 128 s
```

| ppm | 累积（128 s） | 预测次数 | 说明 |
| --- | --- | --- | --- |
| 0 | 0 ms | **0** | 阴性对照：门不该响 |
| 100 | 12.8 ms | **0** | 低于 limit，**算术上不可能触发** |
| 500 | 64.0 ms | **4** | 攒到 45 触发，余 19 ms → 再 3 次 |
| 2000 | 256.0 ms | **43** | 每 5 ms 一次，节奏 2.5 s |
| 5000 | 640.0 ms | **120** | 节奏 1 s |
| 5000（门关） | 640 ms | **0** | 对照：门没接上也会是 0，所以必须出版开关 |

**预测值写进设计稿、不写进校验器的常量里**：
校验器从证据自己的 `drift_gate.limit_ns` / `band_ns` / `source.duration_us` /
`clock_injection.rate_ppm` 复算，改策略只要升 schema，不会出现"新实现被旧预测卡住"。
（P13-AD 已经把 `limit` / `band` 出版，本卡只是第一次**真的用它们算东西**。）

## 三、"误伤"到底指什么

直觉上"误伤"是"不该触发却触发了"。但门只在累积越过 45 ms 时动作，
而 45 ms 是 ITU-R BT.1359 的**可检测阈值** —— 越过它还不动作，那才叫错。

所以本卡把"误伤"拆成三条**可打红**的判据：

| 编号 | 判据 | 为什么它是误伤 |
| --- | --- | --- |
| **F1** | 100 ppm 轮 `drift_rebases > 0` | 累积只有 12.8 ms，越过 45 ms 在算术上不可能。出现即实现有 bug（或注入没按预期生效） |
| **F2** | 观测次数 > 预测 + 2 | 门在没攒够 `band` 时也修 —— 迟滞带失效，会退化成 P13-AB 那种"每帧微调" |
| **F3** | 单次修正 > `band` + 1 ms，或该轮丢帧 > 0，或 `lateness.p99 > 1 帧` | 触发本身造成了看得见的后果。**"触发次数"不是罪，"触发把画面搞坏"才是** |

F3 是这张卡真正想守的东西：次数多不是问题（2000 ppm 下 43 次是**正确**的），
问题是每次修 5 ms 会不会在 30fps（33.3 ms 一帧）上留下可见台阶。
按 P13-AC 的实测，5 ms 远小于一帧，预期看不见 —— 但那是**预期**，本卡要出数。

## 四、四档之间的关系（本卡要回答的第二个问题）

| 问题 | 谁能回答 |
| --- | --- |
| 次数随 ppm 线性吗？ | 500 / 2000 / 5000 三点连起来看；预测表就是那条线 |
| 残差与 ppm 无关吗？ | AD 在 1.5% / 5% 上已经答过（40.00 / 42.79）；本卡看 500–5000 是否也在 40–45 |
| 真实的 `playback_rate` 会变成多少？ | `1 + 残差/时长`。130 s 上 40 ms → 1.0003，**比 8 s 上的 1.005 更接近 1** —— 因为残差是固定量、时长变长了。这是"门压相位不压速率"的第二个推论 |

最后一条是新的：P13-AD 那 1.005 容易被误读成"门把播放搞快了 0.5%"。
换成 130 s 再看，同一套门给出 1.0003 —— **同一个残差、不同的时长，速率读数就不同**。
这说明那个 0.5% 是"40 ms 除以 8 s"，不是"门改了速率"。

## 六、诚实清单（开工前先写）

1. **360p30 不等于 4K60。** 门读的是时钟，与分辨率无关 —— 但这句话本身也需要证据。
   若时间允许，用 4K60 片源在同一 ppm 上跑一轮对照，否则状态卡必须写明"跨分辨率未验"。
2. **130 s 不等于 2 小时。** 2000 ppm 在 2 h 上会累积 14.4 s，门的触发次数会到 2880 次；
   长期累积效应（每次 5 ms 的修正会不会在 2 h 里被听觉察觉成"周期性踏步"）本卡测不到。
3. **注入是合成速率，不是真晶振。** `ClockOffsetSource` 按 `1 + ppm/1e6` 线性放大，
   真实晶振偏差是温度相关的慢变 —— 形状比这更"软"。本卡测的是量级与节奏，不是形状。
4. **`T_eff` 是估的。** 1 s 注入点 + 1 s 盲期，两者在时间上重叠还是先后，取决于首帧时刻。
   所以预测允许 ±2 次的容差，而不是逐位相等 —— 这一条写在判据里，不藏在脚注里。
5. **F3 的"1 帧"按 30fps = 33.3 ms 算。** 60fps 片源上这个判据会严一倍，本卡没测。
