# 109 · P13-AC 设计：让门限不再同时当「触发阈值」和「收敛目标」

- 日期：2026-10-30
- 前置：`108-p13ab-status.md`（确定性触发成立；残差停在 45.00，稳态反复微调）
- 结论先行：**限速（本卡最初的方案）被真机数据否掉，只保留迟滞带**。
  三个版本的数字见 `110-p13ac-status.md` §二。

---

## 一、要修的是什么

P13-AB 用注入把门逼出来之后，暴露出一个只与"修"有关的毛病：

| 现象 | 数据（80 ms 注入） |
|---|---|
| `drift_rebases` | 5 / 6 / 10 次 |
| 总修正量 | **35.2 ms**（= 80 − 44.8） |
| 残差 | 44.80 / 44.74 / 44.95 ms |

第一个（或前两个）复位吃掉了 35 ms 里的绝大部分，其余几次各只修几十微秒。
原因是**门限同时当了两个角色**：`cum > 45` 触发，修到 45 停止。于是稳态就停在
45.00 附近，下一帧钟再往前挤 50 µs 就又越线一次。

## 二、方案 A（先试后否）：单帧限速

最初的设想：修一次不该比它修的东西更响。P13-AB 在一帧里把时间轴拽 45 ms，
事件本身就成了 29–31 ms 的迟到尖峰；那么把它摊到 20 帧、每帧 2 ms，
尖峰应当消失。

真机四轮把它否了：

| | 一帧削平（AB） | 限速 2 ms/帧 |
|---|---|---|
| 事件帧 `due_step` | −45.01 ms | **−78.00 ms** |
| 事件帧迟到 | 29–31 ms | **61.7 ms** |
| 200 ms 台阶丢帧 | 0 | **5** |

原因是结构性的，不是调参能救的：**台阶是输入**，注入那一帧的 `due` 已经被
推动 80 ms 了；限速只决定"这一帧还回去多少"。限速越慢，事件帧就得独自吃下越多。
AB 之所以"看起来更平滑"，是因为它当帧就还了 35 ms —— 它没有消除台阶，
只是把台阶藏进了事件帧。

而在**渐变漂移**上（P13-R/U/V/Z 八次真实事件的唯一形状），触发那一刻的超出量
只有几毫秒，限速连一帧都跑不满 —— 它根本不起作用。

**结论：限速只在瞬时台阶上有作用，且更差；渐变漂移上无用。撤掉。**

## 三、方案 B（采纳）：两阈值迟滞带

```
        cum > limit ──进入收敛──▶ 一次修到 limit − band
             ▲                              │
             └──────── cum ≤ limit−band ◀───┘ 退出
```

- `drift_band_ns = 5 ms`（`PacePolicy`）。复位目标 `40 ms`，触发阈值仍是 `45 ms`。
- 修正**不设单帧上限**：一次还完。因为台阶是输入，还晚了只会让事件帧更难看。

关键实现细节：**必须是两个阈值，不能是"一个阈值 + 一个目标"**。
第一版写成"`cum > 45` 就修到 40"，可它一帧只肯修 2 ms，最后一帧修完落在 44 ——
已经低于触发阈值，状态机退出，永远到不了 40。真机四轮残差全是 **44.00–44.03**。
单测当时是绿的：断言只写了 `lead <= limit`，44 满足。**断言的松紧决定了单测
能不能发现"设计没实现"。**

## 四、预期值（先算再跑）

| 量 | 预期 |
|---|---|
| `clock_ahead` | **40.0 ms**（`limit − band`，与注入量无关） |
| `playback_rate` | `span/(span − 0.040)` = **1.00504**（AB 是 1.00565） |
| `drift_rebases` | **1**（一次还完） |
| `drift_max_correction_ns` | `= drift_corrected_total_ns` = `注入量 − 40 ms` |
| 事件帧 `due_step` | `−(注入量 − 40 ms)`：80 ms → −40.0；200 ms → −160.0 |
| 事件帧迟到 | `due_step` 减去同帧 `present_step`（约 −16 ms）→ **≈ 24 ms**（AB 是 29） |

最后两行是这个方案的额外收益：把收敛目标从 45 挪到 40，事件帧的位移也跟着
少了 5 ms —— 迟到从 29 降到 24，而残差反而更小。

## 五、不做的事

- 不给大台阶开快车道：现在本来就是"一次还完"，没有更快的了。
- 不改 `limit`（45 ms）、`band`（5 ms）与 `late_drop_ns`（100 ms）。
  band 取 5 ms 是"一个 60 fps 帧的三分之一"，没有主观画质数据支撑。
