# 111 · P13-AD 设计：注入「速率」，给门做第一次真对照

- 日期：2026-10-30
- 前置：`110-p13ac-status.md`（迟滞带收口，但全部结论建立在**瞬时台阶**上）
- 目标：把门放到**真实事件的形状**上检验，并且第一次给出"门关"对照组。

---

## 一、为什么台阶不够

P13-R/U/V/Z 一共 8 次真实位移，形状**全都是渐变**：8 秒里 `clock_ahead` 从 0
长到 73–165 ms（1.5%–5% 的速率差）。而 P13-AB/AC 注入的是**瞬时台阶** ——
80 ms 一步到位。

两种输入对门的要求完全不同：

| | 台阶 | 速率 |
|---|---|---|
| 触发时的超出量 | 整个台阶（80 ms） | 几毫秒（每帧只长 0.25 ms） |
| 主要矛盾 | "当帧还多少"（P13-AC 争的就是这个） | "能不能一直追住、不越攒越多" |
| 单帧迟到 | 24 ms | 几毫秒 |

所以 P13-AC 里"限速 vs 一次还完"那场争论，在真实形状下**几乎没有差别** ——
这本身就是必须测一次的理由。

## 二、速率注入怎么做

复用 `ClockOffsetSource`，加一个 `rate_ppm`：

```
pos' = rate_origin + (pos − rate_origin) × (1 + ppm/1e6)     从注入点起算
```

从注入点起算而不是从 0 起算：前面的样本不该被改写，否则 `first_lateness_ns`、
跨度账、`arm_after` 的语义全部跟着漂。

符号与 `offset_ns`、`clock_ahead`、`playback_rate` 一致：**正 = 钟比墙快**。
（写实现时先用过 `__int128`，MSVC 不认，桌面构建当场编译失败 —— 改成 int64，
span ≤ 20 s × ppm ≤ 1e5 = 2e15，装得下。）

## 三、对照组：门关

新增 `PacePolicy::drift_gate_enabled`，探针用 `kivo.drift_gate=off` 关掉。

**为什么必须有这一组**：一份 `drift_rebases = 0` 的证据，可能是"门判断该沉默"，
也可能是"门根本没接上"。这两件事在字段上完全一样 —— P13-T 已经吃过一次
（`drift_rebases` 漏写，看起来像"门从没触发"）。所以关着门的一轮必须
**出版开关状态**（`drift_gate.enabled`），否则对照白做。

顺带把 `limit_ns` / `band_ns` 也出版：校验器从此用证据里的数复算，
不再硬编码 45/5 —— 改策略只要升 schema，不会出现"新实现被旧上限卡住"。

## 四、判据要改：门压的是**相位**，不是**速率**

这是本卡最容易想错的地方。时钟以 1.5% 的速率跑快时，门每越线一次就把位置拉回
5 ms，于是：

- **累积偏移**被压在 `[limit − band, limit]` 里 —— 这是门能做的事；
- **速率**不动：位置照样以 1.5% 增长，只是每次涨过头就被拽回来。
  等价地说，`elapsed` 的**净**推进率被拉到 1.0，但每帧仍然带着约 40 ms 的固定超前。

所以 `playback_rate` 不会回到 1.000，它会停在 `1 + 残差/时长`：

| | 门关 | 门开 |
|---|---|---|
| `clock_ahead` | `≈ ppm × 时长`（**无界**） | `∈ [40, 45] ms`（**有界**） |
| `playback_rate` | `≈ 1 + ppm` | `≈ 1 + 40ms/时长` |

**判据写成"速率回到 1.000"是错的**，那要求门能改速率 —— 只有重采样能做到。
正确的判据是：`clock_ahead` 有界、且与 ppm 无关。

## 五、预期值

| 轮 | 预期 `clock_ahead` | 预期 `playback_rate` | 预期 `drift_rebases` |
|---|---|---|---|
| 干净（无注入） | ≈ 0 | ≈ 1.0000 | 0 |
| 1.5%，门关 | `0.015 × 6.9 s ≈ 103 ms` | ≈ 1.0131 | 0 |
| 1.5%，门开 | 40–45 ms | ≈ 1.0054 | ≈ 每 5–6 ms 一次，约 12–18 |
| 5%，门关 | `0.05 × 6.9 s ≈ 345 ms` | ≈ 1.045 | 0 |
| 5%，门开 | **同样 40–45 ms**（与 ppm 无关） | ≈ 1.0050 | ≈ 57 |

最后一行是这一卡的靶心：**ppm 翻三倍多，残差不变**。

## 六、一个必须写下的前提

门假设"时钟的**估计**错了"，而不是"播放真的快了"。前者是估计器的问题（HAL 报数、
外推），后者是硬件时钟的问题 —— 晶振典型偏差是 ±100 ppm，1.5% 差两个数量级，
所以对这台设备而言这个假设成立。

但如果真遇到音频**确实**在快放，门就是在跟真相对抗，正确的处置是重采样而不是改相位。
这条边界写在结题里，不留在注释里。
