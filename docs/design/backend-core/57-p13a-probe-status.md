## 二、三个必须写下来的细节

### 1. `max_fps = 240` 是幌子，`achievable = 63/149` 才是真的

每条 4K 记录的 `max_fps` 都是 **240**，而 `achievable_fps` 只有 63（AVC）或 149（HEVC）。

**如果只取 `getSupportedFrameRatesFor`，会得出"4K 能跑 240fps"的荒谬结论。**
所以判定取 `min(声明, 可达)` —— 这条被单测 `P13A-5` 钉死了：

```cpp
make("video/hevc", 3840, 2160, 1, 60.0, 30.0)  →  best_fps_for(...) == 30.0
```

取声明值会得到 60（假的），取 min 得到 30（真的）。

### 2. **API 是 per-codec，不是 per-profile** —— 10bit 和 8bit 报同一个数

4K 上 HEVC 的五个 profile（main / main10 / mainstill / hdr10 / hdr10plus）**全部报 149fps**。

这是平台 API 的粒度限制，不是我们采错：`getSupportedFrameRatesFor` 挂在
`MediaCodecInfo.VideoCapabilities` 上，而那个对象是 per-mime 的，**不区分 profile**。

**所以「HEVC 4K60 = 149fps」不能推出「10bit 4K60 一定跑得动」。**
10bit 的带宽通常是 8bit 的 1.5–2 倍，而这里两个数一模一样 ——
这恰恰说明这个数字**没考虑位深**。

结论：**10bit 4K60 必须单独实测**，不能拿 8bit 的结论外推。

### 3. AVC 4K60 的余量只有 5% —— 最可能暴露真实上限的一组

`63 / 60 = 1.05`。这个余量意味着：

- 任何额外的像素开销（Surface 缩放、色彩转换、合成）都可能把它压到 60 以下
- 它最可能成为"能力表说 yes、真播掉帧"的例子

**所以这一组不是"顺便测一下"，它是本卡最有信息量的高压组。**

对照：HEVC 4K60 有 2.5× 余量，属于"应该很稳"的对照组。

## 三、片源规格决策（本卡的下一步）

按上面的分析定，不按"能造多大就造多大"：

| 规格 | 角色 | 理由 |
| --- | --- | --- |
| **4K60 HEVC 8bit** | 主目标 / 对照组 | 149fps，2.5× 余量，应该稳 |
| **4K60 HEVC 10bit** | 关键验证组 | 验证"per-codec 声明"是否掩盖了位深代价 |
| **4K60 AVC** | **高压组** | 63fps 贴上限，最可能暴露真实瓶颈 |
| 4K30 HEVC 8bit | 基准 | 与 1080p30 的既有数据可比 |
| 1080p60 HEVC 50Mbps | 码率压力 | 把"码率"与"分辨率"解耦 |

**不做 120fps**：K40 屏幕是 60Hz，120fps 片源必然被判丢帧（节拍器行为正确），
测出来的"丢帧"是屏幕的物理限制，不是播放器的问题 —— 没有信息量。

## 四、诚实清单（五条）

1. **全是厂商声明，没有一条是实测。** 这张卡（P13-A 的探测部分）只回答"平台怎么说"。
2. **per-profile 的差异被 API 抹平了。** 见 §二 第 2 条，10bit/8bit 同值。
3. **只查了三个分辨率**（1080p/1440p/4K）。1440p 的记录采了但没进 verdict ——
   它是"看线性度"用的旁证，不是判据。
4. **只采了 `isHardwareAccelerated` 的 codec。** 软解在 4K 上没有参考价值；
   API 29 以下拿不到这个标志时会全采（本机 API 33，没有这个问题）。
5. **`size_supported = 1` 不等于"实时可播"。** 它只说"这个尺寸能解"，
   帧率是另一个维度 —— 两个都看才构成能力表，任一单独看都会误判。

---

## 五、下一步（真播验证）

1. 造上面 5 个规格的片源（仓库 ffmpeg，控制在几十 MB 内）。
2. 跑播放取证，判据沿用既有那套：帧数闭合、零丢帧、`av_drift`、首帧时延。
3. **高压组的预期**：4K60 AVC 可能会掉帧。如果掉了，那是**真实的能力边界**，
   要写进证据而不是当成 bug 去修 —— 修不掉，那是芯片的极限。
4. 每份证据的 `scope` 要写明"2400×1080 屏上播放 4K 片源，测的是解码 + 缩放上屏"。
