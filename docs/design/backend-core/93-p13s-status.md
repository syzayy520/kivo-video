# 93 · P13-S 验收：门装上了，但「它有没有生效」这一轮没验成

- 版本：V1.0
- 日期：2026-10-30
- 设计：`92-p13s-design.md`
- 判据：S1–S4
- 结论：**护栏实现并单测通过（S1/S2/S4 达成）；真机 A/B 不成立（S3 未达成）** ——
  三轮里 `drift_rebases = 0`，门一次都没响，所以"时钟变准了"不是这次改动的功劳。
  同一批数据还带出一条对 P13-R 结论的**反向疑问**（§三）。

---

## 一、改了什么

`ClockPositionTracker` 新增累积漂移门：

```
连续 60 帧「位置增量 > 墙钟增量」 且 累积超前 > 45 ms  ⇒  位置 -= 累积量
```

- `jump_limit_ns`（单次 1 s）管不到速率误差，这条门管的是"每帧只差一点、攒起来很大"；
- 只拦"快"不拦"慢"（慢是 stale / free_run 的事）；
- 复位放在倒退钳制**之后**（否则被钳制原样抬回去）；
- 计数 `pace.clock_health.drift_rebases`，schema `sync/17`。

## 二、单测（S1 / S2 达成）

`kivo_p12c5_pace_tests` 新增 **S1**：假时钟每帧多走 250 µs（1.5%），400 帧。

| 断言 | 结果 |
|---|---|
| `drift_rebases ≥ 1` | 2 |
| 末帧 `position − 墙钟 ≤ 45 ms + 一帧` | 通过（实测 −24 ms，略微落后，可接受） |
| `jump_rebases == 0`（不该把速率误差当跳变） | 0 |
| 同步时钟 400 帧 ⇒ `drift_rebases == 0`（S2 不误伤） | 0 |

`ctest -R "kivo_p13|kivo_p12c5"`：**15/15**。

> 这条门在写对之前错过两次，都被 S1 当场打红：
> ① 只做减法、没考虑倒退钳制 ⇒ 66 ms 残余超前；
> ② 用"重设基准值"代替减法 ⇒ 基准自己也会漂。

## 三、真机 A/B：**不成立**（S3 未达成）

三轮（`docs/evidence/p13s/`，`sync/17`）：

| 轮 | max (ms) | 丢帧 | `drift_rebases` | `clock_ahead` | `playback_rate` |
|---|---|---|---|---|---|
| r1 | 34.81 | **18** | **0** | **+247.69 ms** | 1.032032 |
| r2 | 25.47 | 0 | **0** | **+0.02 ms** | 0.999993 |
| r3 | 52.16 | 0 | **0** | **+0.01 ms** | 1.000012 |

**门一次都没响**（`drift_rebases` 全 0），所以：

- r2 / r3 的 `clock_ahead ≈ 0` **不是这条门的功劳** —— 那两轮本来就没出现异常；
- r1 出现了 247.69 ms 的超前，门却没响 —— 说明那 247 ms **不是**"钟比墙快"造成的，
  否则连续超前会攒到 45 ms 并触发。

### 3.1 这条反向证据在说什么

r1 的三个数放在一起：`clock_ahead +247.69`、`arrive_excess −263.98`、丢 18 帧。
`arrive_excess = arrive_mono_span − pts_span` 为负，意味着**帧比媒体时间到得还密**
（管线跑到前面去了）。若管线整体提前 264 ms，而钟按真实时间走，那么
`clock_ahead = elapsed − mono_span` 自然就是 +248 ms —— **它不是"钟快"，是"分母短"**。

这直接动摇 P13-R 的因果判断：那份证据里 `playback_rate = 1.0151` 证明"视频确实播快了"，
但**快的原因是管线提前，不一定是钟超前的估计**。P13-R 写的"音频时钟位置比墙钟快 1.5–5.4%"
应当降级为"两者在同一批数据里同时出现，方向未定"。

## 四、诚实清单

1. **S3 没达成**，本卡不能声称"修好了"。门是否正确实现，只有单测（S1/S2）在守。
2. **这轮的负载很可能没真正加上**：`r1` 是空载轮却出现了 247 ms 异常，r2/r3 标称满载却只有
   +0.02 ms。忙循环是 `adb shell` 起的，没有记录每轮的实际空闲率 —— 这是 P12-D5 犯过的错
   （"假空载"），本卡又犯了一次。
3. **P13-R 的因果需要重写**（§3.1）。`clock_ahead` 是"钟的位置超前"，还是"到达窗口被压缩"，
   现有字段分不开：两者在数值上完全等价。要分开得有一个**不依赖到达时刻**的墙钟基准
   （例如 `CLOCK_MONOTONIC` 在交出端的时间戳，`present_wall_span` 就是它 —— 但它只覆盖呈现段）。
4. **门本身有代价**：每次复位都把位置往回拨最多 45 ms，`av_drift` 会因此出现周期性台阶。
   长片源（10 分钟以上）里这条门会响很多次，`av_drift` 的趋势判据可能被它搅乱 —— 没测。
5. **45 ms 的门限是借来的**（`kAudibleThresholdNs`）。它与"能不能听出来"对齐，但与
   "时钟估计本身有多准"没有关系；真实设备的正常漂移若接近这个量级，这条门会频繁误触发。
6. **只跑了 3 轮**，其中 1 轮丢帧 18（账不平，P13-Q 的已知缺陷）。
7. ~~**`jump_rebases` 那个字段一直是 0**：节拍器从来没把 tracker 的计数搬进去。~~
   **这条是错的，已在 P13-T 更正**：`FramePacer::summary()` 确实搬了 jump / stale /
   backward / monotonic 四个计数（`frame_pacer.cxx` 第 257–260 行）。442 份证据全 0 是因为
   tracker 级的跳变一次都没发生。真正没接上的是**本卡新加的 `drift_rebases`** ——
   `PaceStats::summary()` 漏了那一行，P13-T 已补并加 S3 单测钉住。
