# 74 · P13-J 设计：漂移的误差棒

> 一句话：**漂移量准从来不是卡在 7 ppm，是缺刻度盘。**
> 抗噪的那把尺子只有 1 个刻度（八窗中位数全是同一个数），
> 细的那把尺子从来没画过误差棒（`-0.022183` 在 `r2 = 5.5e-05` 之下是噪声）。
> 本卡把前者换成原始值中位数，给后者补上标准误与置信带。

## 一、问题

### 1.1 从 P13-D 说到 P13-I 的那句话是错的

P13-D 起，每张状态卡都写着同一句欠账：**"漂移量准卡在 0.25 ms 桶宽 ⇒ 分辨率约 7 ppm"**。
7 ppm 是这么算出来的：桶中心量化误差 ±125 µs，在 35 s 跨度上是 `125e-6 / 35 ≈ 3.6 ppm`，
取整说 7 ppm（相邻两格之差 250 µs 除以 35 s）。

这句话听上去很合理，实际**过于乐观**。P13-I 的三轮真机证据摆在一起看：

| 轮次 | 片源 | 八窗中位数 | 不同取值数 | `delta_median_ns` | `slope_from_windows_ppm` |
|---|---|---|---|---|---|
| r1 | 130 s 360p30 | 全 125 000 | **1** | 0 | **0.000000** |
| r2 | 130 s + seek | 全 125 000 | **1** | 0 | **0.000000** |
| r3 | 35 s 1080p30 | 全 125 000 | **1** | 0 | **0.000000** |

三个片源、三种片长、2600 个样本，**`slope_from_windows_ppm` 一次都没有跨过刻度**。
所以它的可分辨力不是 7 ppm，是**零个刻度** —— 它只能输出 0，而 0 在这里既不表示
"没有漂移"，也不表示"漂移小于 7 ppm"，它只表示"八个窗口被量化成了同一个数"。

### 1.2 为什么全都塌成 125 000

`percentile_ns(0.50)` 返回的是**桶中心**，桶宽 0.25 ms。三轮的桶分布：

| 轮次 | 主桶 | 占比 | 该桶区间 | 真实 lateness 范围 |
|---|---|---|---|---|
| r1 | 512 | 2013 / 2048 = **98.3%** | 0 ~ 250 µs | 29 427 ns ~ 2 039 897 ns |
| r2 | 512 | 1963 / 2000 = **98.2%** | 0 ~ 250 µs | 17 657 ns ~ 3 561 874 ns |
| r3 | 512 | 662 / 700 = **94.6%** | 0 ~ 250 µs | 19 219 ns ~ 4 501 189 ns |

桶 512 的中心恰好是 125 000 ns。98% 的样本落在同一个桶里，于是每窗的中位数都是它 ——
而真实中位数在 29 µs 到 250 µs 之间铺了 **220 µs**，全被一个数吃掉。

### 1.3 另一把尺子的毛病：没有刻度盘

同一批证据里，逐点回归的 `slope_ppm` 是精确的（输入是 ns 整数）：

| 轮次 | `slope_ppm` | `r2` | 该怎么读 |
|---|---|---|---|
| r1 | −0.022183 | 5.5e−05 | 这条线解释了 **0.0055%** 的方差 |
| r2 | 0.464859 | 5.1e−03 | 0.5% |
| r3 | 0.408112 | 2.2e−04 | 0.02% |

六位小数在 `r2 = 5.5e-05` 之下**全是噪声**。但因为报告只给一个点估计、不给误差，
读者（包括写它的人）会把它读成"精确测到 −0.022 ppm"，而不是"−0.022 ± 零点几 ppm"。

**这是本卡真正的缺陷**：不是尺子粗，是尺子没画刻度盘。

## 二、做法

### 2.1 窗口中位数改从原始值选

新单元 `core/pace/pace_window_stats.{hpp,cxx}`，两个函数：

- `split_windows(series, window_count, out)` —— 按媒体时间切窗，边界规则与趋势里原来那段
  内联循环**逐字一致**（`index = (media_ns − t0) × 8 / span`，末点归最后一窗）。
  抽出来是因为"哪些点属于这一窗"必须只有一个答案：两处各写一遍，迟早在
  `span × w / 8` 的整除截断上分家。
- `median_of_slice(series, slice, fallback_histogram)` —— 把该窗的**原始** `lateness_ns`
  收进栈上 scratch（512 × 8 B = 4 KB），`std::nth_element` 选第 ⌈n/2⌉ 个。
  桶只给超采样窗兜底，并通过 `WindowMedian::exact` 显式报告降级。

为什么 scratch 是 512 而不是"按需分配"：满容量序列每窗 256 点，512 是两倍余量；
超过时退回桶中心并报 `exact = false`。宁可说"这一窗是估的"，也不编一个精确的样子。

秩取上整，与 `SignedHistogram::percentile_ns(0.50)` 同口径 —— 两份中位数会同时出现在
证据里（窗口分布 vs 整场分布），口径不同就会出现"同一批点的 p50 有两个值"。

### 2.2 斜率配标准误

`Regression::solve()` 多算一项：

```
σ̂²  = SSres / (n − 2)          // 两个参数：截距 + 斜率
SE   = sqrt(σ̂² / Sxx)
```

`DriftTrend` 新增六个字段：

| 字段 | 含义 |
|---|---|
| `slope_ppm_std_error` | 逐点回归斜率的标准误（ppm） |
| `slope_ci_low_ppm` / `slope_ci_high_ppm` | 名义 95% 置信带（`slope ± 1.96 SE`） |
| `slope_detectable` | CI 不含 0 ⇒ 在这把尺子的分辨力之内看得见漂移 |
| `window_median_exact` | 八窗中位数是否**全部**由原始值选出 |
| `window_median_fallback_windows` | 退回桶中心的窗数 |

存两端而不是只存半宽：读者要回答的问题从来是"0 在不在里面"，
一个半宽还要他自己减一遍，多一步就多一次算错的机会。

**`SE == 0` 的两种来源必须分开**：残差恰为 0（完美线性 ⇒ 看得见），或 `n < 3`
算不出方差（⇒ 看不见）。用"斜率是否为 0"区分不了这两种（两个点必过一条直线，
任何两点组合的斜率都"非零"）。所以 `n < 3` 时显式把 `slope_detectable` 置 false，
不靠那个 `else` 猜。

### 2.3 报告层 `/8`

```
"slope_ppm": -0.022183,
"slope_ppm_std_error": 0.074800,
"slope_ci_low_ppm": -0.161491,
"slope_ci_high_ppm": 0.114825,
"slope_detectable": false,
"slope_from_windows_ppm": 0.000000,
"window_median_exact": true,
"window_median_fallback_windows": 0,
```

`std_error` 紧跟 `slope_ppm` 是**防腐不是排版**：两个数分开摆，读者就会单独引用
那六位小数，而它的可信度全看 SE。

`window_median_exact` 紧跟 `slope_from_windows_ppm` 同理 —— 说一个 0 而不说
尺子上有几个刻度，是这份证据从 P13-D 到 P13-I 一直犯的错。

## 三、判据 J0–J6

| 判据 | 内容 | 抓什么 |
|---|---|---|
| J0 | 六个字段齐全 | 报告层没跟上 schema 版本 |
| J1 | `SE` 有限且 ≥ 0 | 符号写反、对负数开根号 |
| J2 | `CI == slope ± 1.96 SE`（容差 2e−6） | CI 走了别的路径，那它就不是 slope 的置信带 |
| J3 | CI 含 0 ⇔ `slope_detectable` 为假 | 把噪声包装成漂移 |
| J4 | `exact` 与 `fallback` 计数自洽 | 两个字段各说各话 |
| J5 | 中位数全等 ⇒ 窗口斜率恰为 0 | 同一批 y 回归出非零斜率 |
| J6 | 降级窗 + 零窗口斜率 ⇒ 该 0 不可解读 | **本卡的核心**：量不出来不许说成没漂移 |

J5 只判一侧：反过来不成立（对称阶梯可以让斜率≈0 而中位数互不相等），
硬判会产出假红。

J3 在 `samples < 3` 时改判"`detectable` 必须为 false"，理由见 §2.2。

## 四、变异自测

| 变异 | 内容 | 结果 |
|---|---|---|
| C1 | `median_of_slice` 一律走桶中心（退回旧实现） | **14 处红** |
| C2 | 不填 `slope_se_per_ns`（等于宣称"没有误差"） | **8 处红** |
| C3 | 秩从 `(n+1)/2` 改成 `n/2` | **1 处红** |

### 4.1 C1 差点白做

第一版 C1 只红了三行 `exact` 标记，八条中位数断言**全绿**。原因是我构造的
测试数据每窗内 lateness 恒定 —— `min == max == 中位数`，`percentile_ns()`
把桶中心钳回 `[min, max]` 又还原成了原值。

真机上不会这样，是因为每窗都有偶发尖峰把 `max` 顶到 125 µs 之上。
所以反例必须**每窗埋一个 300 µs 的尖峰**：它不进中位数（1/250），
但让桶中心落进样本范围，钳位救不回来。

这条写在这里，是因为"变异红了"本身不足以证明判据有效 —— 得看它红在哪。
只红标记、不红数据的变异，等于什么都没验。

### 4.2 C3 撞出一个真缺陷

C3 第一次跑直接崩了：

```
Debug Assertion Failed!
Expression: cannot seek array iterator before begin
```

`rank = n/2` 在单点窗上得 0，`nth_element(begin, begin + (rank-1), end)` 就是
`begin() - 1`。正确实现 `(n+1)/2` 在 n ≥ 1 时恒 ≥ 1，踩不到 —— 但代码没有防御。

已加 `rank_raw` 钳制。**变异该"红"，不该"崩"**：崩了只能证明进程会死，
证明不了判据能抓住错误。加上钳制后 C3 稳定地红在 `t08` 的 n=7 那条上。

## 五、不做的事

1. **不重写历史证据。** `/7` 及以前的几十份证据保持原样，J 判据只对 `/8` 生效。
   重写等于伪造。
2. **不动 `SignedHistogram` 的桶宽。** 0.25 ms 对"抖动是否超过一帧"这个判据够用，
   p99 的历史可比性比精度更重要。要更细的中位数走 `median_of_slice`，不走改桶。
3. **不上 HAC / Newey-West。** 见诚实清单第一条。
4. **不给窗口斜率配 SE。** 8 个点的回归，SE 大且中位数量化问题刚修，
   先让它能跑；主尺子是逐点回归。
5. **不改 `kMinSamples` / `kMinSpanNs`。** 那是"斜率可不可信"的门，与本卡无关。

## 六、诚实清单

1. ⚠️ **SE 假设残差独立同分布，而 `lateness` 是强自相关的**（vsync 抖动 +
   抽稀序列本身平滑）。真实不确定度**大于**这里给出的值，置信带是**乐观下界**。
   要更严格得上 HAC/Newey-West，那是另一张卡。
   **实测证据**：r3（35 s、700 个样本）报出 `detectable = true`，而 `r2 = 0.007`。
   统计上"斜率非零"成立，线性度却只有 0.7% —— 这正是低估 SE 的典型形态。
   所以 `slope_detectable = true` 必须与 `r2` 一起读，单独看会误判。
2. ⚠️ 1.96 是正态近似。n = 2000 时没问题，n = 30 时应该用 t 分布（t ≈ 2.04，
   差 4%，在噪声量级之内）。没有按 n 切换系数，因为切换点本身是个假精度。
3. ⚠️ 这一卡不会让任何"漂移量是 0"的历史结论变真。它只让"小于多少"这句话
   第一次有依据。
4. ⚠️ 窗口斜率的 0 在 `window_median_exact == true` 时才可读成"没漂"。
   这一点由 J6 守，但读者仍可能忽略那个字段。
5. ⚠️ scratch 512 的降级路径只在单测里走到过（合成数据把 600 个点挤在一窗），
   真机上每窗 256 点，没踩到。降级证据按 J6 会被判红，需要人工审。
6. ⚠️ 只验了 360p / 1080p，不支持任何 4K 结论。
7. ⚠️ `PaceSummary` 又大了 8 字节（六个字段里四字节对齐后），可忽略。
