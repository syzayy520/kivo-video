# 106 · P13-AA 验收：领先量改成「两端之差」，账不再漏；真机五轮无位移

- 日期：2026-10-30
- 前置：`105-p13z-status.md`（`clock_ahead +73.30 ms` 却 `drift_rebases = 0`）
- 结论：**改法成立、恒等式有单测**；真机五轮 `clock_ahead` 全在 ±0.03 ms 内，**没撞上事件**。

## 一、改法

```cpp
// 旧：逐帧累加，只在正常分支记
cum_drift += raw_delta − wall_delta;
// 新：从两端算，三条推进分支都被同一把尺子量到
cum_drift = position − (origin_position + (mono − origin_mono));
```

`stale` 外推、`jump_rebase`、倒退钳制都会直接改 `position`，旧账记不到；
新式**按定义**覆盖它们。启动期（首帧后 1 s）仍不拦（P13-W 约定，保 C5 语义）。

## 二、单测

新增 **S6**：300 帧里混入一次 80 ms 台阶与 5 帧 stale，逐帧断言
`position − (原点 + 墙钟) ≤ 门限 + 一帧`，并断言门至少触发一次。
S1/S3/S4/S5 + C5 二十六条全过，`ctest -R "kivo_p13|kivo_p12c5"` 15/15。

但同样**没验证到"触发时不过冲"**。这一批的特点是丢帧多（最高 34），
说明负载到位了，只是这次时钟没跑偏。

## 四、诚实清单

1. **仍未拿到"触发且不过冲"的真机证据** —— 从 P13-S 追到现在，这条一直欠着。
2. 五轮全空不能说明门没用；按历史复现率（约 1/3）五轮全空概率约 13%，不算罕见。
3. **本卡的确定性成果**是恒等式与 S6：不管事件什么时候来，账不会再漏。
4. `origin_*` 只在首帧设一次，`reset()` 里没清（`reset` 会重建 tracker，实际无影响，但没写测试）。
