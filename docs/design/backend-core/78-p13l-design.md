# 78 · P13-L 设计：把"看得见"翻译成"要紧不要紧"

> 一句话：**`detectable = true` 不是结论，它只是"与 0 分得开"。**
> P13-J 的 r3 报着 `detectable = true`，而那个斜率在 35 秒里只累积 **17 µs** ——
> 相当于 60 Hz 一帧（16.7 ms）的 **0.1%**。分得开是因为尺子细，不要紧是因为量太小。
> 同理，CI 宽到含 0（`detectable = false`）也不能推出"没事"：
> 远端积起来可能已经越过人耳阈值。本卡把 `ppm` 积回纳秒，并对着一个
> 写明出处的额度判一次，**用上界判，不用点估计判**。

## 一、问题

### 1.1 一句被读错了两张卡的话

P13-J 加了误差棒，P13-K 换了噪声模型。两卡都在回答同一个问题：
**这个斜率与 0 分得开吗。** 而读者要问的是另一个问题：**要紧吗。**

这两件事可以完全脱钩，三个方向上都会脱钩：

| 情形 | `detectable` | 真实含义 | 被误读成 |
|---|---|---|---|
| 尺子很细 + 漂移很小 | true | 0.48 ppm，35 s 累计 17 µs | "要出事了" |
| 尺子很粗 + 漂移很大 | false | 可能是任意值，CI 上界 80 ms | "没事" |
| 趋势不可用 | false | 样本不够，根本没量 | "没事" |

第一行是真事。P13-J 的 r3（35 s / 700 点）：

```
slope_ppm = 0.479713   SE = 0.215162   CI = [+0.058, +0.901]   detectable = true
r2 = 0.007071
```

按定义"看得见"。可它累积下来是 `0.479713 ppm × 34.97 s = 16.8 µs`。
这是一个**量级判读**，而当时的证据里没有任何一个字段能直接给出它 ——
读者必须自己把 ppm 乘以秒、再乘 1000，才知道那个 `true` 有多小。
**判据不能要求读者做单位换算。**

### 1.2 反方向的漏报同样真实

第二行不是假想的。同一批数据里 P13-K 的 35 s 轮：

```
slope_ppm = 0.306929   HAC SE = 1.762968   CI = [−3.148, +3.762]   detectable = false
```

CI 含 0，判"看不见"。但 CI 的远端 `+3.762 ppm` 在 34.97 s 里积起来是
**131.6 µs**。这个数还没到 45 ms，可它说明了机制：
**只要 SE 足够大，"看不见"就与"没事"无关** —— 带宽是被噪声撑开的，
不是被漂移撑开的。把 CI 宽的证据读成"漂移小"，是拿噪声当保证。

所以判定必须用**上界**：

```
upper_ppm = max(|ci_low|, |ci_high|)
upper_ns  = upper_ppm × span_s
```

取绝对值较大的一端，而不是 `ci_high`：早 45 ms 与晚 45 ms 一样糟，
方向不该影响"会不会被听出来"。

### 1.3 为什么不在报告层顺手乘一下

三个理由，每个都独立成立：

1. **单位换算是错得最安静的那类 bug。** `ppm × 秒 × 1000` 少一个 1000
   就是 1000 倍的结论差异，而结果仍然是个"合理"的整数纳秒。
   把它放进一个 60 行的纯函数里，单测能钉住它；写在 `out <<` 的表达式里，钉不住。
2. **阈值会变。** 45 ms 是今天的口径。哪天要加一档"严格"（比如 10 ms），
   改动半径必须可见 —— 一个单元 > 散落在报告层的三处比较。
3. **三态判定不能靠布尔拼。** `unknown` / `within_budget` / `over_budget`
   是三个结论，不是两个。用 `bool` 表达时，`false` 同时意味着
   "低于预算"和"根本没算出来" —— 而这两种情形对读者的指示完全相反。

## 二、做法

### 2.1 新单元 `core/pace/pace_drift_budget`

只做一件事：`(slope_ppm, se_ppm, span_ns, usable) → 累积量 + 三态判定`。
不读时钟、不分配、不改任何入参。

```cpp
struct DriftAccumulation {
    bool estimated = false;              // 数算出来了吗（与 verdict 不冗余）
    std::int64_t accumulated_ns = 0;     // 点估计，带符号
    std::int64_t accumulated_upper_ns = 0;  // 保守上界，非负
    std::int64_t threshold_ns = kAudibleThresholdNs;
    DriftVerdict verdict = DriftVerdict::kUnknown;
};
```

`estimated` 与 `verdict` 刻意不合并：趋势不可用时数**算得出来**（`estimated = true`），
只是没有资格下结论（`verdict = kUnknown`）。这与 P13-K 里
"`hac_estimated` 与 `slope_ppm_std_error` 分开"是同一条纪律 ——
**事实照给，结论另说。**

非有限数、负的 SE、不前进的跨度，一律 `estimated = false`：

- 负 SE 单独判，是因为它会让 `half` 变负、CI 两端交换，
  而 `max(|low|,|high|)` 挑出来的仍是同一个数 —— **错误会被悄悄吞掉**；
- 溢出用 `|value| > 9e18` 显式挡掉。`llround` 越界是未定义行为，
  在 MSVC 上恰好返回 `LLONG_MIN`，一份荒谬输入会变成一个**负的累积漂移**，
  看起来像"音频跑到了前面"。

### 2.2 45 ms 的出处：为什么是它，不是 125，也不是 40

| 候选 | 出处 | 为什么不用 |
|---|---|---|
| **45 ms** | ITU-R BT.1359-1，音频**超前**可检测阈值 | ✅ 用这个 |
| 125 ms | 同一标准，音频**滞后**阈值 | 方向不对称，取较严的一侧更保守 |
| 40 ms | 业内常引的"体验上限" | **没有可引的文档**，写进证据就是一句无法核对的断言 |
| 16.7 ms | 60 Hz 一帧 | 与帧率绑定，不是人耳阈值 |

两个方向都用 45 ms 是**故意从严**：宁可把一份"刚好听得出来"的证据判成超额度，
也不要漏掉一份真的会被人耳抓到的。

必须同时说清一句：**45 ms 是检测阈值（刚能察觉），不是"可接受"。**
低于它只代表"大概率听不出偏移"，不代表体验合格。

### 2.3 上界而不是点估计

判 `over_budget` 用 `upper > threshold`，不是 `|point| > threshold`。
后果是**判定偏保守**：点估计 40 ms、上界 50 ms 的证据会被判成"越过额度"。
这是想要的 —— 一份"可能听得出来"的证据不该以"大概率没事"结案。

`>` 而不是 `>=`：恰好 45 ms 算"未超过"。这个开闭区间只写一处，
测试 `t06` 钉死它（1000 ppm × 45 s = 45 ms 整 ⇒ `within_budget`；
1001 ppm ⇒ `over_budget`）。

### 2.4 三态而不是布尔

```cpp
enum class DriftVerdict : std::int8_t {
    kUnknown = 0,        // 没资格下结论（不是"漂移很小"）
    kWithinBudget = 1,   // 上界未越额度
    kOverBudget = 2,     // 上界越过额度
};
```

线格式名 `"unknown"` / `"within_budget"` / `"over_budget"`，逐字钉在测试里。
`drift_verdict_name` 的 `default` 兜到 `unknown`：拼错的枚举值应当表现为
"没有结论"，而不是伪装成一个具体判定。

### 2.5 趋势接线：单出口（顺手修掉一个早退留下的 0）

`summarize_drift` 原来在两个统计门处**提前返回**：

```cpp
if (n < kMinSamples)      { out.unusable_reason = "..."; return out; }
if (span < kMinSpanNs)    { out.unusable_reason = "..."; return out; }
```

早退本身没错，错的是 P13-L 要在这两个门**之后**算累积量：
一旦早退，一份 20 点、斜率 2000 ppm 的证据会写出
`slope_ppm = 2000.0` 而 `drift_accumulated_ns = 0` —— 两句自相矛盾，
而那个 0 会被读成"没漂"。

所以两个门改成只设原因、不返回，最后统一算。这不改变任何既有行为
（原实现里窗口统计本来就在早退之前跑完），只是把"出口"从一个变两个再变回一个。
`t11` 专门钉这一条：20 点序列的 `drift_accumulated_ns` 必须是 1.9 ms 而不是 0。

### 2.6 报告层 `/10`

四个字段紧跟在 `slope_detectable` 后面输出，**不挪到 trend 末尾**：
挪开就等于让读者自己去乘那个 ppm，而 P13-K 的 r3 正是这么被读成"要出事"的。

```json
"slope_detectable": false,
"drift_accumulated_ns": 28885,
"drift_accumulated_upper_ns": 78586,
"drift_budget_ns": 45000000,
"drift_verdict": "within_budget",
```

三个数是**事实**，一个词是**结论**。`drift_budget_ns` 放进结构体而不是
让读者去翻常数：判定和它的尺子必须在一起，一个 `over_budget` 旁边没有额度，
等于一句没有刻度的断言。

### 2.7 校验器 L0–L5

只做一件事：**独立复算**那三个整数，不信证据里的数。

| 判据 | 内容 | 抓什么 |
|---|---|---|
| L0 | 四个字段齐全 | 报告层没跟上 schema |
| L1 | `point == slope × span / 1e6` | 单位错（漏 1e6 ⇒ 大 100 万倍） |
| L2 | `upper >= |point|` | 上界比点估计乐观（把半宽当上界） |
| L3 | `upper == max(|low|,|high|) × span / 1e6` | 取 `ci_high` 导致负斜率凭空乐观 |
| L4 | `budget == 45_000_000` | C++ 改了常数而校验器跟着改 |
| L5 | 三态与上界/额度/可用性自洽 | `unknown` 与 `within_budget` 混成一个 `false` |

`AUDIBLE_THRESHOLD_NS = 45_000_000` 在 Python 侧**独立写死**，
不从证据里读 —— 从证据里读就只会跟着一起错，P13-H 的 `observed_hz`
正是栽在"校验器复算同一个公式"。

复算容差 `2.0 + 2e-12 × span`：`slope_ppm` 是 `%.6f` 打印的，
误差 5e-7 ppm 乘 `span/1e6` 后变成 `span × 5e-13`（102 s 窗口 ⇒ 0.05 ns），
再加 `llround` 的半个格点。

## 三、判据 L0–L5

见 2.7。补充两条设计意图：

- **L2 与 L3 不是重复。** L2 只判方向（上界不许更乐观），L3 判数值来源
  （必须来自 CI 远端）。一个用点估计乘 1.1 的实现能过 L2，但过不了 L3。
- **L5 的三支不合并。** `unknown` 那一支判的是"趋势可用却判 unknown"
  与"趋势不可用却判了 within/over"两个方向 —— 后者更糟，
  那是让失败伪装成通过。合并成一个 `verdict == expected` 就看不见方向了。

十处注入，每处都必须让对应的判据/测试变红：

| 编号 | 注入 | 应红 |
|---|---|---|
| m01 | 上界改用点估计 × 1.05 | L3、t05 |
| m02 | 上界取 `ci_high` 而非两端较远者 | L2、L3、t04 |
| m03 | 额度改 40 ms | L4、t01、t06 |
| m04 | 边界用 `>=` 而非 `>` | t06 |
| m05 | 忽略 `usable`，永远判 within/over | L5、t09 |
| m06 | 不判非有限数 | t08 |
| m07 | 不判负 SE | t08 |

## 五、不做的事

- **不做跨轮汇总。** 单轮 verdict 不是设备常数（P13-K 已证 SE 会从
  0.2152 跳到 1.762968）。三轮各自判各自的，不合成一个"设备结论"。
- **不改 `slope_detectable` 的语义，也不改名。** 它没写错，它只是被读错了。
  改名会让历次证据的字段名与代码不一致，反而不利于对照 ——
  正确的做法是**在它旁边立刻给出翻译**。
- **不给绝对值偏移配预算。** `lateness` 本身有多大由 `quantiles` 那一份管。
  本卡只判**漂移增量**，两件事分开。
- **不做自适应阈值。** 按片长或帧率缩放额度会让"45 ms"这个可引用的数
  变成一条曲线，读者再也无法把它和标准对上。
- **不重写 `/9` 及以前的证据。** 旧证据不补算累积量 —— 补算等于伪造。

## 六、诚实清单（设计期）

1. **45 ms 是检测阈值，不是可接受上限。** 低于它只代表"大概率听不出偏移"。
   这张卡没有、也不能给出"体验合格"的结论。
2. **累积量只覆盖 `span_ns` 那一段，不是整场。** 斜率不能外推。
   一份 600 秒的片源若趋势只覆盖最后 102.4 秒（`truncated = true`），
   `drift_accumulated_ns` 说的也只是那 102.4 秒。长片源上它是**下限**。
3. **上界只覆盖斜率的抽样误差，不覆盖模型失配。** 序列若不是直线
   （中途跳一下、换向），这条斜率本身就描述错了对象，把上界放大也救不回来。
   那种情形由 `slope_halves_agree` 报警。
4. **三态没有区分"算出来了但趋势不可用"。** `verdict == unknown` 时，
   四个数值字段里可能真有一个算出来的累积量。读者若想知道"到底算没算"，
   只能看 `drift_accumulated_upper_ns != 0` 或 `slope_ppm != 0` ——
   这是一个由三态带来的信息损失，本卡接受它换取判定语义的单一性。
5. **判的是漂移增量，不是绝对偏移。** 一段 `lateness` 恒为 300 ms 的播放
   照样 `within_budget`：它一秒也没多漂。整体偏移由分位数那份负责。
6. **45 ms 对称使用，比标准偏严。** BT.1359 是 +45 / −125 ms 的不对称阈值，
   这里对"越来越晚"方向也用 45 ms。代价是可能误报，收益是不漏报。
7. **三份 P13-K 证据全部 `within_budget`，不代表"通过验收"。**
   它只说明"漂移这一项不是短板"—— 而同一批证据里 `r2` 全在 1e-4 量级，
   分位数 p50 还带着桶中心偏移（P13-J 遗留第 ③ 项）。
8. **`estimated` 没有写进 JSON。** 结构体里有，报告层没输出。
   理由是 `verdict` 已经承载了"能不能引用这些数"这个判断；
   再加一个 `estimated` 会让两份布尔在矛盾时无法裁决。
