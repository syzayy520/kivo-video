244 · SMB 链路 seek 复验（结转项 #2 解除）

设备：MatePad MRR-W29（`CFE6R21B12000179`），Android 12
时间：2026-11-10 07:02
服务器：`192.168.5.1`，共享 **`视频`**（不是原先记录的 `XiaoMi`）

## 一、解卡过程（为什么之前"共享不存在"）

原记录：`net use \\192.168.5.1\XiaoMi` → 系统错误 67。本轮复查发现共享是**改名了**：

```
net use
  OK  N:  \\192.168.5.1\视频      Disk
  OK  O:  \\192.168.5.1\<另一共享>  Disk
```

`N:/` 下可见目录：`111`、`tv`、`学习`、`电影` —— 共享**可用且可写**（匿名可写，已实测）。
所以"`XiaoMi` 不存在"是真的，但"服务器共享不可用"不成立，问题只是**共享名从 `XiaoMi` 变成了 `视频`**。

## 二、同源对照的做法

不拿共享里现成的大片做对照（编码/时长/音轨不一致，无法归因），
而是把**本地复验用的同一份文件**上传到共享，做成真正同源：

```
cp local-seek.mkv  → N:/kivo-test/local-seek.mkv   (2270964 B, H.264+MKV, 无音轨, 60 s)
cp mkv-audio.mkv   → N:/kivo-test/mkv-audio.mkv    (773318 B,  H.264+MKV, AAC,  20 s)
```

命令（`smbPath` 相对共享根，`smbShare` 用中文名）：

```
adb -s CFE6R21B12000179 shell am instrument -w \
  -e smbHost 192.168.5.1 -e smbShare 视频 -e smbPath kivo-test/local-seek.mkv \
  com.kivo.cinema.test/com.kivo.cinema.smb.SmbPlaybackSeekInstrumentation
```

## 五、结论

1. **SMB 链路的 seek 已真机验证通过**，视频-only 与带音轨两组均 4/4 PASS。
   原先担心的"`RangeFd` fd 输入 / `asyncInput=true` 落点时机不同"没有造成差异。
2. `session_seek` 的修复（`system_clock->rebase(video_landing)`）对 SMB 同样生效——
   因为它挂在共用路径上，与输入方式无关。
3. 244 结转项 #2 **解除**。14 个字的教训：**"共享不存在"要区分「名字变了」和「服务没了」**，
   本轮就是前者，卡了一个多小时的复验。
