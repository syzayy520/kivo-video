### ★★ 核心教训 1：**量像素，不要从代码推**

前四轮我从设计稿 HTML 的代码推导占比（`ic()` 的 `w:'56%'` → viewBox 86×96 →
`meet` 等比适配 → 居中偏移），**每轮都错**——那条链有四层嵌套。

正确做法：把图转 rawvideo 逐像素量。
```python
dark = lum<14 的像素 → 按 x 聚类 = 图标块
块内 lum>150 的像素 = 三角 → 边界框 → 占比
```
用户指认的稿子实测：图标 70×69 px、三角 30×37 px ⇒ **占宽 42.9% / 占高 53.6%**。

### ★★ 核心教训 2：**占比基准是「72dp 可见区」，不是 108dp 画布**

adaptive icon 前景层是 108×108dp，但**系统显示时裁出中心 72×72dp**。
拿 108 当基准 ⇒ 每版都大一大圈（45% × 108/72 = 67.5%）。

### ★★ 核心教训 3：**图标更新后设备不显示，是 PackageManager 的图标缓存**

APK 已装、`aapt2 dump` 也能确认资源是新坐标，但**设备上仍是旧图标**：

| 尝试 | 结果 |
| --- | --- |
| `am force-stop com.android.settings` | ❌ 无效 |
| `am force-stop com.miui.home` | ❌ 无效 |
| **`adb reboot`** | ✅ 生效 |

⇒ **改了 launcher icon 必须重启设备才能看到**，否则会误判成"代码没生效"，
白改好几轮（本卡实际浪费了两轮）。

### ★★ 核心教训 4：**我第一轮"小尺寸下三层描边会脏"的判断是错的**

糊的真正原因是当时**描边 2.4 太粗 + 三角太大（66dp）**。
描边收到 1.2、三角缩到 34.6dp 之后，高光/暗影/辉光都留得住，而且明显更精致。
**第一版把"当时条件下难看"错误推广成了"原理上不成立"。**

## ★ 定稿：白底 + 深墨三角（与 Kivo Music 统一）

用户拍板：**白底**（Kivo Music 已在另一台手机上用白底且效果不错，同门要统一）。

| 项 | 值 | 理由 |
| --- | --- | --- |
| 背景 | **`#FFFFFF`** | 与 Kivo Music 同门统一；用户实机确认好看 |
| 三角 | **深墨渐变 `#2E2E33 → #1D1D1F → #0C0C0E`** | 钛金属是浅色渐变，只配深底成立 ⇒ 白底上**反色成暗面**；取色与设计稿 flat 版（`#1d1d1f`）一致 |
| 比例 | **可见区 高 53.6% / 宽 42.9%** | 按用户指认的稿子逐像素实测 |
| 描边 / 辉光 | **无** | 设计稿那圈 `drop-shadow(0 0 5px rgba(255,255,255,.07))` 是给**深底**的浮起感，白底上画白描边等于没画 |
| 细缝 | 5/84（原始几何） | 不动设计稿比例；两片分离是核心意象 |

⇒ 108dp 画布上：**三角 31.98 × 38.59 dp**，左上 (38.01, 34.70)。

**实测观感**（重启设备后，浅色花卉壁壁纸面）：
白底方块 + 深墨三角 + 清晰细缝，与旁边 Kivo Music（白底深色 V）风格一致；
深色三角在白底上对比很强，**担心的"陷进浅色壁纸"没有发生**。

**⚠️ 改了 launcher icon 必须 `adb reboot` 才能在设备上看到**（见教训 3）。

## 二、从设计稿还原了什么

设计稿是**交互式 HTML**（15KB，JS 动态生成 SVG），几何数据内嵌在 JS 里，不是现成图片。
从中提取并复现：

| 元素 | 设计稿数据 | 落地 |
| --- | --- | --- |
| 播放三角 | 上片 `[[0,0],[69.6,39.5],[0,39.5]]`、下片 `[[0,44.5],[69.6,44.5],[0,84]]` ⇒ **细缝 5px** | 同几何，路径精确计算 |
| 顶点圆角 | 二次贝塞尔圆角化，半径 `[3,7,3]`（尖角 7 / 底角 3） | 复现其 `rp()` 算法，用 Python 算出 pathData |
| 钛金属 | `#F7F4EF → #E0DCD3 → #B9B4A9`（上→下） | VectorDrawable `<gradient>`，两片共用同一渐变坐标 |
| 背景 | `#0A0A0B` | `@color/ic_launcher_background` |
| 占比 | `ic()` 的 `w:'56%'` × (69.6/86) = **45.3%** | **宽 48.95 / 高 59.07 dp**，居中 (29.53, 24.46) |
| 安全区 | 「前景位于 66dp 安全区内」 | 高 59.07 ≤ 66 ✅ |

### 定稿为什么「不加描边」
设计稿的三层结构（填充 + 上缘高光 + 下缘暗影）是**大尺寸展示**用的。
在 48–72dp 的图标上，2.4 的单色描边会把轮廓糊掉（第一轮真机验证的教训）。
⇒ 图标只用填充渐变；**那两层质感留给启动动画里的完整标识**（2.3 s 的英雄镜头值得用三层）。

## 五、已知风险（诚实记录）

**白底版（实验）**：试过 `#FFFFFF` 底 + `#1D1D1F` 纯色三角，
在 **MIUI 桌面上三角没显示出来**（图标变成纯白方块）⇒ **不采用**。
另外两条理由（与设备无关的通用判断）：
1. 浅色壁纸上白底是**同色系**，容易"陷进去"；深色底对比更强、更跳；
2. 钛金属渐变需要深底才成立，金属要有环境对比才显厚度。

底色**定稿为设计稿的 `#0A0A0B`**。

**圆形蒙版：终稿参数正好落在圆内。**

- 三角边界框 `x 40.31–67.69`、`y 37.48–70.52`；
- Android 圆形蒙版 = 直径 72dp 的圆（圆心 54,54，半径 36）；
- 角点到圆心距离 ≈ **√(13.69² + 16.52²) ≈ 21.5 < 36** ⇒ 完全在圆内 ✅

（中间几版因三角过大，角距分别到 42.9 / 49 / 32.4，圆形蒙版会切角；
缩回设计稿原比例后自动消解。）

## 六、没做的部分（设计稿里的其余内容）

1. **启动动画**（冷启动 2.3s / 热启动 0.8s）—— 需要改 `MainActivity` 启动流程；
2. **音效**（98/196/294 Hz + lowpass 900Hz + 1.1s 衰减）；
3. **播放策略**（安装后首次 / 距上次使用超一天才播完整版）；
4. **SplashScreen 主题**（背景 `#050506` + 全透明图标，让应用内动画接手）；
5. **字标 KIVO**（`viewBox -6 -6 267.2 84`，K/I/V 多边形 + O 同心圆环）—— 图标用不到，
   但启动动画/关于页需要。

**这五项单独一张卡**，其中 1、4 必须先摸清 MainActivity 的启动路径
（播放页绝不能有启动动画）。
