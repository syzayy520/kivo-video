## 三、这一轮踩过的坑（可复用）

| 坑 | 现象 | 结论 |
|---|---|---|
| `Log.d` 在 MIUI 上不可见 | `logcat` 只有系统日志，App 日志抓不到 | 诊断必须写 `files/net-diag.log`（NetDiag 通道） |
| 脚本写 Kotlin 正则 | `\b` 被 Python 转义成退格符 0x08，**正则静默失效** | 关键正则必须配单测；写完校验文件无控制字符 |
| TMDB 图片必须走统一出网口 | 裸 `URL.openConnection()` 不走 SOCKS 代理 → 图片全空 | 用 `TmdbClient.openConnection` |
| 图片 CDN 时断 | `SocketException: Connection reset` | 3 次重试 + 8s 超时 + **磁盘缓存**（成功一次永久可用） |
| 取样不足 | 只查 2 个目录就断言"NAS 无图"，实际 7% 有 | 结论前先按比例抽样，别用个例下判断 |

## 六、已知限制（诚实边界）

- **NAS 影片不刮削**：不移动/改名文件，只读索引。
- **TMDB 图片国内网络不稳**：部分卡片仍可能落渐变占位；成功过的会磁盘缓存。
- **无 `tmdb_key.txt`** 时只有库内图（7%）+ 占位。
- **SMB 条目无 mtime**（`SmbEntry` 只有 name/dir/size）⇒ "最近添加"排序暂按目录名，非真实入库时间。
- 首页每分类只展示 12 部，暂无"查看全部"入口（未做，等需求确认）。
- 剧集行同一部剧的多个集会显示相同片名（季集已被剥掉用于搜索），未附带 `S01E01` 区分。
