## 二、主理人交叉验证：三条 P0 必须修正

这是本次汇编最重要的产出。三份分项报告独立成文，主理人逐一回查代码后，发现以下问题**不能直接按报告改**：

### 修正 1 · P0-05「底部胶囊深灰底黑字」——不是没实现，是触发条件太窄

- **报告说**：`CapsuleNavBar` 深态没落地、深灰底配黑字。
- **回查实际**：`CapsuleNavBar.kt:47-66` 已完整实现 `onDark` 深态（`navPillDark` + 浅色标签 `navIdleDark`），且 `MainActivityShell.kt:110-126` **有调用点**，只是触发条件为 `onDark = page == 1 && state.ambientDark`（:125）——**仅「发现」页且环境暗时**才开深态。
- **真实根因**：详情/首页 hero 是独立页面或环境光未判暗，深态不触发，于是退回浅态组件压在深底上 → 视觉上"深灰底黑字"。
- **正确修法**：不是重做组件，而是**修正 `onDark` 的判定来源**（对 hero 深底页强制深态），并把深态几何/浅态几何保持完全一致。改动量从"重做导航"降为"改一个布尔判定"。
- 证据文件：`android/app/src/main/java/com/kivo/cinema/MainActivityShell.kt:125`。

### 修正 2 · P0-01「详情标题三重叠加」——证据是旧截图，代码已有两道防线

- **报告说**：海报美术字 + 自绘白字 + 自绘黑字同屏三套。
- **回查实际**：
  1. `DetailHeroContent.kt:30-48` 的 `TitleLayer` 已做优先：有 `logoUrl` 就画 TMDB logo，**不再画自绘文字**；只有无 logo 时才画单套 `Text`（34sp）。
  2. `SmbDetail.kt:68,129` 的 `loadImage` 已套 `trimTitleBand()`（:269 裁掉海报底部 15% 烧字带）。
- **判定**：报告证据用的 `detail-hero-fix-*.png` 是修复过程截图，**很可能拍于这两道防线生效前**。当前是否仍叠加，**必须真机复验**，不能据旧图直接改代码。
- **正确做法**：先在有解锁设备时打开电影/剧集/SMB 三类详情页各截一张，确认叠加是否真实存在；若已消失，本条降级为"回归用例"（写进测试防回退），不进修改清单。
- 证据文件：`ui/detail/DetailHeroContent.kt:30-48`、`ui/detail/SmbDetail.kt:265-278`。

### 修正 3 · P0-03「删 SDR 大字、资源卡折叠」——与用户已明确裁决冲突，需用户拍板

- **报告说**：删掉资源卡的 SDR 大标题、把资源卡折叠成一行。
- **冲突事实**：这正是**用户上一轮明确要求**的形态。用户原话「能不能和 REX 那样做成小的豆腐块」，并要求站在审美制高点重做；当时的实现决策（见 `.workbuddy/memory/2026-11-19.md`）是"页级胶囊分辨率档 + 卡内粗体动态范围主标题 + 图标化容量码率 + 绿菱形来源 + 绿圆勾"，并经真机确认「7.82Mbps 完整显示、小豆腐块、达到 REX 观感」。
- **判定**：这是**审计理想态（信息极简）vs 用户已确认方向（REX 式信息卡）**的价值冲突，不是 bug。主理人**不擅自推翻用户裁决**。
- **交用户决策**：见本报告第四节。若用户认可审计意见，才排期改；否则保留现状并把"不做折叠"记为设计决策，避免下一轮审计再提。

## 三、交叉印证：三份报告互相支持的结论

以下问题由两个以上成员独立指出，可信度最高，建议优先处理：

| 问题 | 交叉印证来源 | 建议动作 |
|---|---|---|
| **详情页信息区过重**（勋章/chip 堆叠、大空白） | PM P0-03 + 架构师（EmbyResource 519 行职责混杂）+ QA Q-03（无超时串行 get） | P0 批：详情 hero 一次重构，同时解决视觉与代码结构 |
| **在看页问题成簇** | 架构师（多选 remember 丢态、行数临界 269 行）+ PM P1-11（缩略图形态混乱）+ QA Q-05/06/15（注释矛盾、热区<48dp、TalkBack 无标签） | P1 批：在看页整页重做，而非零散补丁（当前正有未提交改动，先合并再统一改） |
| **弹窗/浮层三套语言并存** | PM P1-09 + 一致性 C3 + 架构师（DetailActionMenu 私有色、令牌重复）+ QA Q-04（多层 BackHandler 竞争） | P1 批：建全局 `OverlaySurface` 两规格，所有浮层二选一 |
| **裸色/强调色失控** | 架构师（UI 176 处裸色、蓝绿紫橙四色）+ PM C9（收敛到蓝+绿）；PM 逐张复核 REX-EMBY 23 张确认**与原生 REX 同源、无第四套语言** | P1 批：`PlayerTokens`/`SettingsVisuals` 收敛到 DesignPalette 映射；`DetailActionMenu.kt:27-28,90` 私有紫色系（`0xFF655978`/`0xFFF3F0F8`/`0xFFE7E1F0`）未登记进 DesignPalette、与唯一紫源 `bgLavender` 也不同源——按 REX 同源色板核对后并入语义色，不新建第四套强调色 |
| **空图占位是裸色块** | PM P0-04 + P1-12 + QA（反馈完整性链路） | P0 批：全网卡通占位 + 修缓存链路 |

**治理共识（PM 与架构师对齐）**：PM 提的唯一来源组件集（`OverlaySurface`/`PrimaryAction`/`PagerDots`/`PosterPlaceholder`/`RatingBadge`）与架构师的令牌收口是**同一治理动作的两面**——视觉一致不能只靠改截图，必须让令牌/组件成为页面唯一可调用入口，否则改完必回退。建议给 `ui_gate` 增加**组件层门禁**：`ui/design/` 与 `ui/components/` 下组件文件禁止 `Color(0x...)` 字面量，把"组件只能读 DesignTokens/DesignPalette"固化成规则。

## 五、统一优先级路线图（修正后）

### 第一波 · P0（一开屏就看到，成组交付）
1. **详情 hero 一致性**（P0-01 真机复验 → P0-02 背景取色 → P0-05 深态判定修正）：三处都在详情/首页 hero，一次真机取证、`before/after` 并排图。
2. **空图占位统一**（P0-04）：`TmdbPlaceholder` 全网替换裸色块 + 修缓存，涉及首页/在看/详情/聚合，单独一批回归。
3. **详情信息减肥**（P0-03 的非冲突部分）：评分并入元信息行、消除 >48dp 空白带；**资源卡折叠按第四节冲突项暂缓**。

### 第二波 · P1（按页成组，不逐个补丁）
4. 在看页整页重做（状态 rememberSaveable + 拆文件 + 缩略图规范 + 热区/TalkBack）。
5. 弹窗语言统一（`OverlaySurface` 两规格 + BackHandler 单一消费）。
6. 裸色/字号令牌收敛（`PlayerTokens`/`SettingsVisuals` 映射化 + 高频字号映射 + ui_gate 新增裸字号告警）。
7. 播放器三处（标题显示片名、6pt 三段轨、图标线性化）——**已有 v3 像素基线，不动 pitch50/锚点表**。
8. 设置页 chip 收敛、聚合搜索去绿、角标统一。

### 第三波 · P2（打磨与治理）
9. `PlayerActivity` 909 行 god object 拆分（架构师 Top1，收益最高但风险也最高，单独排期）。
10. `EmbyResource` 519 行三层拆分、门禁 19 个超限文件分 6 批降线。
11. 滚动条 / 展开简介 / 分页点组件统一；补 4 个主 Page 的 @Preview。

**路线图原则**：先"同页统一"再"跨页统一"；每波成组交付、出并排图；未并排不宣布完成（依据 `visual-polish-spec.md` §三硬性验收）。
