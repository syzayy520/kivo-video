# P247 · SMB 顺序预读（独立连接 + 环形缓冲）

日期：2026-11-10
设备：MatePad MRR-W29（SD865 / kona，Android 12）
片源：`[恐怖废墟].The.Ruins.2008...VC-1.TrueHD.5.1-CMCT.mkv`（20.2 GB，软解）
回归：`土豆逗大话语文 02. 影子哪来的：《影子》.mp4`（hardware AVC，硬解）

## 一、问题

用户反馈「音画不同步，画面还是卡卡的」。改前实测（同一部片）：

| 指标 | 改前 |
| --- | --- |
| `read` 段成本（每帧均摊） | **14.5 ms** |
| 段内 `send`（VC-1 解码本体） | 15.5 ms |
| 端到端 `ratio`（媒体时间/墙钟） | **0.79 ~ 1.32 摆动**，30% 采样 <0.97 |
| 音频闸门 `gated` | 反复触发（音频被停/放开） |
| 累计 `per` | 43.4 ms > 帧间隔 41.7 ms |

### 根因不是平均值，是长尾

`SmbByteSource` 的 1 MiB 窗口是「命中若干次 → 阻塞填一次」的锯齿：

- 平均值 14.5 ms 完全可以由「每约 12 帧卡 174 ms」摊出来；
- 平均值把长尾抹平，`per` 43.4 vs 41.7 只差 1.7 ms，看数字像「差一点」，
  实际观感是周期性顿一下，然后靠「连续多渲几帧」追赶 —— 观众看到的是忽快忽慢；
- 视频一旦落后，`softAudio` 闸门（领先 >800 ms 就 `setPaused(true)`）开始
  停音频/再放开。**声音走走停停，就是用户说的"音画不同步"**。

## 二、改法

`android/app/src/main/java/com/kivo/cinema/smb/SmbByteSource.kt`

1. **独立连接的顺序预读线程**（`KivoSmbPrefetch`，daemon）
   - 自己的 `SmbReader`（自己的 libsmb2 context、自己的 socket），不与主读取器共用锁；
   - 6 MiB 环形缓冲、单次 1 MiB 块；
   - **网络读一律在 `pfMutex` 之外**——持锁读等于把预读退化成同步读。

2. **顺序播放时只等预读，绝不并发第二条读**
   - 两条连接同时拉同一台服务器会互相拖慢：实测 1 MiB 单次从 92 ms 恶化到 **543 ms**（6 倍）；
   - 因此 `readAt` 未命中但缓冲仍有未消费数据时，等待预读追上（上限 1.5 s），
     只有缓冲空（首帧/seek）才走同步读。

3. **代际校验 `pfEpoch`**
   - 消费者跳读时 +1，预读线程回写前核对；不核对就会把旧位置数据追加到新位置缓冲，
     表现为花屏/错帧。

4. **失败一律降级，不污染播放**
   - 预读 open/read 失败 → `pfDisabled = true`，退回原同步路径；
   - 不重连：重连会跟主读取器抢同一台服务器，反而拖慢正在播的那条。

5. **运行时读取画像**（`KivoSmbRead`，每 4 秒）：命中率 / 同步读次数 / 填充均值与最大值。
   这组数据是这次能定位问题的唯一入口，保留为常态可观测性。

## 三、改后实测

### 3.1 逐窗口帧间隔（每 60 帧一个独立窗口，19 个窗口）

| 指标 | 值 |
| --- | --- |
| min | **40.9 ms** |
| p50 | **41.6 ms** |
| p90 | 42.1 ms |
| max | **42.7 ms** |
| 窗口 >45 ms | **0 个** |
| 窗口 >50 ms | **0 个** |
| 等效帧率（p50） | **24.04 fps**（源 23.976） |

逐窗口而不是累计平均：任何一次 174 ms 的长卡都会让某个窗口跳到 44+ ms，
19 个窗口全部 ≤42.7 ms，等于「没有卡过」。

### 3.2 读取与同步

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| SMB 命中率 | — | **100%（24 个窗口全部 100%）** |
| 同步读 `fills` | 每帧 0/1 | **0 次**（24 个窗口全 0） |
| `read` 段（每帧） | 14.5 ms | **1.5 / p50 1.8 / max 2.0 ms** |

### 3.3 音画

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| `ratio` 区间 | 0.79 ~ 1.32 | **0.93 ~ 1.06**，p50 **0.99** |
| 偏离 ±3% 以外 | 52% | 15%（且最大只到 1.06，属帧量化） |
| `gated=true` 次数 | 反复 | **0** |

音频闸门全程未触发，等于「视频不再落后到需要压音频」。

### 3.4 seek 正确性

拖到约 30 分钟位置：画面跳到正片场景，**无花屏、无错帧**，
之后 `hits=100% / fills=0` 恢复。代际校验有效。

## 四、已知遗留（非本次改动引入）

**快速连续切换片源时，新播放器会报**
`audio start: aaudio start: 流未进入 STARTED，当前状态码 3`。

- 冷启动后单播同一文件正常（`setState 3 → 4`，`AudioPlaybackConfiguration state:started`）；
- 判断为上一路 AAudio 流未释放完就开新流（`closeNetworkPlayback` 在后台线程异步关闭）；
- 与 SMB 预读无关，未在本卡处理。

## 五、内存与带宽

- 每路字节源：6 MiB 预读环 + 1 MiB 窗口 ≈ 7 MiB（视频、音频各一路，合计约 14 MiB）；
- 带宽：片源码率约 3.6 MB/s，单连接实测 11 MB/s（1 MiB / 92 ms），余量 3 倍；
- 6 MiB ≈ 提前 1.7 s，可吸收连续两次网络抖动。
