- K40（b6e950ee）通过现有 Emby 表单登录第一组服务器，出现 60 条电影。此轮只保留脱敏观察，不归档私人片单。

- 两次输入检查中，手机原中文输入法对快速 ADB 按键注入产生候选组合，无法保证完整录入。最终检查临时使用设备已有 Latin 输入法，结束后恢复原输入法。因此网址键盘已配置，但不能据这次注入测试宣称所有中文输入法人工输入已通过。
- `build.log`：最终 `assembleDebug` 成功。固定签名覆盖安装，无卸载、清数据。

## 本次修改

Emby 沿用既有客户端：网址/密码键盘与 Next/Done、表单滚动及键盘避让、网格限制为剩余高度、独立连接反馈、空库提示、库内返回连接页。

PlayerComposeActivity 沿用既有网络会话：网络入口优先于本地测试文件定位；网络启动失败不再创建软解回退会话，保留错误；入口日志与状态不再输出完整网络播放 URL。

## 尚未通过的闸门

- 合成无效 URL 的截图时序不正确，XML 实际仍是上一页，截图为过渡黑屏，已删除，不作为通过证据。随后重试该本地端口 URL 的启动命令被工具策略拒绝；未继续尝试相同命令。错误可见/返回/无软解仍需独立真机回归。
- K40 随后电量耗尽；用户要求切换平板。已识别平板 MRR-W29（API 31，1600×2560，400dpi），最初安装期间 USB 断开；用户重新连接后已覆盖安装成功，第二组服务器登录显示 60 部电影并返回表单，见 `tablet-emby-result.json`。这只是旧界面历史验证，新版另行归档。
- SMB 仅电脑侧确认端口可达，未确认共享、浏览或播放；不把连通性当播放成功。
- 网络会话目前仅视频，`createDecoderByType` 不证明选中硬件组件。未验音频、完整影片播放、性能、音画同步与生命周期；本卡不修改解码层。

## 复测

连接平板后固定签名 `adb -s <serial> install -r -t`，进入现有 Emby 页，现场填写用户授权的测试源。检查键盘、长表单滚动、连接中/失败/成功、网格反馈、返回；归档只允许合成表单或脱敏结论。网络播放器错误路径独立复测，不能在该闸门未过时标 DONE。
